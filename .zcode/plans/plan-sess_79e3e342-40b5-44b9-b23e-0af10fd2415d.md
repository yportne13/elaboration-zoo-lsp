## 修复计划:review 发现的两个 P0/P1 问题 + 两个 P2 文档化

### P0 — 多余 wire(根因已确认,一行修复)

**根因**:`AxiLite.create.asMaster` 经 trait 分派重写为 `let $asMaster = ...; $asMaster (AxiLite.create)`,分派 rest 用 `Cxt::define` 展开,而 `cxt.rs:540` 的 `define` 把 `binding_name` 重置为 `None` → receiver `AxiLite.create` 的隐式 bn 合成到空名 → 生成无前缀 plain wire(`wire awaddr;`);asMaster 方法体的端口 bn 在上一层插入(带名 `master_awaddr`)→ 名字不匹配,"端口优先于同名 wire"机制失效 → wire 泄漏。

改动:
1. `src/L13_namespace/cxt.rs:540`:`binding_name: None` → `binding_name: self.binding_name.clone()`(define 保留绑定名)。3 个调用点已验证:Let 的 rest 继承 let 名(正确语义)、class 字段循环用 `with_binding_name` 显式覆盖、module body 顶层语句有自己的处理——无回归面
2. 回归断言:`test_hdl_bundle_master_slave`/`_param`/`_nested` 补 `!contains("wire [15:0] awaddr;")` 等无前缀 wire 断言(现有断言是空断言——检查的是带前缀名,真实 wire 是无前缀的)
3. 修复后 `master_awaddr` wires 与端口同名 → 被 hdl-verilog 的端口优先机制正确丢弃,与文档承诺一致

### P1 — `<>` 双向连接(零 derive 改动,trait 默认方法)

SpinalHDL 语义:`:=` 保持现状(宽松、向后兼容),新增 `<>` 一次双向连接:

1. `trait Bundle`(hdl-bus.typort:158)加默认方法:
   ```
   def <>(that: Self): Unit =
       let _ = this := that;
       let _ = that := this;
       unit
   ```
   bundle 的 `:=` 已跳过 input LHS,组合天然双向;derive 生成的 `impl Bundle` 缺省 `<>` 由 elaboration 自动填充默认方法(现有机制,零 derive 改动)
2. `trait Data`(hdl-types.typort:7)加默认方法(primitive 信号的 `:=` 无 skip,需自带):
   ```
   def <>(that: Self): Unit =
       let _ = match isInputPort(this.zz_expr) { case true => unit; case false => this := that };
       let _ = match isInputPort(that.zz_expr) { case true => unit; case false => that := this };
       unit
   ```
   `isInputPort` 在 hdl-bus.typort,默认方法体惰性检查(impl 填充时已注册)——测试验证
3. 示例:`10-bundle.typort` 10c/10e 改用 `master <> slave`(展示正确姿势;`:=` 单向用法在 10a/10b 保留)
4. 新测试 `test_hdl_bundle_connect`:`master <> slave` 输出与两条 `:=` 相同(连线、无 input 驱动)
5. `docs/spinalhdl-gap.md`:`<>` 行 ❌ → ✅(Data + Bundle,同 `:=` 的 skip 语义,inout 不连接)

### P2 — 文档化(完整运行时诊断成本高,先文档)

1. **def 体内创建信号**:`hdl-bus.typort` create 注释注明"工厂须在 module body/class 字段内调用(def 体内拿不到调用者绑定名,会生成空信号名/无端口)"
2. **双重分派**:`AxiLite.create.asMaster.asSlave` 在 P0 修复后会产生同名重复端口(非法 Verilog);`hdl-bus.typort` IMasterSlave 注释注明"asMaster/asSlave 只能用于未方向化的工厂结果"
