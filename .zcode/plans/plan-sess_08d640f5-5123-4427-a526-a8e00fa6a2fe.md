# 第十三轮：Nat 计算的系统性 prim 覆盖（"彻底版"）

## 目标

把 round 12 定位的 prelude force 风暴（`pred`/`log2Up`/`maxNat`/`andCond` 等 Nat 递归函数被 force 共 6.98 亿次，prelude 固定成本 24.7s）从根上消除。预期 prelude 24.7s → **~4-5s**（因果实验下限 4.02s），17-stream 等用户新库文件同步受益。

## 方案选择（为何是这个）

- **逐函数 prim（round 12 P0，只覆盖 5 个函数）**：不彻底，下一批宽度函数（metaPow2/metaDiv2/nat_compare…）还会再犯。
- **本方案：系统性 prim 层（~25 个函数，全部 Nat 计算面）**：沿用仓库既有 prim 机制（`count_nat_forced` 读链、`build_nat` 构造、`str_eq` 构造 Boolean 的先例），round 11 `count_nat_forced` 有成功先例。
- **表示层改造（Val::Nat(u64) 原生表示）**：**否决**。Nat 是 prelude 用户定义 enum，Val 层无类型信息区分"这是 Nat 链"，需在每个 Sum/SumCase 位点渗透 Nat 特判；round 8 的教训（eval 记忆化：正确但全线性能回归后撤销）表明这类核心渗透风险高、收益不明确——identity 实验已证明 per-application 计算才是成本主体。

## 核心机制（三个关键点）

1. **prim 触发点只有两处**：`force(Val::Decl(name, spine))`（mod.rs:1770-1782）与 `v_app` 的 Decl 臂（mod.rs:1917-1931），参数均被 reverse 成左到右序；返回 `None` = 保持 stuck。**eval(Tm::Decl) 只取值槽**——因此给现有 def 挂 prim 必须把 decl 表条目的**值槽（slot 2）替换为中性 `Val::Decl(name, [])`**，同时填 prim 槽（slot 5），保留 Tm 体/类型/span（hover、goto、源码显示不变）。
2. **stuck 表示随之归一**：Rigid 参数上的应用从"Call(Match 树)被反复重走"变成 O(1) 再 force 的 Decl spine（prim 快速 WHNF 预检后返回 None）。这是符号位宽表达式（`UInt[log2Up (w+1)]`，hdl-ops:676 已知限制）携带成本的系统性改善。
3. **quote 显示对等**：Val::Call 的 quote 会查 symbol_table 把 `nat_add_helper x y` 显示为 `x + y`（OpCall，mod.rs:2392-2419），Decl spine 的 quote（mod.rs:2306）目前不查——补上同样的查表，保证 stuck 运算显示逐字节不变。

## 实施步骤

### 1. 基线快照（改任何代码之前）

- 用当前 `target/perf-probe/full_out.py` 重采**全部 27 个示例**（22 旧 + 16-20 新）到 `target/perf-probe/out_r13_base/`（旧 out_base/out_fast 是废弃的首行捕获版，不能用作基线）。note 块提取以 `[LOG`/`Analyzing` 为界，计时行天然排除。

### 2. prim 基础设施（cxt.rs）

- 辅助：`nat_arg(infer, decl, v) -> Option<u64>` —— 先 force 到 WHNF，非 SumCase 头（Rigid/Flex/Call/Match 等）**立即返回 None 不做计数**（防大链重复计数），再走 `count_nat_forced`；`build_nat` 复用（cxt.rs:37）；结果带上限保护（如 >2^20 返回 None 走解释器，与现状等价不会更糟）。Boolean/Ordering 结果构造参照 `str_eq`（cxt.rs:327）既有模式。
- 挂载函数 `attach_prims(&mut self, &[(&str, PrimFunc)])`：`Rc::make_mut(decl)` 后对每个名字**只改 slot 2（值槽 → 中性）与 slot 5（prim）**，其余槽保留。

### 3. prim 清单（按注册时机分组，全部只做"全参具体才计算，否则 None"）

| 注册点（文件加载后，沿用 `p == nat_typort` 内容匹配模式） | 函数 |
|---|---|
| nat.typort 后（扩展 register_nat_to_dec） | `nat_add_helper`、`nat_mul_helper`、`pred`、`nat_sub`、`nat_div_helper`（**必须复刻"整除少 1"的既有 bug 语义**，见 hdl-utils.typort:46 注释）、`nat_rem_helper`、`nat_max`、`nat_min` |
| bool.typort 后 | `nat_eq`、`nat_lt`、`nat_lte`、`nat_gt`、`nat_gte`、`is_even`、`is_odd` |
| order.typort 后 | `nat_compare` |
| hdl-core.typort 后 | `div2Up`、`log2Up`、`maxNat`、`minNat`（与 nat_max/nat_min 是重复实现，各自挂各自的） |
| hdl-utils.typort 后 | `metaPow2`、`metaDiv2`、`metaShiftR`、`metaBitTest`、`metaDiv`（注意与 nat_div_helper 语义不同，不能共用） |

- 同步镜像到 bench 路径的按名注册（mod.rs:5783-5785 一带）。
- `pred` 优先零分配实现（直接返回链尾 data 指针）；`nat_add_helper` y=0 时直接返回 x。

### 4. quote 对等修复（mod.rs:2306 Decl 臂）

- 与 Call 臂（mod.rs:2392-2419）相同地查 `symbol_table.get(&(name, arity))`，命中且全显式则产出 `Tm::OpCall`，其余维持 `Tm::Decl` + App 链。

### 5. 顺带小修（lib.rs，round 12 发现的功能缺口）

- `load_prelude_impl` 的 builtin 文档注册表补上 6 个缺失文件（hdl-utils/stream/crossclock/bus-proto/misc-io/misc），恢复对这批库函数的 goto/hover。

### 6. 验证门槛（全部通过才算完成）

1. 27 示例完整 note 块**逐字节一致**（full_out.py 重采 vs out_r13_base）。
2. `cargo test --lib L13` 326 全过 + 集成套件全过（预计 ~167）。
3. 性能：prelude-only 墙钟（tiny 文件）24.7s → ≤5s；抽测 01-basics/17-stream/19-crossclock 总墙钟与用户侧 infer 时间；`cargo test --lib L13` 套件时间对比 143s。
4. 特别核对点：`check_app_obj_direct`（elaboration.rs:523，CANONICAL 路径）读值槽的方式与中性值槽的兼容性；bare 函数值（如 `let f = pred`）的显示/应用行为。

### 7. 二期（条件触发）

落地复测后若 andCond/negatePrev（Expr 值域，本轮不做 prim——Rust 侧构造 31 构造子的 Expr 太脆）仍是显著热点（如 prelude 仍 >5s 且归因到它），再单独评估（候选：在 addWhenContext 层做字面量快速预检，不动 elaborator）。

## 风险与对策

- **最大风险：值槽中性化改变 stuck/显示表示** → 全量逐字节对比 + 326/167 测试把关；显示差异预期集中在 quote OpCall 对等修复覆盖的运算符场景。
- **prim 语义偏差**（尤其 nat_div_helper 的 bug 语义、nat_rem_helper）→ 逐函数与 prelude 定义体对照实现；有疑义的（double、nat_of_int 等 show.typort 函数）宁可不覆盖（保留解释器路径，与现状等价）。
- **大链重复计数** → WHNF 预检短路（机制点 2）。
