### [P1] SInt 有符号性族缺陷只修了 `>>>` 一处——比较/除模/加宽仍按无符号求值（P1-4 同类，修一漏多）
- 位置：`src/prelude/hdl/hdl-ops.typort:291-311`（`Compare` for SInt）、`:313-325`（`Equal`）、
  `:115-123`（`Div` for SInt）、`:130-133`（`%`）、`:576-593`（`resize`/`asSInt`）
- 证据：55f1f06 自己的修复理由逐字适用于这些点——“`b.asSInt >> 1` 复用无符号 wire `b` 作
  Expr，旧产码 `(b >>> 1)` 实为逻辑移位”。`asSInt` 只是重标：
  `hdl-ops.typort:580-581 def asSInt: SInt[width] = SInt.mk(None, this.expr)`，
  `hdl-ops.typort:293 def <(that: SInt[width]): Bool = Bool.mk(None, binary(this.expr, "<", that.expr))`。
  `Expr` 不带类型信息，发射器只能看到 `<`（`hdl-verilog.typort:288-289` 的普通二元臂）。
- 机制/影响：IEEE 1364-2001 §5.1.1——**只要任一操作数无符号，整个运算按无符号求值**。
  触发用例（3 行，与本轮新增测试 `emit_tests.rs:44-50` 同形）：
  ```
  module m {
      input b = UInt[8]
      output lt = Bool
      let s = b.asSInt
      lt := s < 0
  }
  ```
  `let s = b.asSInt` 走 `isDeclaredSignal`（`hdl-core.typort:224-253` 对 `createInWidth` 返回 true）
  ⇒ 别名，不建新 wire（`emit_tests.rs:39-57` 正是钉这个形状）⇒ 产码 `assign lt = (b < 0);`，
  `b` 是 `input wire [7:0] b;` ⇒ b=8'hFF（SInt 语义 -1）时**恒为 0**，静默错硬件。
  同类未修面：
  - `s < c` / `s <= c` / `s > c` / `s >= c`（c 为 SInt[8]，其实参 expr 同样可能是无符号 wire）；
  - `s / c`、`s % c`（`:115-123`、`:130-133`）：有符号除法/取余静默退化为无符号；
  - `b.asSInt.resize[9]`（`:576-577` no-op 重标，spec §7.9 明记“无检查重标”）：`assign y = b;`
    目标 9 位 signed，RHS 无符号 ⇒ **零扩展**而非符号扩展 ⇒ 负数错。
- 处置：**仅报告**（不引入新的 op 语义）。修法（需 Lead/A4 协同，二选一）：
  (a) 无条件包裹 SInt 比较/除模的**两个**操作数为 `$signed(...)`（同 `arithShiftLhsStr`，
  `hdl-verilog.typort:59-60`）——注意 `>>>` 只需左操作数，比较/除模**必须两侧都包**，
  否则 RHS 是无符号 wire 时仍是混合无符号（`$signed(a) < b` 依旧无符号）；产码字节会变，
  `examples/hdl/04-compare.typort` 的 golden 在 **A4 的 `src/L13_namespace/legacy_tests.rs`** 里，需同步；
  (b) 给 SInt 比较/除模引入专属 op 标记（如 `"<s"`），在 `verilogBinOp` 与 3 个二元发射点
  （`hdl-verilog.typort:167-172/230-237/285-290`）展开成 `$signed(l) OP $signed(r)`——只改 SInt impl 的 op 串，
  UInt/Bits 产码零变化，推荐 (b)。
- needs-verify：改 (a) 的两个 golden（04c `compareSInt`、14a `divMod`）影响面；我禁止运行 cargo 无法确认。

### [P1] 事件驱动 harness 在端口宽度 0 时 `p.width - 1` 下溢 panic（**已修**）
- 位置：`src/sim/verilog_harness.rs:34-44`（原 :34-38）
- 证据（原码）：`let range = if p.width == 1 { String::new() } else { format!("[{}:0] ", p.width - 1) };`
  宽度直接来自 manifest JSON（`src/sim/mod.rs:116 width: p["width"].as_u64().unwrap_or(1) as u32`），
  而 manifest 的 width 是 prelude 原样输出的声明宽度（`hdl-verilog.typort:1889 nat_to_dec(width)`）——**可以是 0**
  （见 P2-1：compat 升序端口范围 `1 + 0 - 7` = 饱和减 = 0）。同一函数 `:75-78` 还有
  `format!("val[{}:0]", p.width - 1)`。iverilog/vcs/vivado 三个后端都走 `harness_verilog`
  （`iverilog.rs:111`、`vcs.rs:54`、`vivado.rs:88`）；verilator 后端做的是 `ctype()` 映射（`mod.rs:63-70`，
  0 落 CData）不做减法，所以**两个后端对同一 manifest 行为不一致**：verilator 能跑（按 1 位端口），
  iverilog 在 debug 下 panic（`attempt to subtract with overflow`）。
- 机制/影响：用户可触发——`SimConfig::compile` + `Simulator::Icarus` + 一个宽度 0 的端口
  （`input a = UInt[0]`，或 compat `input [0:7] a`）⇒ 测试/调用方进程 panic。
- 处置：**已修**（`src/sim/verilog_harness.rs:34-44`）：宽度 0 时返回
  `SimError::BadManifest("port '<p>' has width 0; …")`，附上升序兼容端口这个最可能的来源提示。
  宽度 ≥ 1 的产码与错误判定逐字节不变（新增分支只在 `p.width == 0` 时进入）。

### [P2] HDL041 只查“越界”，不查反向片选（`hi < lo`），片选宽度与类型承诺不符
- 位置：`src/prelude/hdl/hdl-check-graph.typort:1378-1384`（`oobRangeBad` 只查 `succ(hi) <= w`、`succ(lo) <= w`）
- 证据：`hdl-ops.typort:543/554/567 def slice[hi: Nat, lo: Nat]: … UInt[(hi - lo) + 1]`，

  `hdl-verilog.typort:323-324 partsel → expr + "[" + hi + ":" + lo + "]"` ⇒ `a[3:5]`。
  类型系统承诺 1 位、产码是 3 位反向片选（README:32 “Extracts (hi-lo+1) bits”）。
- 机制/影响：`y := a.slice[3,5]`（y: UInt[1]）静默产生越界/反向 part-select；无任何诊断。
  全仓 `.typort` 无反向 slice 用例（grep `.slice[`：06/08/18/examples/hdl_ops/quick_validate 全为 hi≥lo），
  所以补这条规则不会打到现有回归。
- 处置：**仅报告**（附建议 patch，但未落盘）。理由：这是**新增错误判定**（新警告文本），
  而 `.typort` 改动只能在运行时（prelude 加载）失败，爆炸半径是全套 HDL 测试；
  BRIEF §6.3 要求有实证才能改判定，而我禁止运行 cargo/iverilog。建议 patch（保持作者要求的
  扁平单 match 尾形态，避免 5 层 `let _ = match` 链与行注释里的 `*/`）：
  ```
  def oobRangeBad(mname: String, nm: String, hi: Nat, lo: Nat, w: Nat): Unit =
      let badHi = chkBnot(chkNatLe(succ(hi), w));
      let badLo = chkBnot(chkNatLe(succ(lo), w));
      let rev = chkBnot(chkNatLe(lo, hi));
      match chkBor(badHi, badLo) {
          case true => chkReport("HDL041", mname, nm, "constant bit range [" + nat_to_dec(hi) + ":" + nat_to_dec(lo) + "] out of declared width " + nat_to_dec(w) + " - Verilog reads/writes x")
          case false => match rev {
              case true => chkReport("HDL041", mname, nm, "constant bit range [" + nat_to_dec(hi) + ":" + nat_to_dec(lo) + "] is reversed (hi < lo) - Verilog part-select is out of order")
              case false => unit
          }
      }
  ```
  （配套在 `hdl_check_graph_tests.rs` 的 HDL041 组加一条正例 + 一条 `slice[0,7]` 界内反向负例。）

### [P2] `UInt.expand` 对“字面量来源”的 UInt 发射 `{1'b0, 5}`（非法/宽度错）
- 位置：`src/prelude/hdl/hdl-ops.typort:633-634`（本轮 3662546 的新实现）+ `hdl-verilog.typort:62-72`（`catLitStr`）
- 证据：新实现是 `UInt.mk(None, binary(literal(0), "##", this.expr))`——**直接构造**拼接，
  绕过了 `Cat` trait 的 impl（`hdl-ops:459-530`）。`catLitStr` 的注释明说兜底分支
  “A literal can only reach `##` as a Bool (value 0 or 1) — the Cat impls always concatenate a Bool
  or a named signal — … (defensive fallback, not reachable through the Cat impls)”，而它自己的兜底是
  `case _ => natToDec(v)`（未定宽十进制）。
  触发路径：`def five: UInt[8] = 5.into`（`hdl-types.typort:126-128 Into[UInt[width]] for Nat`
  = `UInt.mk(None, literal(this))`）⇒ `five.expand` ⇒ `binary(literal(0), "##", literal(5))`
  ⇒ 发射 `{1'b0, 5}`：IEEE 1364-2001 §4.1.14 禁止拼接里的未定宽常量；即便工具接受，
  它按 32 位定宽 ⇒ 自决定上下文（`flag ## five.expand`）宽度是 1+33=34 而不是类型承诺的 10。
- 处置：**仅报告**，needs-verify。① `.into` 在 def 返回类型位置能否解出 `width=8`（决定可达性）；
  ② iverilog 是否拒绝 `{1'b0, 5}`。若可达，建议把 `catLitStr` 的兜底改成 `w'dv` sized 形式
  （`sizedLitStr(v, 需要的位宽)`——但 `catLitStr` 拿不到目标位宽，故更稳的是让 `UInt.expand`
  显式用 `sizedLiteral`/或新增“sized 1 位零字面量”形状）。

## 5. 设计决定讨论（不属 bug，只记录）

1. **Expr 不带类型 ⇒ 发射器无法知道有符号性**：`>>>` 之所以能靠 op 串修，是因为 op 串本身是
   “算术移位”的语义标记；`<`/`/` 没有这种标记，所以 P1-1 只能靠“新 op 标记”或“无条件包裹”二选一。
   长期看更干净的方案是让 `Expr` 携带一位 signedness（或把 SInt 的重标变成显式 `$signed` 节点），
   这样发射器不需要猜。记录用，不建议本轮动。
2. **`asSInt` 的“重标”语义与 Verilog signedness 的错配是系统性的**：`resize` 明记“无检查重标”
   （spec §7.9），但 Verilog 的赋值/拼接上下文会按**表达式自身**的 signedness 决定扩位方式，
   “同一 Expr 换类型”在有符号性相关运算里不等价。建议在 spec 里把“重标”的适用面写清
   （哪些运算下有符号性会被忽略）。
3. **“宽度 0”在整个链路上没有被定义**：`width_range(0)` 静默当 1 位（`cxt.rs:60-69`），
   manifest 报 0，harness 下溢。建议统一（要么语言层拒绝 `UInt[0]` 端口，要么全链路把 0 归一为 1），
   我本轮只堵了 harness 的 panic。
4. **HDL042 的“首轮地面记录制”是有意的取舍**（作者注释说明存量 def 在检查期不可比：
   Phase-A 中性轮 + 类字段重放残影）：代价是**同一 Backend 生命周期内**名字集合单调累积，
   `cxt.rs:709` 的 `mutable_map` 是 per-Infer 全局；`src/lib.rs:1337/1912/2538` 有清空点，
   但“编辑后重新 elaborate”是否每次都走到清空我没能静态确认 ⇒ 记 needs-verify：
   若有路径不清空，改宽后再检查会出**假 HDL042**（只是警告，不阻断 emit）。
