### 2.2 [会签·P0 既有] BRIEF §8 整机重借 SB UB：A3 机制论证**独立复核成立**（附两点细化）

- 复核方式：本机无 Miri 组件（`~/.rustup/toolchains/*` 无 `miri`/`stacked_borrows` 源），故拉取
  `https://raw.githubusercontent.com/rust-lang/miri/master/src/borrow_tracker/stacked_borrows/mod.rs`（今日 HEAD，HTTP 200）
  逐条对照 A3 §2.1 的四步论证。**逐条结论**：
  1. `let mach_ptr: *mut Machine = self`（`machine.rs:1310`）→ `NewPermission::from_ref_ty(RawPtr(Mut), RetagMode::Raw)`
     = `Uniform { perm: SharedReadWrite, access: None }` ✓（源码 `from_ref_ty` 的 `ty::RawPtr(_, Mutability::Mut)` 臂）。
  2. `access: None` 走 `grant` 的"tricky case"：`find_granting(Write, derived_from)` 后
     `find_first_write_incompatible(granting_idx)`；父 tag（`&mut self` 参数在 FnEntry 被 retag 成 `Unique`+StrongProtector）
     的 `Permission::Unique ⇒ granting + 1` ⇒ **raw tag 恰好插在父 tag 正上方** ✓（A3 第 1 步成立）。
  3. 字段解构 `let Machine { spine, … } = self;` 每字段一个 `&mut` retag（`Unique, access: Some(Write)`）：
     `grant` 先 `self.access(Write, 父tag)` → Write 分支
     `first_incompatible_idx = find_first_write_incompatible(parent_idx) = parent_idx+1` →
     `pop_items_after(...)`：**把 raw tag 从该字段的字节段栈上移除**（`item_invalidated` 见其 `protected()==false`
     ⇒ 不报错）✓（A3 第 2/3 步成立；注意是 **pop**，不是 read 分支的 `disable_uniques_starting_at`）。
  4. `unsafe { (&mut *mach_ptr).solve_multi_trait_ref(..) }` 的 `&mut Machine` retag 覆盖 `size_of::<Machine>()`：
     `for_each(range)` 逐字节段 `find_granting(Write, raw_tag)`——被解构字段的字节段里 raw tag 已不存在
     ⇒ `Err(())` ⇒ `dcx.access_error` ⇒ **UB 在该表达式求值时即成立**，与内层求解成败无关 ✓（A3 第 4 步成立）。
- **`trait_metas`"一步之遥"结论：成立，且原因可精确表述**：SB 的栈是**按字节段**的（`Stacks.stacks: DedupRangeMap<Stack>`
  + `for_each(range, ...)`）；字段 retag 只在自己那个 range 的栈上做 write-access。`trait_metas` 未进解构列表
  ⇒ 其字节段的栈仍是 `[…, Unique(self), SRW(raw)]` ⇒ `unify.rs:691` 的 `(*mach_ptr).trait_metas.len()`
  在 `find_granting(Read, raw_tag)` 处命中、Read 分支只 `disable_uniques_starting_at`（其上无项）⇒ **不 UB** ✓。
  同点 `:725` 的 `trait_metas.truncate()` 是 raw 写，同样在**未解构**字段的段上 ⇒ 亦不 UB。
  ⇒ 任何人把 `trait_metas`（或 `defs` 已在内、`tstate`/`symbol_table` 等任一新字段）加进解构列表，
  这两行**立即**变 UB——A3 建议把这条写进 `machine.rs:1311` 注释，**我同意，且建议同时在被调用侧
  （我切片的 `typeclass.rs:79/143`）注明"本函数只能经整机 `&mut` 调用，调用方必须不持有 Machine 任何字段借用"**。
- **对"把取指针挪到解构之后不能修"的细化**（我的独立补充）：该说法要分两种变体才完整——
  (a) 字面重排：`let Machine {..} = self;` 之后再也拿不到 `*mut Machine`（字段借用已活，借用检查器拒绝；`&mut` 非 Copy），
  不可编译；(b) **可编译的变体**：`let mach_ptr = self; let Machine { .. } = unsafe { &mut *mach_ptr };`
  ——此时字段 retag 的父 tag 是新建的 Unique（在 raw 之上），字段 write-access 不会弹 raw
  ⇒ `(&mut *mach_ptr)` 的 retag 能 `find_granting` 成功（**不再 access_error**），但其
  `find_first_write_incompatible(raw_idx)` 对 SRW 只跳过**连续 SRW**，紧随其上的 Unique 即边界
  ⇒ `pop_items_after` 会**弹掉字段 `&mut` 与新 Unique** ⇒ 返回后 `unify_iter` 继续用 `spine/metas/conv/stack`
  仍是 UB（只是从"retag 时报错"变成"后续使用时才报错"）。**故 A3 的结论正确，但理由应写成 (a)+(b) 两条**。
