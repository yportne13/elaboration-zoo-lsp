   (i) 撞名检查**前移**对齐 `cxt.rs:1230-1232`（先 `cxt.decls.contains_key(x)` → Err，**不写表**）；
   (ii) 插入成功后把待确认键压栈：`self.decl_stub.push(SmolStr::new(x));`
2. `machine.rs:383` `Machine` 加字段 `pub(super) decl_stub: Vec<SmolStr>`（`Machine::new` 初始化；
   `clear_round` 一并 clear 更稳）。**必须用栈**：`infer_after_prefix`（克隆入口，`:3494-3502`）也会经
   `fake_bind`（class Phase B 的内层 def 走 `:4034/:4054/:4315`），单值字段会被内层覆盖。
3. 成功路径出栈：Def 臂 `:3677` 之后、Enum 臂 `:3794` 之后 `self.decl_stub.pop();`
   （`infer_after_prefix` 的克隆入口：成功也 pop、失败也 pop——它的表是克隆，失败即弃，无需回滚。）
4. 失败回滚收口在 `machine.rs:3489-3490` `infer_decl`：
   ```rust
   let r = self.infer_after_prefix_mut(bump, cxt, d);
   if let Some(k) = (r.is_err()).then(|| self.decl_stub.pop()).flatten() {
       // 对齐参考版 `Infer::infer(&Cxt)` → `infer_after_prefix` 的 clone 隔离
       Rc::make_mut(&mut cxt.decls).remove(&k);
   }
   r
   ```
   用 `make_mut` 而非 `get_mut`：失败时 decl 表可能仍被 `MetaSnap.cxt`（`machine.rs:1068-1077`）
   共享，`get_mut` 会返回 `None` ⇒ 清理变成"有时生效"（R1 已识别的不确定行为）。
   **代价只在错误路径**：独占时 `make_mut` 原地 O(1)，共享时一次 O(D) 拷贝/失败 decl（每 kick 至多一次）。
- **验收**：① A7 的 F2 源码（无 println 版）两版 errs 逐条相等；②（内部不变量，非用户可见）§2.1b 的
  redefine 探针已由 Lead 实测为"孪生回落 ⇒ 用户可见面一致" ⇒ 该步只作方案 A 第 1 步的分支验收，
  **不要求**用户可见差异；③ `cargo test --lib` + `--test twin_engine_tests` + `--test l13_fast_parity` 全绿。

**方案 B（per-decl decl 表写点 journal；建议立项，需专项验证）**
- 覆盖 A 覆盖不到的形态：失败的 class/module decl 会写**多个**名字（Phase A/B 的 `decl_reg_in` 多次），
  只回滚 `fake_bind` 的 stub 不够。
- 结构：仿 `STATE_JOURNAL`（`machine.rs:111-184`）加一个 per-decl 帧的 decl 表日志；条目需要
  `DeclEntry<'static>`（`StateUndo` 无生命周期参数，但同枚举已有
  `StateUndo::TmImport(usize, Option<&'static Tm<'static>>)` 的 `'static` 擦除先例，照抄其口径即可）；
  `observe_user` 每 decl 开帧，Ok⇒并帧/弃帧，Err⇒回滚后再 `user_errors.push(e)`。
- 代价：每写点 1 条日志（`SmolStr` + `DeclEntry` move），帧 pop O(1)，**成功路径零表拷贝**；
  失败路径 O(写入条数)。⇒ 不改变良性路径复杂度。
- 消化（§6.7 精神）：这是**声明表**的热路径改动，写错会污染整个 kick（Lead 的告警成立）⇒ 我不盲改。

**方案 C（"遇错即停 + 交参考版接管"）：不建议单独落地——性能收益归零，且略负**
- 做法：`entry.rs:1254-1259` 的 `Err(e)` 臂改成 `return Err(e)`（`lib.rs:1474` 会记
  `observe-failed` 并回落），或新增一个明确的"不可信恢复"类别。
- **量化**：LSP 打字期**多数按键都带错误**（用户正在改的代码）。该方案下每个错误 kick 都要：
  (i) 付孪生用户段的**部分** elaboration（parse + 到首个错误为止），(ii) 再付参考版**完整**一遍
  ⇒ 相对"只用参考版"是**多付**，相对 2026-09-14 收窄后的"错误态孪生接管"（wiring doc：
  错误态 kick ~98ms vs 参考 ~450ms）是**收益归零**。⇒ **是，会让孪生错误态的速度收益归零并略负。**
- 因此它只能作为**门策略重新设计**的一部分：正确方向是让孪生的错误集与参考版一致（方案 A/B），
  门的判据才可能从"类别白名单"升级为"错误集完整"；否则每一次收紧都要么牺牲速度、要么放行错诊断。

**裁决（按 Lead 要求的分类）**
| 方案 | 标签 | 理由 |
|---|---|---|
| A 定点回滚 | **可安全落地**（条件：Lead 编译 + 2 个探针 + 3 个测试目标） | 只动错误路径；良性路径代价 = 1 次 `contains_key` + 1 次 Vec push/pop；不变量可逐条静态论证 |
| B journal | **需 Miri 与专项验证 / 建议立项** | 完整覆盖多写点，但触及声明表热路径与 journal 帧语义 |
| C 遇错即停 | **不建议**（除非与门策略一并重设计） | §5.2 的性能量化：收益归零且双付 |
