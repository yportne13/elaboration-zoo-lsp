## 5. 设计决定讨论（不属 bug，只记录）

1. **`Val::Nat(u64)` ↔ 深 `succ` 链的 O(k) 展开**：`quote_nat`（`mod.rs:3587`）把 `Val::Nat(k)` 展开成 k 深 `Tm::SumCase`，消费端（`pretty_nat`、`Tm::drop`、`eval`/`force` 链）逐点迭代化。这保住了"下游看到的项形态不变"，但每次跨值/项边界都要 O(k) 构造 + O(k) 析构；`bignat_large_add_no_stack_overflow`（`legacy_tests.rs:5036`）钉住了栈预算，但**没有钉住分配量**。若将来做 `Tm::NatLit` 之类的原生项形态，可同时消掉这一层 O(k)——属设计选择，本轮不动。
2. **`PoolState` 的 `unsafe impl Send` vs 改 `Arc`/序列化**：当前论证依赖"推池前清空全部持 `Rc` 的线程局部"这一**约定**（已由 §2.1 的注释与 `Drop for PreludeSlot` 维护）。更稳的形态是让池交接的内容根本不含 `Rc`（或整体 `Arc` 化），代价是 prelude 装载/克隆路径全面改造。建议作为长期项，不建议在评审轮内动。
3. **零断言 `#[test]` 的存留**：它们让 `--lib` 用例计数（885）与实际保护力脱钩。若改为普通注释块，多处文档引用的"199 passed / 192 passed"等历史数字会失配——这也是我本轮选择"只更新注释、不删测试"的原因。
4. **`Infer::clone` 共享 `mutable_map`/`def_replay_memo`**（`mod.rs:1458`、`mod.rs:1464`）：这是刻意的"快照共享变更表"语义，`clone_prelude_state` 用深拷 + 重建把它隔离；但 `Infer::clone` 本身在别处（A2/A3 的 solve 快照、twin 对照）也被调用。建议把"clone 不是隔离快照"写成字段级文档，避免未来出现第三个共享面。
