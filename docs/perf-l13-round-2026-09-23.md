# L13 性能版深挖第二轮 + 全层拆分（2026-09-23）

## 0. 本轮的定位

两段工作：（A）L06–L13 七章性能版（`bump_spine_iter.rs`）按 L07 蓝本
（fb89bb0）拆分为目录模块——纯机械搬运、行数守恒、外部消费者零改动，
每章独立 commit；（B）拆分完成后的 L13 性能+内存深挖轮：6 个子 agent
并行（S1 trait/typeclass、S2 eval_aux、S3 缓存/memo、S4 内存、S5 测试
设施、S6 归因采样），逐流落地/证伪。口径同前几轮：l13bench（时间，nf
两版互检）、l06l13mem（确定性分配计数）、release + fat-LTO、min-of-5。

**方法论教训（本轮确立）**：共享机器上多流并行编译/跑测，窗口间漂移
±10%，跨窗口绝对对比会产生假信号（S3 一度把 phdl −9% 误归因给探测缓
存）。所有交付结论一律**同源码树、同窗口交错 A/B**（HEAD 版与候选版
二进制交替取 min）；全局分配计数（l06l13mem）不受噪声影响，可跨窗口。

## 4. 关键证伪（同等价值，全部有数据存档于代码注释）

- **trait_wrap 二次正规化（上一轮 §3.2.1 头号命题）→ 证伪**：相位计时
  实测 quote→eval 仅 ~0.5ms/轮（~0.04%）；真身是命中后的
  `infer_expr($method x)`（~84%，语义必需）。上一轮"18% 采样两帧内有
  trait_wrap"是入口 tick 采样的子树归因。S6 独立复核：时间加权链含口
  径 38.7% 成立——**伞面数字对，归因对象错**（子树里的 infer/unify
  才是成本，trait_wrap 自身便宜）。
- **probe_accessible (Sum,ctor) 轮内缓存 → 证伪**：三级键形命中率仅
  5~6%——跨 match 重复探测在孪生现有形态下本就不存在（per-match memo
  + 无参 Sum 短路 + 嵌套记账）。S6 复核 pcore 时间加权 10.24% 成立，
  但消融 A/B |Δ|≤1.5%：探测成本大头已随 #2 journal 化消掉，缓存无的
  放矢。
- **嵌套 unify conv.memo 共享 → 证伪**：「成功单调」论证成立、按协议
  落地后八负载 |Δ|≤1%——memo 窗口被嵌套切断的损失在现有负载形态下
  不可测。论证+数据存档 unify.rs。
- **eval_aux 宽表 constr_idx 索引（逐调用重建）→ 证伪**：重建本身要
  全表触达；表宽超 L2 后每分派强制整表 DRAM 扫，we11 +9.1%、match
  k=12 +16~24%。抽掉后同负载 −8.8%——18 个百分点全是它造成的。正解
  （跨调用 per-Tm-node 懒建索引）留档下轮。
- **"release PDB 不被 std backtrace 解析"破案**（S6）：非 dbghelp 坏
  ——release 默认 debuginfo=0 出 thin pdb，函数名不在其中；
  `/DEBUG:FULL + debuginfo=1` 出全量 pdb 后进程内 resolve 全符号。
- **参考版 struct 负载 n^1.79 近二次**（S6 新发现，k=13 basic 1375ms）：
  读码指认 `elaboration.rs` 后缀扫描每 miss 全表 `ends_with` + 每 miss
  重建 ns 方法键 HashSet——"参考版移植后缀倒排索引"（上轮 §3.3.1）
  的收益上限由此定量（k=13 ~600ms）。
