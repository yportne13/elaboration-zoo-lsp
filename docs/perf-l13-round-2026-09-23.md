# L13 性能版深挖第二轮 + 全层拆分（2026-09-23）

## 0. 本轮的定位

两段工作：（A）L06–L13 七章性能版（`bump_spine_iter.rs`）按 L07 蓝本
（fb89bb0）拆分为目录模块——纯机械搬运、行数守恒、外部消费者零改动，
每章独立 commit；（B）拆分完成后的 L13 性能+内存深挖轮：6 个子 agent
并行（S1 trait/typeclass、S2 eval_aux、S3 缓存/memo、S4 内存、S5 测试
设施、S6 归因采样），逐流落地/证伪。口径同前几轮：l13bench（时间，nf
两版互检）、l06l13mem（确定性分配计数）、release + fat-LTO、min-of-5。

**方法论教训（本轮确立）**：共享机器上多流并行编译/跑测，窗口间漂移
±10%，跨窗口绝对对比会产生假信号（S3 一度把 phdl −9% 误归因给探测缓
存）。所有交付结论一律**同源码树、同窗口交错 A/B**（HEAD 版与候选版
二进制交替取 min）；全局分配计数（l06l13mem）不受噪声影响，可跨窗口。

## 9. 第四轮（2026-09-24）——examples 的 LSP kick 口径：force 叶子臂快路径（−5.2%）

> 目标：优化"性能版跑 `examples/`"的**键盘输入延迟**（LSP 每键击全量重推），
> 口径即 `tests/twin_engine_bench.rs::bench_examples_per_file_by_engine`
> （30 个 examples，每文件新建 Backend + prime HDL prelude，min-of-5 稳态 kick）。
> 方法：`l13lspsample`（LSP kick 采样口）+ 新增 `TYPORT_KICK_DECLTIME`
> 逐 decl 计时 → force 入口形状探针（**临时，测量后已移除**）→ 同源码树、
> 同窗口**交错 A/B/A/B**（min-of-2）。

### 9.1 三步归因（每一步都改写了上一部的结论）

1. **假设"force 记忆化还有冗余没吃到" → 证伪。** 探针实测复合入口命中率
   **91.9-99.2%**、taint 恒 0、且**不同输入指针数 ≡ 未命中数**（21-crossclock
   6336/6336、20-misc 18152/18152）——即每个未命中都是该轮首次见到的输入，
   没有任何重复输入。memo 已饱和，沿 round 15 的方向没有余量。
2. **假设"观察面是大项" → 证伪（LSP 口径下）。** `TYPORT_TWIN_NO_USER_OBSERVE`
   实测 20-misc 2807 vs 2827ms、18-utils 6258 vs 6226ms：**噪声内**。
   round 2026-09-22 §3.1 记录的"观察面 19-21%"是 `l13bench` bench 口径的
   假象（LSP 装载段已显式 `observe=false`），与当时文档的注记一致。
3. **逐 decl 计时（新工具）→ 定位到模块 class 声明，并暴露真正的量级。**
   模块 class 单条声明吃掉 kick 的 **68-85%**（21-crossclock 的 i=2 =
   1.9-3.1s / 2.8s kick，363-484MB arena）；而更关键的是 force 的
   **形状分布**：`force` 总调用里 **95-96% 是叶子臂**
   （21-crossclock 16.03M/16.04M；01-basics 613K/643K；
   25-verilog-reset 3.10M/3.25M）。这些形状在 `force_inner` 里一律
   `return v`（纯 WHNF 叶，零副作用），却每次都完整支付
   memo-wrapper 的全部前置（原子计数 + sampler tick + `v_tag` 测试 +
   `v_xcell_of` 解引用匹配）**再**进 `force_inner` 走四份草稿栈构造 +
   `v_tag` 重派发 + loop 骨架，才命中那个 `_ => return v`。

### 9.2 落地项（2 处，均在 `bump_spine_iter/`）

1. **`force` 的纯 WHNF 叶快路径**（force.rs）：在 `!compound` 分支里先按
   tag 就地返回——tag 0/1/3/4/6（Rigid/Clo/U/Pi/LiteralType）与 tag 7 的
   `Nat`/`Sum`/`Lit`/`Match`。语义与 `force_inner` 对应臂**逐位相同**
   （那些臂都是 `return v` 且无副作用）。**刻意排除** tag 5（裸 meta）、
   tag 2（spine 链）与 tag 7 的 `Decl`/`Obj`/`Call`/`SumCase`：它们要查
   `metas`/`decl` 或带副作用（prim 执行 / taint），必须仍走 `force_inner`。
2. **SumCase 臂的惰性 `new_datas`**（force.rs）：旧实现无条件
   `Vec::with_capacity(datas.len())`，而"全部字段 force 后逐位不变"（不需要
   重建）在 kick 里是常态 → 绝大多数 SumCase force 白付一次堆分配+释放。
   改为 `Option` 起步、首个变化处才建并回填已见字段（回填语义与旧实现
   逐位相同，`debug_assert_eq!(changed, new_datas.is_some())` 钉住不变式）。

**顺带落地**：`TYPORT_KICK_DECLTIME` 逐 decl 计时（entry.rs）——`L13BENCH_DECLTIME`
的 LSP kick 口径对应物，env 门控、关闭时每 kick 只多一次 `var_os`；
本轮定位全靠它，留作常驻诊断工具。

### 9.5 遗留（按收益×置信度）

1. **18-utils 的 0.74×（3.9s，占总 twin 时间 ~39%）**：孪生跑完一遍后因
   `untrusted-error`（`LetNamed` trait 求解分叉）**再回退参考版跑第二遍**，
   是 double-pay 而非孪生自身慢（孪生段实测 ~2.4s）。根因已在
   `docs/lsp-twin-wiring-2026-09.md` 定性到"孪生对用户 decl 多执行约 246 次
   隐参插入 → 多注册 trait meta → `LetNamed` 递归求解失败"，**需逐 decl
   `insert_go`/`fresh_meta` 调用计数对照**才能继续，属引擎级修复，不属本轮
   点优化范围。
2. **模块 class 声明仍是单点大头**（kick 的 68-85%，363-484MB arena/kick）：
   摊平链（create/tree/Phase-A 三遍）在一个 kick 内**重求值**三遍的固有成本
   （round 8 §9.4 的"3× → 1×"长期方向仍未落地）。**已进一步定位到
   spine 链**（§10.1）：其中 84% 是 `string_concat`、33× 重入；对应的
   修复方案见 §10.3（先 force 实参再查表）。
3. **arena 每 kick 涨到 908MB 后压实回 181MB**（20-misc/24-verilog 实测每 kick
   触发 `compact_resident`）：`restore(clones)` 因此从 0.1ms 涨到 150-190ms，
   且压实换地址使 force memo 跨 kick 失效（`memo_start=memo_end` 不增长）。
   调大 `TYPORT_TWIN_BUMP_BUDGET_MB` 不改善墙钟（2.85s vs 2.86s），
   说明压实本身不是主要成本——真正的量是每 kick 的 ~850MB 中间值分配。

### 10.1 动机：量化到位（这部分是真的）

force 入口按 tag 细分（临时探针，已移除），21-crossclock 单 kick：

| 桶 | 调用数 | 占比 |
|---|---|---|
| 纯 WHNF 叶快路径（§9.2 已落地） | 11,895,020 | 74.1% |
| **叶 → `force_inner`（tag-2 spine 链）** | **3,319,196** | **20.7%** |
| 复合（SumCase/Call/Obj，memo 覆盖） | 830,934 | 5.2% |

即 §9.2 落地后剩下的最大单一桶是 **spine 链**，其中：

- **99.95% 是 `HK_DECL` 头**（3,318,363/3,319,196）；
- 按名 Top：**`string_concat` 2,792,202（84%）**、`nat_to_dec` 383,620、
  `str_eq` 77,928、`nat_add` 64,269 —— **全部在 `prim_is_pure` 白名单内**；
- **只有 99,476 个不同链 → 33× 重入**（最大单链重入 16,915 次）。

而 memo 只覆盖 tag 7 的 `SumCase|Call|Obj`，**spine 链完全不进表**，于是
每次重入都重跑 `prim_exec`：重 force 全部实参 + 在 arena 重新分配结果。

### 10.2 两次实现与两次判负

**第 1 版：按 spine 下标当键。**
`FORCE_MEMO` 的键是打包字，tag-2 的打包字就是槽位下标 `(idx<<3)|2`。
实测 kick 从 1,679ms → 275ms（force 调用 16.05M → 162,784，**98.6×**），
但 `twin_engine_tests` **8 个测试红**：

```
03-bitwise: 输出残留未归约的 `string_concat {...}` 链
            并伴随 `can't unify expected: Vec[ModuleDef](1) find: (0)`
```

**根因**：`Spine` 是 push/pop 栈（`spine.rs`："只增不减，槽位下标即句柄"
——但 `reclaim`/`clear_round` 会归还并复用槽位），**同一轮内先后两条不同的
链可能落在同一下标**。§9.2 的 tag-7 复合形状没这个问题（bump 分配地址
同轮不复用），我当时把这个论证错误地推广到了 tag-2。

**第 2 版：按链内容当键。**
键 = `(链头 V.0, 应用序实参 V.0 列)`（链的真实身份）。输出**正确归约**了，
但 `twin_engine_tests` **仍 6 个红**：

```
02-arithmetic: left 少一条 `[hdl][warning] HDL001 [arithmeticUInt] a:
              read but never driven (and not an input port)`
```

**根因（比第 1 版有价值）**：`prim_is_pure` 只描述「**该 prim 自己的结果**
只依赖实参」，而 memo 早退**同时跳过了 `prim_exec` 内部的实参 force**——
那一步可能触发其它路径上的**副作用 prim**（`report_check_issue` 等 HDL
自检）。taint 计数器只覆盖「被 memo 的那次求值**内部**」观察到的副作用，
覆盖不到被整条跳过的那条链。

即：**纯度 ≠ 可跳过**。"这个 prim 是纯的" 不足以支撑 "整条应用可以不再求
值"——因为求值过程除了算结果，还负责把实参推到 WHNF，而实参的强制本身
可能有可观察副作用。

### 10.3 正确的做法（下一轮的起点）

把「实参已 force」作为**显式前提**建立，而不是把整条链丢给 memo 早退：

1. 进入 tag-2 的 `HK_DECL` 分支时，**先**照旧 force 全部实参（副作用照跑）；
2. **再**按 `(prim 名, 已 force 的实参列)` 查内容键表；
3. 命中 → 直接返回结果（此时实参强制已完成，跳过等价）；
4. miss → 执行 prim、插表。

这样第 2 版的病根（跳过实参 force）被移除，而收益的大头（省掉
`prim_exec` 的分派 + **arena 里重新分配结果**）仍然拿得到——`string_concat`
的 2.79M 次拼接里，实参 force 在"实参本就是 WHNF 叶"时是 O(1) 直通
（`prim_exec` 的注释已说明这一点），真正的成本在分配。

验证门槛照旧：`twin_engine_tests`（26）必须全绿——**它是本轮两次判负的
唯一裁判，也是这类改动唯一可靠的裁判**；再加 30 examples 逐字节 +
`tools/gate_l13.sh`。

### 10.4 方法学记录

- **`twin_engine_tests` 必须先跑**：本轮第 1 版看着有 98.6× 的漂亮数字，
  一跑就 8 红。若按"先测性能再验证"的顺序，很可能把错命中当成大捷报出来。
- **打包字当键要区分形状语义**：tag 7 是**分配地址**（同轮不复用，可当身份），
  tag 2 是**栈下标**（会复用，不能当身份）。同一个 `V.0` 字段，两种语义。
- **纯度白名单不是"可跳过"许可证**：`prim_is_pure` 的语义边界是"结果只依赖
  实参"，不含"求值过程无副作用"。任何基于它的 memo 都必须保证**实参强制
  仍发生**。

### 11.1 实现

在 `force_inner` 的 `HK_DECL` 臂，**实参 force 之后**插内容键缓存：

1. 照旧 `collect_args` + 逐个 `force`（**副作用照跑**，这是与第 2 版的
   唯一结构性差异）；
2. `prim_is_pure(pid)` 为真时算键 `(pid_code(pid), 已 force 实参打包字列)`；
3. 命中 → 直接返回（此时实参强制已完成，跳过等价）；
4. miss → `prim_exec` → 结果再 `force` → 插表。

键用**已 force 的实参**而非原始 spine，因此：不需要链头地址（pid 已编码
prim 身份）、不需要 keepalive、不受 §10.2-1 的槽位复用影响（键是值内容，
不是下标）。轮界 `force_memo_clear()` 清空。
