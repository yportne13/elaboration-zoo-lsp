## 1. 动机（L13 相对 L12 的机制缺口）

| 面 | L12（新链） | L13（移植前） | 后果 |
|---|---|---|---|
| 合一失败原因 | `UnifyKind{Absurd,Undecided,Fuel}` + `Cell`，顶层 reset、失败臂 note、调用方读取 | 只有 `UnifyError{Basic,Stuck,Trait}`；覆盖探测用 `fuel_exhausted()` 二分启发式 | "判不出"与"矛盾"不可分；预算类失败只能靠"fuel 是否恰好为 0"猜 |
| 卡住 match 自比较 | `MATCH_CMP_BUDGET = 64`（每顶层合一一份，慢路径计数），超出按无法判定失败 | 无次数上限，递归 def 每层展开新的卡住 match，只能等共享 fuel（4096）烧完 | 深/宽负载长尾（L12 同型实测 4 个 def 的 `Eq (add x zero) (add y zero)` 需 256s） |
| 覆盖判定的保守性 | 非 Absurd 的失败一律"按可达处理" | 只对 `fuel_exhausted()` 按可达处理 | 深负载下"预算耗尽"若不在 1→0 帧内会被误判不可达（静默接受非穷尽 match 的风险） |

P1.3 的目标：机制对齐（三档、预算、注入点），**不动** L13 的载体与产品语义。

## 2. 改动清单

### 2.1 `src/L13_namespace/mod.rs`

- 新增 `pub(crate) enum UnifyKind { Absurd, Undecided, Fuel }`（带 `rank()`：
  `Absurd < Undecided < Fuel`），文档注明默认 `Absurd` = 旧行为；
- `Infer` 新增 `match_cmp_budget: Cell<u32>` 与 `unify_kind: Cell<UnifyKind>`，
  `new()` / `Clone` 同步（快照复制，不跨快照污染）；
- 新增 `MATCH_CMP_BUDGET = 64`（与 L12/孪生同口径）；
- 新增 `reset_match_cmp_budget` / `burn_match_cmp_budget` /
  `reset_unify_kind` / `note_unify_kind` / `unify_kind`；
- `unify_catch` 入口增加 `reset_unify_kind()` + `reset_match_cmp_budget()`
  （对齐 L12 顶层入口）。

### 2.2 `src/L13_namespace/unification.rs`

按 L12 P3 的**同语义**在失败族注入分档（默认 Absurd 保持旧口径）：

- rename/invert/prune/solve 族失败（`invert_go`、`prune_ty_go`、
  `prune_meta`、`prune_vflex_go`、`prune_vflex`、`rename` 的 occurs/作用域、
  `solve`/`solve_with_pren` 的已解 meta 降级、`unify_sp` 长度失配）
  → `Undecided`；
- 共享 fuel 池耗尽、单次合一 `fuel == 0` 的展开重试耗尽 → `Fuel`；
- 卡住 prim 应用作不透明叶（异名/不可解）、卡住 match 非 eta 形态 → `Undecided`；
- `(Match, Match)` 慢路径前消耗 `match_cmp_budget`，耗尽 → `Fuel`
  （见 §3 偏差）；
- 兜底臂改为 `unify_no_arm`：两侧都是规范值/规范类型头（构造子、字面量、
  Sum、U、Π、λ、原生 Nat）⇒ 保持默认 `Absurd`；其余 ⇒ `Undecided`。

### 2.3 `src/L13_namespace/pattern_match.rs`

- `probe_accessible` 的可达性判定从 `unify_indices(...) || fuel_exhausted()`
  改为三档消费：`Ok` / `Fuel` ⇒ 可达；`Absurd` / `Undecided` ⇒ 不可达
  （见 §3 偏差：语义档保持产品既有判定）；
- `unify_indices` 返回 `Result<(), UnifyKind>`，逐方程重置分档与比较预算
  （对齐 L12 的"每方程一份"口径）。

### 2.4 `src/L13_namespace/bump_spine_iter/unify.rs`（孪生）

- 新增 `MATCH_CMP_BUDGET = 64`；`unify_iter` 每顶层调用一份，
  `MatchStruct` 慢路径前计数，耗尽返回 `false`（与参考侧同点、同口径）。
- 孪生的覆盖判定维持既有 `fuel_exhausted` 启发式——与 L12 同构（L12 孪生
  亦只有预算，无三档）。

## 3. 与 L12 的有意偏差（载体约束 / 产品 oracle 优先）

1. **Undecided 不参与覆盖"按可达处理"**。L12 的 σ 路线把任意非 Absurd 失败
   一律当可达（保守），L13 的 `update_cxt` 精化载体下，臂上下文可能解出
   探测期"判不出"的索引方程——L13/twin 一直把这类臂按不可达过滤，产品
   oracle（`l13_fast_parity` 的 GADT 函数索引用例）即此口径。改随 L12 会让
   `parity_review_fixes_2026_09_19` 的 `W (n => n)` 臂从 unreachable 变成
   合一错误（ref/twin 分叉，629/630）。故只对 `Fuel`（预算）做可达兜底：
   预算问题不得把可疑臂判死，语义问题保持产品行为。
2. **卡住 match 预算耗尽记 `Fuel` 而非 L12 的 `Undecided`**：L13 的覆盖
   消费者需要把"预算问题"与"语义判不出"分开（见上条）。
3. **未移植 `struct_eq` 结构快路径**：L13 无该模块；预算按"慢路径一律计数"
   适配。若后续出现合法但 >64 次慢比较的负载，先按 §5 的 `l13bench`
   代表负载确认再调参（L12 亦有同类启发式上限，文档化取舍）。
4. **未移植 `flex_flex` 反向重试（L12 review R9）与 `unify_catch` 的
   `(fuel exhausted)` 尾注**：前者是行为增强（可能新增成功合一），留作
   P1.3b 独立提交评估；后者是文案面，避免 golden 漂移。
