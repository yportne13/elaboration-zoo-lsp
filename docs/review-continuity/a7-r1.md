### 2.1 【裂缝·P1·needs-verify】L11/L12 参考版模式编译探测隔离丢失（转交 A5）

- **位置**：`src/L11_macro/pattern_match.rs:174-178`、
  `src/L12_canonical/pattern_match.rs:176-180`（同构副本）。
- **证据**：
  - commit `165313d "perf(pm): do not clone infer"` 把
    `let mut temp_infer = infer.clone();` 注释掉，`check_pm` 直接跑在主
    `infer` 上——探测（逐构造器 `Raw::Hole` 应用 + `check_pm` 合一）分配的

    注释明言"可访问性判定在 **metas 快照换入换出**的 temp-infer 里跑
    check_pm（参考版克隆 `temp_infer` 的对应物）"，实现在
    `run_pure_probe` 快照/回滚入口内（L11 twin :5955 一带；L12 twin 同构；
    commit 8a79162 统一抽出）。
  - 相邻层参考版：L09（`pattern_match.rs:204`）、L10（`pattern_match.rs:182`）
    保留 `temp_infer = infer.clone()`；L13 恢复了窄快照
    （`pattern_match.rs:270-334` 只快照 meta/trait_metas + 快路径提前 return）。
    **L11/L12 是全链唯一失去探测隔离的两层**（双向裂缝：参考版内部语义
    L10→L11 退化；参考↔孪生行为分叉）。
- **为什么 parity 测试没抓住**：探测泄漏 fresh meta 会移动 `?N` 编号，而
  parity 比对前对 `?N` 做归一化（`tests/l11_fast_parity.rs:31-35` 文档化
  偏差）——编号漂移被掩盖；探测期误解程序 meta 的触发器静态读码未能构造
  （需"被匹配索引类型内含已解 meta"的 match 场景），标 needs-verify。
- **分类**：裂缝（perf commit 牺牲隔离，非有意契约变更——无测试/文档锚定）。
- **处置**：仅报告，转交 A5。建议修法：保留 165313d 的性能意图，按 L13
  `pattern_match.rs:270-334` 的窄快照（meta/trait_metas 换入换出）恢复隔离，
  与孪生 `run_pure_probe` 对齐；补一条"探测不改变 ?N 序列"的回归探针
  （不做 ?N 归一化的直接比对）。

### 4.6 L13 compact.rs（d711fde）下沉评估（专项结论）

**判定：L13 twin 专属，不下沉。**
- 机制：bump arena 不回收中间值，`compact.rs`（625 行）把可达图按旧指针
  memo 深拷进新 bump 后整体弃旧（常驻 1835MB→429MB，峰值 1847→730MB）。
- 不下沉理由：收益前提是**常驻会话**里"可达稳态 << 已分配 bump"——只有
  L13 孪生是常驻生产引擎（LSP twin_engine，prime 24 文件 prelude）。
  L02–L12 孪生的部署形态是一次性 bench/测试进程；稳态复用（`Tycker` 的
  `bench_nf_impl` 每轮 `bump.reset()`）已给出内存上界且容量跨轮重用，
  无跨轮垃圾累积问题。压缩机制本身与语义无关，属于部署形态差异而非
  继承裂缝。
- **可存档的通用移植要点**（若未来低层孪生常驻化）：①可达根枚举清单
  （cxt/decl 表、metas 含 MetaSnap 快照、会话全局、machine.defs、spine 栈、
  导入表——d711fde commit message 逐项列出）；②按旧指针/旧打包字 memo 的
  DAG 深拷（立即数 tag 原样 + 下标因保序拷贝 spine/defs 仍有效，指针 tag
  深拷+remap）；③`&str` 按指针 intern 保共享；④与 bump 无关的状态
  （TraitState/Synth/symbol_table 等）跨 swap 原样存活；⑤新容量按上次
  实测 live×2 提示，防 bumpalo 倍增过冲；⑥留 `TYPORT_TWIN_NO_COMPACT`
  类开关保 A/B 对照。
