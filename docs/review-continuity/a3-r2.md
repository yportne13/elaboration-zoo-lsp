### 2.2 [P2·刻意分歧·维持] A4 转交的 η applicability 守卫——裁决：不可达
A4 论据："L07/L08 有 `get_global`（可变全局），触发面比 L09/L10 更实"。
逐条对质（全部行号为当前工作树实测）：

1. **`get_global` 的值进的是项位置，不是类型位置。** 其 builtin 类型是
   动态协议 `(x : String) -> string_to_global_type x`
   （L07 cxt.rs:103-107，L08 同构）：表达式 `get_global "g"` 的**推断类型**
   由 `string_to_global_type "g"` 归约给出（登记名→登记类型；未登记名→卡住
   Decl 逃逸舱口），与 mutable_map 里存的**值**分属两条轨。λ 要进 unify 的
   η 臂（L07 unification.rs:672-685 的 `v_app` 两侧），必须先占住一个类型
   位置（注解 eval、decl 类型、codomain）。
2. **唯一的值→型提升通道在存值侧被同一动态类型封死。** 类型位置 eval 出 λ
   的唯一形态是注解 `def X : get_global "g" = …`，它要求
   `check(get_global "g", U)` 通过，即 `string_to_global_type "g" ≡ U`，即
   "g" 以类型 U 登记；而 `create_global` 的第二实参域恰是
   `string_to_global_type x`（L07 cxt.rs:89-93）——存入值当年就被**同一个**
   动态类型 check 过，g 以 U 登记则存的必是类型不是 λ。存/读两侧共用
   `string_to_global_type "g"`，值与型恒一致，λ 只能存进 Π 型名字下，而
   Π 型名字的 `get_global` 永远过不了 check(_, U)。
3. **L06 的触发源在 L07/L08 已被重构堵死——这正是 r1 登记的"源头关闭"。**
   L06 cxt.rs:88-91 `string_to_global_type` 返回 `e.vt`（登记**值**，可为
   λ；L06 unification.rs:10-15 注释自证"λ 值会以类型身份流入 unify……源码
   级可达"）；L07/L08 同函数改为 `Some(e) => e.ty.clone()`
   （L07 mod.rs:528-531、L08 mod.rs:533-536，注释"登记名给登记**类型**"）。
   A4 的"更实"推断没有追踪这条 vt→ty 重设计。
4. **L07/L08 的 `v_app` 比 L06/L09 宽容得多，panic 面更小。**
   L07 mod.rs:713-727：全部中性头——Lam/Flex/Rigid/Decl/Obj/Prim/**Match
   （收 pending）**——都可应用；panic 仅限规范非函数值（U/Pi/Sum/SumCase/
   LiteralType/LiteralIntro）对 λ 的"类型混淆对"。快版 `vapp1`
   （bump:950-1012）同形：panic 仅 tag 3/4/6 与 XCell::Lit/Sum/SumCase，
   其余全 `spine.push`。对照 L09：其 `v_app` **缺** Match pending 臂
   （L09 mod.rs:3-7 自证 "Val::Match 经 v_app 会 panic impossible apply"）
   ——A4 在 L09/L10 需要守卫的形态（卡住 match vs λ）在 L07/L08 被
   pending 吸收**合法处理**，不 panic。
5. **A4 自己登记了 L09/L10 无端到端触发例**（a4-r1 §6-2："现无端到端触发
   例……守卫为纯 hardening"）。L07/L08 的条件只会更严（第 2-4 条），更不
   存在触发例。
6. **其余 η 臂入料面也封死**：pm 臂先于 η 臂拦截可解 rigid 对任意值
   （unification.rs:633-654 / bump:2750-2761），`pm_solve` 只记录带环守卫
   （mod.rs:334、:958）不 v_app；SumCase datas 合一是同构造子同槽同域类型
   （unification.rs:716-731），λ 侧出现则对侧同为 λ 或中性（中性全可应用）；
   check 的 λ 臂要求 Val::Pi（elaboration.rs:78），λ 推断产 Pi
   （elaboration.rs:476-487）。

**结论：守卫在 L07/L08 为死代码，按 BRIEF §2 适用性判据不移植，维持
r1 刻意分歧**；A4 无需进一步动作（回执见 §4-4）。
