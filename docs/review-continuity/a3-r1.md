### 刻意分歧（保留，锚点见 §5）

- **L07/L08 pretty `go_app_pruning` 只显示内核 + `go_ix` 越界退化 `@{ix}`**
  （port-audit 表"✅(部分)"的缺失半边）：与 L06/L13 的掩码感知 `go_pr_inner`
  不同。**无 panic 残留**（两层的"部分"只差渲染信息量）；且 L07/L08 所有
  pretty 调用点都吃 quote 产物，quote 对 Flex 产 `Meta`+实参链、不产
  `AppPruning`，elaboration 错误路径也不 pretty 裸项（L09 修的 `_.foo` 路径
  在 L07/L08 不存在）——掩码渲染在本层**不可达**，按 port-audit 自己的
  "移植即死代码"判据不移植。孪生无独立 pretty 拷贝（`use super::pretty`）。
  已登记 L07 README §7-5 / L08 README §7。
- **`v_applicable` η 守卫不移植**：L06 触发链是 `string_to_global_type` 返回
  登记**值**（cxt.rs:90 `e.vt`，可为 λ）以类型身份流入 unify；L07/L08 同
  builtin 返回登记**类型**（mod.rs:528 `e.ty`，经 `check_ty` 对 U 检查，λ 不可能
  成为类型值）——触发路径在源头关闭，守卫在本层为死代码。
- **L08 孪生 MatchStruct 屏障 vs L07 孪生前置结构检查**：L08 为 Err 正文
  逐字节 parity 升级而重构（c5ef047/79410ee）；L07 的 parity 合同只锁 Err
  判定（README §10），前置检查的偏差已文档化且不可达（unify 错误均致命）。
  重构穿 fuel/副作用时序，代价 > 收益，不回合。
- **intersect_bump 的 Obj 头守卫仅 L07 有**：L08 新增 `(Obj,Obj)` unify 合同臂
  后，Obj 对回落 unify 可合法成功，守卫前提消失——同源代码不同语义环境。
- **全局哨兵**：L07/L08 decl 表按名设计，`1919810`/`GLOBAL_BASE` 族不适用。
