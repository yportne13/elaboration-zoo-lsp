# L07 ⟷ L12「共有部分」实现差异 · 事实底稿与协作约定

> 用户问题：**L12 和 L07 共有的那部分实现，是不是同一份（一脉相承）？差异在哪、性质是什么？**
> 用户原始预期：**这两层应当一脉相承。**
> 本轮：HEAD `8f4287ae`（master，2026-11-24）。只读分析，**不构建**。
> 背景：上一轮 `docs/compare-l07-l13-shared/` 做过 L07⟷L13；本轮对象换成 **L12**，
> 结论**不能**从那边平移——L13 是断点，L12 不是。本轮数字全部在本轮代码上重新核。

## 0 为什么这轮的答案会和上一轮 L07⟷L13 完全不同

上一轮（L07⟷L13）的结论是"语义前提层断裂"。**不能把那个结论套到 L12 上**：
机械度量显示 L12 几乎是 L07 的**超集**——31 个同路径文件里，**24 个保留了 L07 90% 以上的归一化 token
流**，2 个**逐字节相同**（`pattern_match.rs`、`syntax.rs`），只有 7 个低于 90%。
所以本轮的真问题不是"是不是两套机器"，而是：

1. 那 7 个"漂移文件"里，哪些是**本章有意增量**（L08–L12 的新特性），哪些是**无意漂移**（L07 的修复/加固/优化没跟过来）？
2. L12 **落后于 L07** 的地方有哪些（L07 在 11 月做了很多加固，L12 的孪生侧最后一次重建在 11-17）？
3. `observe.rs` 整个文件在 L12 不存在（L07 有 296 行，11-21 才加入）——L12 的观察面到底承接了多少？

L12 的唯一大块"单边新增"是 typeclass / Call 节点 / canonical trait 求解（本章主题）。

## 7 复算方法（Lead 口径）

- token：手写 Rust 扫描器，跳过 `//`、嵌套 `/* */`、`"…"`、`r#"…"#`、char/lifetime；
- shingle：连续 6 token 串联；`keep07` = 交集 / L07 侧 shingle 数；`jac` = 标识符归一化后交/并；
- 复算产物：`tmp/l07l12-similarity.tsv`；机制矩阵：`tmp/l07l12-mechanism-matrix.txt`。
  **这只是筛子**：它只能说明"逐字保留了多少"，不能判断语义是否等价——那是各分析员的工作。

## 9 分类判据：什么才算"共有的部分"

同时满足：**同一角色** + **同一位置**（同路径/同模块）+ **两侧都在用**（不是死代码）。
L12 独有特性（typeclass、Call 节点、canonical trait 求解、parser/macros）算 E4；
凡被 L12 新代码路径**复用/改写**的 L07 旧机制，算"共有部分的漂移"。
