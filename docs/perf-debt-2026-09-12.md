## P1 参考版 L07-L09：`SumCase.datas` 按值持有 → 依赖 match 自递归链 O(n²) ✅ 已修

- **症状**：natadd（`add x y = match x { case succ(n) => succ (add n y) }`，
  `p{i} = add p{i-1} p{i-1}`）参考版 k=9/10/11 = 0.22/0.93/4.74 s
  （×4.2/翻倍 = O(n²)），k=12 = 25 s / **24.8 GB RSS**；孪生全章线性
  （0.9 ms @k=11）。
- **根因**：`Val::SumCase.datas: Vec<(Span<String>, Val, Icit)>`
  （L07-L09 参考版）——match 提取字段 `n` 即深拷贝剩余 succ 链，第 j 步拷
  O(n−j) → 单次 add O(n²)。同源对照：L10 起字段是 `Rc<Val>`，提取 = 引用
  计数 +1，实测线性。
- **修法（已落地）**：L07/L08/L09 参考版 `Val::SumCase`（`typ: Box→Rc`、
  `datas` 元素 `Val→Rc<Val>`）与 `Sum` 参数槽（值/类型槽 `Rc<Val>`）迁移；
  `eval_aux` 改借用传递（head 字段 clone O(1)）；消费型路径（quote/rename/
  project）经 `rc_take`（独占零拷贝、共享深拷贝，与迁前克隆语义逐字一致）。
- **实测**（basic，min）：natadd k=9/10/11/12/13 = L07
  2.71/4.98/10.50/21.88/51.79 ms、L08 2.46/4.68/9.59/22.49/55.84 ms、
  L09 2.40/4.42/8.90/21.59/57.85 ms（×2/翻倍，线性；旧 k=11 = 4.74 s、
  k=12 = 25 s）。孪生 fast 同批 0.24/0.45/0.90/1.8/3.6 ms 未动。
  church（修复外负载）同批 basic 17.3/17.0/16.3 ms @k=13，与矩阵
  修复前 18.4/18.1/19.6 同档，无回归。
- **验证**：三章 lib + l07/l08/l09_fast_parity 全绿（682 lib + 全部 parity
  套件通过）。

## P2 孪生 L09/L10：`bind_name` 每 binder 整表克隆（universe 残留平方项）✅ 已修（2026-09-13，全局名字搬 Machine）

- **症状**：同一 universe 源（1029-4096 defs），L09/L10 孪生 65 ms
  @k=11（16 µs/decl，×4/翻倍），L11/L12 孪生 1.8 ms（0.45 µs/decl），
  L13 孪生 3.45 ms——同源同参差 19-35×。
- **根因**（比「bind_name 克隆」更深一层，探针实测）：L09/L10 孪生把
  **顶层 define 累积进 Cxt 的 names 快照**（`define_name_in` 每 def 插
  by_name+by_lvl 各一条，fake_bind 占位再插 `by_lvl[GLOBAL_BASE+idx]`，
  表大小 O(D)）——`bind_name` 每 binder 克隆整表只是它的下游表现。
  L11+ 孪生全局走 decls 表、names 只装当前 def 的 binder，故天然免疫。
  另有同量级残余：quote/eval/unify 包装器每次 `neutral_of(&self.globals)`
  **整拷 globals Vec**（O(D)/次）。
- **修法（已落地，弃 trail 方案）**：与 L11+ 对齐的架构搬运，无 trail、
  无 unwind 纪律，两章同构：
  1. Machine 增 `global_names: FxHashMap<SmolStr, (u32, V)>`（append-only
     不随 Cxt 克隆）：`define_name_in` 真名插此表并撤除局部 names 的
     fake 占位（by_name 旧键即 by_lvl 键）；`bind_name`/`define_name`
     （Let 局部）不动；Var 臂局部优先、回落全局表（遮蔽序不变）。
     refresh 改为只更新局部条目——过去的 define 定义早于当前局部层级、
     其类型不提及它们，重锚为恒等，跳过无语义差。
  2. Machine 增 `neutral: Vec<V>`（`neutral[i] == v_lvl(i+GLOBAL_BASE)`
     随 globals 同步 push），包装器解构字段借用替代 `neutral_of` 整拷。
  3. `update_cxt` 的 names 整表克隆（opt-name-table-cow 残留项 2）随
     局部表恒小同步 O(1)。
  途中试过 `im` 持久化 HAMT 替代克隆（63→11.4 ms，仍 ×2.4/翻倍）——
  表仍在累积，HAMT 常数与缓存行为拖尾；搬运后局部表恒小（个位数
  条目），FxHashMap 直接克隆即 O(1)，im 依赖已撤。
- **实测**：universe 孪生 L09 k=11/12 = 2.73/3.21 ms（63.1 → **23×**），
  L10 k=11 = 1.68 ms（63.7 → **38×**），增长因子 ×1.2-2.1/翻倍（线性）；
  四章 universe 拉齐到 L11 1.81 / L13 3.45 ms 同档，19-35× 差距消失。
  回归批：L09 church k=13 = 2.06/18.3 ms、natadd k=13 = 3.33 ms、
  match k=11 = 0.60 ms（受益，原 0.85）；L10 church k=13 = 1.95/8.48 ms、
  natadd k=11 = 1.20 ms；L13 strchain k=11 = 12.3 ms、prelude-hdl
  2292 ms——全部持平或改善。
- **验证**：lib 682 + 全部 parity 套件（l07-l13 共 666）全绿。

## P3 共享：pretty 打印深链 O(n²)（L11+ 全流程口径被输出绑定）✅ 已修

- **症状**：church（L11/L12 逗号复活版，生成器带 `println p{k}`）两版

  140 ms 全在 pretty。
- **根因**：`pretty_tm` 对嵌套链逐节点 `format!` 拼接，深度 d 处的字符串

  任何字节只写一次；`pretty_tm` 保持原签名（分配 + 调 go），全部调用点
  不变。需要整体子串做决策的臂（Sum 参数表、Match 分支体括号截断判定、
  Pi binder 域类型）仍走小串渲染。输出逐字节不变。L13 pretty 结构不同
  （indent/Call/Nat 糖）且实测无平方症状（church k=13→15 线性），未动。
- **实测**（k=13，min）：L11 全流程 basic 7.26 ms / fast_run（孪生含
  println）4.10 ms / 孪生 bare（check+quote）1.56 ms；L12 7.17 /

  natadd（修复外负载）basic/fast = 7.55/3.84、6.86/3.85 ms，与矩阵
  修复前 7.79/3.82、6.74/3.89 同档，无回归。
- **验证**：黄金锚——临时集成测试把 church_src(k=9/11/13) 喂参考版

  一致；l11/l12_fast_parity 37/36 全绿。测试已删，结论记录于此。

## P4 L13 bench 路径：孪生 strchain O(D²) ✅ 已修（根因与原猜想不同）

- **症状**：L13 孪生 strchain k=9/10/11 = 228/933/3798 ms（×4.1/翻倍）；
  同源同参的 L11 孪生 2.81 ms。
- **定位（L13DECL_PROBE 分相计时，替代原 LSP 观察面猜想）**：bench 计时
  路径是 `bench_check_nf_bounded`（无 CheckIssues 排水），逐 decl 耗时
  线性增长（256→768 decl：116→341 µs）。分相探针钉出两个 O(D) 相位：
  1. **`tm_scan_global_ops` 引用链重扫**：Def 臂的 replay 探测每 decl 扫
     body 引用的 def 链，`scan_def_replay` 递归**不查** `mutable.replay`
     memo（memo 只在顶层 `def_needs_replay` 生效）→ 依赖链每 decl O(D)。
  2. **eval 期急切纯 prim 归约**：`vapp1` 对 prim 头即时 `prim_exec`，
     strchain 每层实参已是上一层物化好的字面量 → 每层 concat 拷贝 O(i)
     字节（参考版 `v_app` 同急切，参考版 4624 ms 同病；L11 孪生无此形态
     故 2.81 ms）。
- **修法（已落地）**：
  1. `scan_def_replay` 加 memo 读 + **带截断守卫的 memo 写**（子扫描命中
     visiting 环守卫的结果可能是保守假，不入表；链形/树形引用全程干净、
     每 decl O(1)）。参考版同病未动（可读规格定位）。
  2. `vapp1` 增 `lazy_pure_prim` 语境参数：**eval 层纯 prim 不再执行**
     （值保持中性，归约统一留给 force——最终 quote/force 一次 O(n)）；
     非纯 prim（create_global/file IO/vconnT 等副作用）保持 eval 点急切，
     副作用时机不变。force 入口（`force_inner` HK_DECL 臂）补「实参先
     force 再交 prim」（参考版 force 同款纪律）；`prim_exec` 入口统一
     把实参 force 到 WHNF（非纯 prim 直呼时实参可能是惰性中性，不 force
     则形状检查失准——曾破坏 vconnT parity，由此修复）。
- **实测**：strchain 孪生 fast k=9/10/11/12 = 2.84/5.63/12.01/25.86 ms
  （×2.0-2.2/翻倍，线性；修复前 k=11 = 3798 ms，**316×**）；church
  k=13 basic/fast = 22.53/3.80 ms（修复前 fast 17.00 ms）、natadd
  fast 3.16 ms（修复前 20.85 ms）——同改动连带受益；prelude-hdl
  2334.6 ms（基线 2385 ms，无回归）。
- **验证**：lib 682 + 全部 parity 套件（l07-l13 共 666）全绿；strchain
  nf=1 两版一致。

## P5 traitchain 两处（本轮完成 L12 孪生失败的精确定位，未修）

  重复劳动（疑似每次 `.say` 全表重扫）；低优先（L10 是教学中间层）。
- **L12 孪生 parity 失败（定位结论）**：`impl[T] Say for T` 毛毯实例
  （need_create=false、带类型参数）在孪生上必败、与链深无关；`impl Say
  for Nat`（具体实例）两版一致通过。失败链：ImplDecl 臂把实例记录折叠成
  `Decl::Def{params:[T], ret_type: Say[T]}` 交 `infer_decl` → Def 臂
  `check_universe(Π[T: Hole]. Say[T])` → Π 域 Hole 的 check_universe 在
  **binds=1**（参数循环里同 Hole 在 binds=0 通过）返回
  `expected universe, got Π(T: U(0)). U(0)`（tag=4 实 Pi，探针实测）——
  即域 Hole 的双 meta 展开（`?k1: U(0)`、`?k2: Flex(?k1)`）在非空
  pruning 下经 quote/close/eval 往返把 ?k2 的类型物化成 Π 值，而非
  Flex 形态进入 check_universe 的 Flex 臂（参考版同构代码 Flex 臂可解，
  孪生在 meta 生命周期/表示差异上走样）。**未修**：修复需动孪生
  fresh_meta/close_tm/insert 的 meta 表示或 check_universe 的臂序，
  属语义级改动，需专项设计 + parity 兜底；L11 孪生生成器无毛毯实例
  用例（`impl ToString for Bool`），故同缺陷未在 L11 暴露。
