# L13 行为基线快照（2026-11-17，重定基 P0）

本文件是 `docs/l13-rebase-plan-2026-11-17.md` 的 P0 产物：在任何 L13 重定基
尝试之前，先冻结 L13 当前产品层的行为基线，供后续每阶段回归对比。

## 1. 快照内容

- 生成脚本：`tools/l13_rebase_baseline.ps1`（增量、断点续跑、单次默认最多 8 个）
- 基线表：`tools/l13_baseline_2026-11-17.tsv`（TSV：`Path / Mode / Verdict / Sha256`）
- 覆盖：`examples/` 下 32 个 `.typort` 示例（25 个 `examples/hdl/*` 用
  `--with-prelude hdl`，其余用 `--with-prelude core`）；**当前首批已采 11 个**
  （2 个 core + 9 个 hdl），其余按需增量补齐（见 §3 断点续跑）；
- 采集口：`target/release/l13bench.exe --file <f> --with-prelude <mode> --rounds 1`
  的**判定行**（`-- 名 (decls) nf=K` / `BOTH-FAILED` / `DIFF`），计时被丢弃；
- 判定行同时是参考版↔孪生的互检结论（`l13bench --file` 内部跑两版），因此
  一行 diff 表示“两版都改变/分叉”，适合作为重定基回归 oracle。

## 3. 使用方式（增量采集与重定基回归）

> **运维约束（2026-11-17）**：l13bench 的 hdl prelude 示例单次就数秒，一次性
> 跑满 32 个会把长任务/内存压力带进 DSH。脚本默认每次最多 8 个、逐行落盘，
> 中断后重跑自动跳过已完成路径；**不要再起一次性全量批量**。

```powershell
# 每次最多 8 个，重复执行直到 remaining == 0
& ./tools/l13_rebase_baseline.ps1
```


```powershell
# 1) 重新生成当前树快照到临时文件
& ./tools/l13_rebase_baseline.ps1 -Out tools/l13_baseline_current.tsv
# 2) 与冻结基线比较（只比 Path/Mode/Verdict，Sha256 列可先剥掉）
git diff --no-index -- tools/l13_baseline_2026-11-17.tsv tools/l13_baseline_current.tsv
# 3) 判定行差异逐条归因；任何非“有意行为变更”即回退
```

注意：
- 基线中的 `decls` 数受 prelude 规模影响——若重定基阶段**有意**改变 prelude
  装载/合并方式，需要先评审并重新冻结基线，而不是把 diff 当回归；
- 只跑一次（`--rounds 1`）够用：判定/nf 与轮数无关，计时才需要多轮；
- 若 `l13bench` 本身被改（如 `--file` 输出格式变化），基线需同批更新。

## 4. 覆盖缺口（已知，留给 P1+ 补）

- `examples/` 只覆盖产品层常见路径；HDL 的 inout/crossclock/verilog-compat
  在 `src/L13_namespace/hdl_*_tests.rs` 与 `verilog_compat_tests.rs` 中（由
  `cargo test --lib` 覆盖，见 §2 表）；
- prelude 宏库的逐文件成本/规模效应不在本表（`--prelude-files` 诊断口留给
  P2 prelude 合并阶段）；
- LSP 端到端（hover/completion/goto）不在本表；P4 阶段需另建 LSP 冒烟基线。
