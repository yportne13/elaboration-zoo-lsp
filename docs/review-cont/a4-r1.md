## 1. [P0] 快版整机重借 Stacked Borrows 别名 UB —— 本轮已修（挂起-续跑驱动）

### 1.1 重新评估：为什么"拆不相交字段自由函数"不可行

任务设想的修复方向（把 `metas` 可变访问单独拆出、solve 系列改传不相交参数）经溯源**不可行**：
`solve_multi_trait_ref → solve_trait_ref` 的成功路径调用
`self.infer_expr / self.insert / self.eval / self.unify`（修前 L10 `bump_spine_iter.rs:3857-3865`
同构三章）——整套 elaborator 以 `&mut self` 整机运行，其写集 = 整个 Machine。SB 是按字节位置的
模型，回调需要整机独占写权限就必然与 `unify_iter` 存活中的字段借用（`spine/vals/.../conv/memo`
以及 `while let Some(item) = stack.pop()` 的 `stack`）冲突，无论从哪个方向派生指针。
结论：唯一健全结构 = **回调时不存在存活字段借用**。

### 1.2 实施的修复（三章节同构，最小外科）

把 3 个回调点改为**挂起信号**，`unify` 改为**驱动循环**：

- `unify_iter` 签名：`- mach_ptr: *mut Machine, - cxt, - trait_err`（后两者在回调移除后死亡，
  一并删除避免 unused 告警）；`+ resume: bool, + solve_req: &mut Option<u32>`。
- 3 个挂起点（修前行号 L10 `:2232/:2347/:2370`、L11 `:2385/:2501/:2524`、L12 `:2436/:2552/:2575`）
  改为：先恢复 `conv.scratch*`（原 Err/Ok 两路都恢复，等价合并）→ `memo.insert` →
  `*solve_req = Some(m); return false;`。
- 入口块（conv 清空 + `debug_assert!(stack.is_empty())` + 初始 `stack.push(Pair(l0,t0,u0))`）
  与驱动的 `work/stack.clear()` 全部 gated `if !resume`。
- `unify` 驱动：`loop { 重新解构 Machine 字段 → (cast) work/stack → if !resume clear →
  unify_iter(...) → true 即返；solve_req.take() None 即真实失败返 false；
  Some(m) ⇒ self.solve_multi_trait_ref(bump, cxt, m)（Err ⇒ *trait_err + false）；
  resume = true }`。修后锚点：挂起点 L10 `:2248/:2358/:2373`、L11 `:2401/:2512/:2527`、
  L12 `:2452/:2563/:2578`；驱动 take 行 L10 `:3771`、L11 `:3977`、L12 `:4053`。
- `mach_ptr` 全部消除（grep 仅剩注释里的历史说明）。

### 1.3 静态论证（SB / 借用）

1. **借入不相交 / 无重叠存活**：驱动内字段解构（`let Machine {..} = self`）派生的全部引用
   （含 unsafe cast 得到的 `work/stack`——cast 切断与 self 的 borrowck 血缘，仅元素生命周期改写）
   的**最后使用 = `unify_iter(...)` 调用**（NLL 可验证）；`self.solve_multi_trait_ref(...)`
   运行时无任何字段借用存活，下一轮循环重新解构。这就是 borrowck 自己会接受的"循环内重新
   split borrow + 中间整-self 方法调用"标准形态——**除既有 `W<'static>→W<'a>` 元素生命周期
   cast 外，新结构无 unsafe、无裸指针**。
2. **SB 视角**：每轮循环的字段标签在 `&mut *self`（方法接收者 reborrow）之前已死；
   使用旧标签不再发生（`unify_iter` 返回即弃）。不存在两条整机 `&mut` 血统并存的时刻。
3. **行为等价**：
   - `resume` 跳过入口 clear 与初始入栈 ⇔ 旧代码"回调返回后 `continue` 继续弹栈"——
     工作栈/记忆表/草稿全住 Machine 字段，内容跨挂起点保持。
   - scratch 在挂起前恢复：嵌套 unify 入口本就 `conv.scratch*.clear()`（take-then-clear
     纪律，全文件核对），内容不承载语义。
   - 唯一 delta：`memo.insert((t,u))` 从"回调后"移到"回调前"——若合成触发嵌套 unify，
     该单条会被嵌套入口 clear 抹掉。memo 是成功单调 cache（`:2126` 注释），且**旧实现里
     嵌套 unify 的入口 clear 本来就抹掉整个 memo**——丢一条 entry 只影响性能，不影响判定。
   - solve Err 路径：旧 = 回调内 `*trait_err; return false`，新 = 驱动同款，等价。
   - `debug_assert!` 只在非 resume 路径（resume 时栈非空是设计）。
4. **残留 unsafe**：仅既有 `'static` 槽位元素生命周期改写（SAFETY 注释保留），与本别名问题正交。
5. **建议**：仍应跑一次 Miri（`MIRIFLAGS=-Zmiri-strict-provenance cargo miri test`）作终裁。
