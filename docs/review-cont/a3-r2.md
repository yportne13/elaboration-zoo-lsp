## 2. 任务 1：失败探针 `parity_enum_struct_impl_hole_pinned_u`（fast=Err）的根因与修复

### 根因（不是钉 U 不完整）
- 失败输出 `expected universe, got V(10)` 来自**快版 `ty_precheck`**
  （`src/L08_product_type/bump_spine_iter.rs:5251` 修前）。`V(10)` = tag 2
  spine 链（idx 1）——即 README 描述的「部分应用 meta」链。
- L08 快版 `Decl::Enum` 臂的钉 U（R1 回移）**本身是完整的**（与 L07 逐字同）。
  但钉 U 后 elaborate 走到更深的位置，踩中 L08 快版 `ty_precheck` 里一个
  **L07 已修而 L08 未跟进**的 bug：

  ```rust
  // L08 修前（内联 naive 版）：只看链句柄槽的 f 字段
  2 => v_tag(self.spine.stack[v_spine_of(v)].f) == 5,
  ```

  对于 **≥2 实参的 flex 链**（`?m a b`），句柄槽的 `f` 指向的是**去掉最后
  一个实参的子链**（tag 2），不是链头 meta（tag 5）→ 误判为非 flex →
  误报 `expected universe`。L07 快版的同位置早已换成共享 helper：

  ```rust
  // L07（bump:589 已有 helper；ty_precheck :5138 调用）
  fn is_flex(spine: &Spine, v: V) -> bool {
      match v_tag(v) {
          5 => true,
          2 => v_tag(spine.spine_head(v_spine_of(v))) == 5,  // 走 spine_head 找真头
          _ => false,
      }
  }
  ```

  L07 的注释原话即点名该 bug：「只看栈顶槽的 f 会把 ≥2 实参的 flex 链误判
  成非 flex」。这是又一个「优秀修复只落在 L07」的实例——L08 孪生从 L07
  移植于该修复之前（或未同步该 hunk）。修前 L08 测试全绿只是因为既有测试
  恰好不构造「钉 U 后仍产生多实参 flex 链」的形态。
- 参考版无此问题（`Val::Flex(_, _) => Ok(())` 对 spine 形状不设限）。

## 3. 任务 2：L09 Obj 三件套移植（R1 路由项，本轮完成）

### 3.1 参考版剥链精确化（`src/L09_mltt/elaboration.rs:455-484`）
- 显式字段 binder 的实例化：`Val::U(0)` 占位（`//TODO:not Val::U(0)`）

  `P e.witness` 而非 `P (U 0)`。
- 隐式参数实例值：从「反转全部 params 盲 pop」改为**只取 Impl 过滤后
  按声明序**（L08 同款；显式索引不再错占槽）。

### 3.2 参考版 (Obj,Obj) 合同臂（`src/L09_mltt/unification.rs:551-559`）

### 3.4 快版 (Obj,Obj) 合同（`bump_spine_iter.rs` 两处）

### 3.5 新探针（`tests/l09_fast_parity.rs::parity_struct_dependent_field_projection`）
```
enum Nat / enum Eq[A](x,y) / def two
struct Ex { witness: Nat; proof: Eq witness two }
def p = Ex.mk two (refl two)
def get_proof(e: Ex): Eq e.witness two = e.proof   ← 触发线
println (get_proof p)
```
- 触发链：`e.proof` 检查位合一 `Eq e.witness two ≡ Eq e.witness two` →
  Sum/Sum 参数槽 zip → stuck Obj 对 → (Obj,Obj) 合同臂按接收者判等。
  **修复前**：`e.proof : Eq (U 0) two` → 参数槽 `(U 0) ≡ stuck Obj` 失败
  → 两版一致 Err（假拒）；**修复后**两版 Ok。
- 探针断言 `run_basic(src).is_ok()` + `assert_parity(src)`——比纯 parity
  更强：钉住「必须通过」（否则修复回退即失败）。无需显式隐式实参供给
  （`Eq`/`Ex` 的隐式参数全部可推断），规避 L09 语法面不确定区。
- 设计参照既有 `parity_eq_proofs`（Eq/证据打印已有覆盖，SumCase 打印
  路径安全）。
