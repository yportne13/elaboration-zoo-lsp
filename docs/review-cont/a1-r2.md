## 3. 四个核查点逐项结论

### 3.1 等价性 / resume 现场恢复 —— 通过

挂起时的现场：工作栈 `unify_stack`（剩余 UItem）、`conv.memo`、
`conv.scratch*`、`unify_work` 全部住在 Machine 字段；挂起返回路径不触碰
它们，驱动在两次 unify_iter 之间只调 `solve_multi_trait_ref`。逐路径对照：

| 旧实现路径 | 新实现路径 | 等价? |
|---|---|---|
| solve_bump Ok → 回调 Ok → memo.insert → `continue` 弹栈 | solve_bump Ok → scratch 恢复 → memo.insert → 挂起 → 驱动合成 Ok → resume=true → 续弹栈 | ✔（合成不触发嵌套 unify 时，栈/memo/草稿原样跨挂起点） |
| 回调 Err → `*trait_err` + scratch 恢复 + return false | 挂起 → 驱动合成 Err → `*trait_err` + return false（scratch 已在挂起前恢复） | ✔ 终态相同 |
| solve_bump !Ok → return false | return false（solve_req 不写） | ✔ |
| 栈耗尽 → true | 栈耗尽 → true（resume 与否同一路径） | ✔ |

solve_req 残留分析：写入点全部 `return false` 紧随，无「写后继续执行」；
驱动 `take()` 恒清空；`true` 出口不读它；变量是驱动局部、随调用消亡——
跨轮、跨调用均无残留误续跑 ✔。嵌套时也安全：每个驱动层有独立局部
solve_req，unify_iter 只见自己驱动的 `&mut`（§3.2）。

scratch 恢复时序：旧 Err/Ok 两路都恢复（旧码两次写），新码合并为挂起前
一次；恢复值是 solve_bump 已消费的死状态（入口与每次 take-then-clear
纪律下内容不承载语义）✔。

### 3.2 嵌套挂起 —— solve_req 无交叉污染；**共享工作表有先在共模隐患（§4）**

嵌套 unify 静态确认可达：`solve_multi_trait_ref → solve_trait_ref` 的成功
路径在三章均调用 `self.infer_expr / self.insert`（可经 check/infer 的
unify_catch → `Machine::unify`）与 SumCase 类型把关 unify（L10:3873 /
L11:4085 的 `let _ = self.unify(..)`、L12:4157 的 `let _ = self.unify_catch(..)`）。

- **solve_req 本体**：每层驱动局部，不可交叉污染 ✔。
- **共享字段（unify_stack/unify_work/conv.memo/conv.scratch*）**：嵌套
  unify 入口（驱动 `work.clear(); stack.clear();` + unify_iter 入口三清）
  会**抹掉外层挂起现场**——外层 resume 后弹到的是空栈（嵌套成功耗尽）或
  嵌套残留项（嵌套失败早退）。**这在旧实现同样发生**（旧回调在外层工作
  栈存活时执行，嵌套 unify 走同一共享字段、同一入口 clear），A4 改动
  忠实保持了该行为——不是回归。展开定级见 §4。

### 3.3 memo 单条丢失 —— A4 的「纯 cache 损失」结论成立（且比自述更窄）

A4 自述唯一 delta：`memo.insert((t,u))` 从回调后移到挂起前，若合成触发
嵌套 unify，该条被嵌套入口 clear 抹掉。本轮把两种情形都推到底：

- **合成无嵌套 unify**：memo/栈都无人动，insert 位置无差异——零丢失。
- **合成有嵌套 unify**：嵌套入口把 memo 与工作栈**一起**抹掉。旧实现
  虽在回调后补 insert 了一条，但工作栈同样被抹——外层随即弹空栈返回
  true，此后到下一次 unify 入口 clear 之前**没有任何代码读 memo**——
  旧的那条 insert 与新实现的丢失同样不可观测。

结论：「只影响性能」的定性成立，且实际影响比 A4 自述还小（丢失场景下
连性能影响都不存在，因为 memo 随整表一起作废）。A4 论证可接受。

### 3.4 NLL / SB / 新 unsafe —— 通过

- 字段借用死亡点：每轮 `let Machine {..} = self` 的全部再借用（含两个
  cast 出的 work/stack）最后使用 = `unify_iter(...)` 调用；NLL 区域在
  调用处终止，`self.solve_multi_trait_ref(...)` 的 `&mut *self` 再借时无
  存活字段借用；下一轮全新解构。这是 borrowck 自己接受的「循环内 split
  borrow + 中间整 self 方法调用」标准形态——`cargo check --all-targets`
  绿（门禁）即经验佐证 ✔。
- SB 视角：旧代码违规是「字段借用存活期间 `(&mut *mach_ptr)` 弹出其标签、
  返回后继续使用」；新代码两条整机 `&mut` 血统（驱动层的字段拆分与
  合成层的独占 self）在时间上不重叠，被弹出的旧标签不再被使用 ✔。
- 新 unsafe：无。diff 中 `+` 侧 unsafe 仅两条既有 `'static→'a` 槽位
  cast 原样移入循环（SAFETY 注释随行）；`mach_ptr` 只在注释出现 ✔
  （三章 grep 复核）。
- 嵌套层的借用链同样干净：solve_trait_ref 内部的字段拆分先收集为 owned
  Vec 再调 `self.infer_expr` 等，无并存借用 ✔。
- 顺带核实：`unify_work` 的第二消费者（L10:4205/L11:4420/L12:4496 的
  rename 前置块）自带 `work.clear()` 且不在挂起窗口内，与本改动无新交互 ✔。

## 4. [P1·先在共模，非 A4 引入] 嵌套 unify 擦除外层工作表 → 提前 true / 处理外来栈项

- 位置：三章 `bump_spine_iter.rs` 的 `Machine::unify` 驱动（新）/
  unify_iter 回调（旧）+ `solve_trait_ref` 嵌套 unify 路径。
- 机制：外层 unify 在**工作栈非空**时挂起于 trait-solve 位点（可达形态：
  Π 臂挂着的 `Store` + `EvalCod2` 余域屏障、`unify_sp_lockstep` 压着的
  逐实参 Pair、η 臂的 Store/Pair 等，见 L10:2157-2310）；驱动执行的
  trait 合成触发嵌套 `Machine::unify`（实例含隐参插入 / SumCase 类型把关，
  L10:3873、L11:4085、L12:4157 及 infer/insert 内的 unify_catch）；
  嵌套入口 `work/stack/memo/scratch` 全清 → 外层现场销毁。外层 resume 后：
  1. 嵌套成功 ⇒ 栈空 ⇒ 外层**直接返回 true**——Π 的余定义域、spine
     逐实参等待比较项被静默丢弃（可能受 不良型程序）；
  2. 嵌套失败且结果弃置（`let _ =` 把关点）⇒ 栈留残留 ⇒ 外层把**嵌套的
     Pair/Store 当自己的弹**——外来子对流进外层 memo/solve，可能再次
     挂起触发更多合成，语义不可控。
- **非回归**：旧实现（a99972a）回调在外层工作栈存活时执行，嵌套 unify
  走同一共享字段、同一入口 clear，两种结局逐字相同。A4 重写对该行为
  保留忠实（其 §1.3.3「工作栈内容跨挂起点保持」的表述未覆盖此嵌套
  场景，属论证缺口而非代码缺陷——见 §5 建议 1）。
- **与参考版的 parity 裂缝**：参考版 `unification.rs:582` 的递归 unify
  中，外层待比较项在 Rust 调用栈/不可变持久数据上，嵌套 `solve_multi_
  trait`（:522/:636/:640）不可能触碰——参考版天然免疫。故此隐患是快版
  独有的「共享工作表 vs 调用栈」表示偏差，可造成快版接受、参考版拒绝的
  判定分叉（trait 负载下）。
- 触发条件（三缺一不可，故既有测试未爆）：外层挂起时工作栈非空 + 该
  meta 的合成确实走 infer/insert/SumCase-unify + 构造出余域/实参不等
  的对照项。l10-l12 无 blackbox 差分套件（a4-r1 §5 记录的缺口），当前
  无测试网。
- 处置建议（本轮不改，路由协调者）：最小修复方向是驱动在合成调用前
  `mem::take` 保存 `unify_stack`（连同 conv.memo），合成后恢复——即把
  嵌套 unify 隔离成「借用独立草稿」；或给合成期 unify 配独立工作表。
  注意这会**改变行为**（修掉先在 bug），需与参考版对照构造回归探针
  （Π 余域含 trait-solve + 实例隐参触发嵌套 unify + 余域不等应报错），
  且 L13 若同构需同步（L13 共享文件不在本轮范围）。
