### 读表注记

1. **L13 的 bench 路径不可与 L06-L12 直接比**：l13bench 走
   `run_decls_bounded`（逐 decl LSP 观察面：CheckIssues 排水等），strchain
   孪生实测 O(D²)（k=9/10/11 fast = 228/933/3798 ms，×4.1/翻倍）——bench
   形态固有成本（prelude-hdl 无此现象），与 COW 改动无关。
2. **L09/L10 twin 的 universe 65 ms vs L11-L13 的 1.8-3.5 ms**：同源同参，
   差在 L09/L10 孪生的 `bind_name` 每 binder 整表克隆（优化记录中的残留
   项 1）——universe 的 `Type 1 -> Type 0` 每 def 触发一次。这是下一步
   孪生侧优化最明确的目标。
3. **match 负载过小**（k+1=12 个 def、递归深度 2）：L09+ 的引擎固定启动
   成本（Infer/Tycker 建表 ~0.5 ms）主导数字，倍率看绝对值意义有限。
4. **traitchain (L10)**：两版都病态（参考版 23.8 s / 孪生 12.5 s，k=9 即
   如此），实例合成路径的专门问题；L11 孪生 11 ms / 参考 731 ms（66×）
   说明 L11 的 canonical 化路径已绕开 L10 的病态。L12 的孪生 parity 失败
   是既有 bug（见 l12bench 自检），修复前无对照。
5. 特色负载的巨大倍率（struct 108-837×、macro 747-768×、strchain
   135-764×）来自参考版逐 def 克隆名字/声明表的 O(D²)（§opt 文档 §2），
   孪生经 COW 后线性；倍率随 D 增长，非常数加速比。

   这也是 LSP 实际体感对应的两条。
