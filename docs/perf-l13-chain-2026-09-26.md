## 1. 因果 A/B 定价（宏级 stub 四变体 × 25 个 examples/hdl）

口径：`l13lspsample`（twin，3 kicks）+ `TYPORT_KICK_DECLTIME=1` 逐 decl，
每 decl 取跨 kick min。force 级探针（标记 prim、reset/restore 括号）两轮
均被求值语义打碎——impure prim 每次 force 重新执行、被丢弃的 let 不一定
被 force（`chainMark("tree")` 全程零触发但 stub tree 体省 34% 即反证）——
故定价全部用宏级 stub 的因果差值：

| 变体 | 内容 | 逐 decl 合计 |
|---|---|---|
| a0 | HEAD 基线 | 7172ms |
| a1 | + `moduleTreeVL`/`allModulesVL` 体 stub | 6990ms（Verilog 生成仅 2.5%） |
| a2 | + 三臂 `def tree` 体 stub（tree 链全消） | 4535ms（**tree 侧 34.2%**，且大头在 class 声明内部——Phase-B 的 tree def 检查期求值） |
| a3 | + 顶层 `X.create.tree` 调用点换空树 | 3655ms（**用户 create 调用 12.3%**） |

两次额外求值（tree 侧 + 用户 create）可测部分合计 **46.5%**，保守下界
（Phase-B create-def 检查期重求值未含）。原始日志曾存 `target/ab/{a0..a3}`
（清理时已删，数字归档于此）。

## 2. tree 宏改造（`5f30727`，<1 人天，用户段 **−32.2%**）

`def tree: ModuleTree = this._res`——inherent-impl 方法注册本就前置
`this` 接收者，`_res` 是 create 时捕获的模块树（宏注释自称 "dead weight
by design" 的暴露字段）。重放语义无不可替代用途：实例记录/自检注册/
幂等/bn 逐项等价；唯一差异是 body 读 create 与 access 之间被改的外部
可变全局时取 create 时快照（语料内无此用法且更确定）。
`def_needs_replay` 对 `X.tree` 不再命中。26 全绿 + 26 文件逐字节一致，
收益为 a2 上界的 93.5%。

## 3. Phase-B 消重（`f6fd14c`，0.5 天，20-misc kick **−12.8%**）

twin check 的 `Raw::Tm` 臂删弃结果的 `let _ = self.eval(.., tm)`：
结果无人消费，且外层 Let 臂立即对同一 tm 同 env 再 eval——双跑纯冗余。
链上副作用 prim 全部按名幂等或首登记优先（ModuleRegistry 按模块名、
CheckIssues 行级、三明治 save/restore）。参考引擎有意不同步改，充当
parity 基准：26 个 parity 测试全绿即证明第二遍零贡献。
class decl 段 −16~22%。

## 4. App 臂实参跳过（`804c4dd`，0.5 天，25 文件 **−8.0%**）

create 路子 agent 的分解：一次 `println(moduleTreeVL(X.create.tree))`
链跑 **6 遍** = tyck 期 4（Obj 臂接收者 eval ×1 + App 臂逐层实参 eval ×2
的 create 链 + 1 tree 链）+ println nf 期 2（必要）；观察面/导出桥零。
通用修复：`binder_occurs` 深度感知扫描，余定义域不引用 binder 则不为
类型检查 eval 实参（Match/Call 保守不跳）。经 `TYPORT_TWIN_APP_SKIP`
门控试点（26 绿 + 字节一致 + 无一回退）后去门控化合入。
顺带裁决历史矛盾：观察面 HDL 文件 ≈0、证明类文件 ~8%（round 23 §9.1
与 23b backlog #1 各对一半口径）；`maybe_prechecked_method_body` 把
`checkModuleTree` 顶进 tree 体的配对缺陷被 §2 自然吸收。

## 6. 长期方案裁决：ModuleTree 下沉 Rust prim——现在不做

设计研究结论：两补丁落地后链剩 3 遍（Phase-A 检查、create 检查实跑、
用户 create 调用），三者的存在理由都是"必须求值"——树下沉只降低每遍
副作用单价（~6-18%，中心 ~10%），**消不掉任何遍数**，12-18 人天不划算。
MVP 形态已存档（`mtBegin/mtEnd/mtAddExpr/mtAddInstanceIfParent/mtSnapshot`
+ Val 桥接，读端 Verilog 生成与自检规则第一期不下沉），触发器二选一：
(a) 自检阶段 2（SCC/CDC 图分析）立项；(b) `string_to_global_type` meta
家族或三明治红线再次咬人。更近的后续项：Phase-B 值复用（Raw::Tm 类型
复用推广到值复用，3 遍→2 遍，~10-15%，3-5 人天）与 Obj 臂接收者惰性化。

## 7. 附带修复

`45b75e0`：`resident_compaction_matches_fresh_replay_across_kicks` 的
强制机制（预算 0 + 垃圾撑大 arena）因本轮消重失效——小文件单 kick 垃圾
不再使 `allocated_bytes` 越过预算。改为每 kick 起点显式
`compact_resident`（`pub(super)`），等价断言在旧机制下从未执行，修订后
重新生效。
