## 1. 与 L06 版的差异（都是 L07 语言面与结构带来的）

1. **渲染要带 decl 表**：L07 的 `quote(&Decls, Lvl, Val)` / `force(&Decls, Val)` 都要
   传 decl 表，故 observe 的渲染/校验接口统一从 `cxt.decl()` 取；
2. **Val 是按值**（不是 `Rc<Val>`）：push 接口收 `Val`（Clone），渲染前不持有借用；
3. **登记面用旁表**而不是扩 `DeclEntry`：`Infer::{decl_spans, decl_pretty, ctor_pretty}`
   三个旁表承载「全局名 → 定义处 span / 登记期渲染串 + final / 构造子渲染记忆化」。
   这样 `cxt::DeclEntry` 的十来处构造点（builtin 注册、enum 构造子、`simpl_decl`、
   `decl_insert` 包装……）一行都不用改，代价是 decl 表与旁表要同步维护（当前只有
   def / enum / 构造子三处写点）；
4. **构造子 hover 走两条路**：裸名 `succ` 是 `Raw::Var` → 走 `push_hover_decl`
   （旁表已登记裸名别名）；限定/模式位置的构造子走 `Raw::SumCase` 臂 →
   `push_ctor_hover`（键 `E.c`，按 key 记忆化渲染串）；
5. **completion 按 receiver 类型过滤**（L07 有成员投影，L06 没有）：两处产出——
   ① 限定投影 `E.c` 的补全候选 = 该枚举的构造子名（receiver span = 枚举名 token）；
   ② 一般投影 `x.f` 的候选 = 接收者 WHNF 类型上的字段名（`Val::Sum` 的索引参数 /
   `Val::SumCase` 的字段）。不做前缀过滤（交给客户端）`；
6. **洞型 inlay**：L07 的 `check` 有专门的 `(Raw::Hole, _)` 臂（期望类型已知），
   在那里补一条 `: <type>`（锚点 = 最内层 binder 尾 / 顶层 0）；与「def 无返回类型
   注解 → 推断返回类型 inlay」共用可见区过滤。

## 2. 语义与门禁

- 默认关闭时 `run` 的输出/判定逐字节不变（采集只是 `lsp_collect` 为 true 时多几次
  布尔判定与 push）；
- 采集开启时 **Ok 输出与 run 逐字节一致**（同一个 `pretty_tm` + `nf` 管线，println
  串只多存一份）；
- `check_with_surface` 是 opt-in 继续驱动：失败 decl 记名字后继续，**错误文案不变**；
- 自检行排水是**只读**的（L07 把 `CheckIssues` 当用户可见值打印，清空会改输出）。

## 2.5 采集开销（L07 参考版，`l07bench --observe`）

三档行与 `basic` **同一入口**（`bench_check_nf_observe`：elaborate + 末值 nf，
与 `bench_check_nf` 逐位同工作量，只把采集闸打开），故差值即采集开销：

| 负载 k=11 | basic（无采集） | `basic_obs`（全量） | `basic_obs_at`（按光标） | `basic_obs_view`（光标+可见区） |
|---|---|---|---|---|
| church | 1.398 ms | 1.534（1.10×） | 1.502（1.07×） | 1.524（1.09×） |
| match | 0.092 ms | 0.132（1.43×） | 0.094（1.02×） | 0.094（1.02×） |
| enum（k=9） | 0.168 ms | 0.242（1.44×） | 0.175（1.04×） | 0.172（1.02×） |
| natadd | 3.241 ms | 3.209（0.99×） | 3.178（0.98×） | 3.225（1.00×） |
| strchain | 7.364 ms | 12.379（1.68×） | 8.191（1.11×） | 8.125（1.10×） |
| global | 13.786 ms | 26.403（1.92×） | 14.779（1.07×） | 14.393（1.04×） |

读法：全量采集在 decl 密集负载上 1.7–1.9×（strchain/global），来源是每个 def 的
登记期渲染 + 每次使用处的 hover 串；**查询口径（LSP 一次请求的真实形态）把它压回
1.0–1.1×**。match/enum 的全量开销主要来自构造子/字段 hover 的渲染（1.4×）。
## 3. 查询口径（惰性采集）

`SurfaceQuery { hover: Option<usize>, inlay: Option<(u32, u32)> }`：

- `hover` 有值时只渲染「使用处 span 含该偏移」的悬停条目（def 登记串也只在光标落在
  def 名上时才渲染）；
- `inlay` 有值时只渲染锚点落在可见区内的 inlay；
- println / 自检行 / 失败 decl 仍全量（全文件消费）。

`run_with_surface_at(src, path, off)` = `run_with_surface_query(hover_only(off))` 的快捷。
