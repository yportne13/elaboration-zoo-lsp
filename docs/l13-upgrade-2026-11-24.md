## 3 跑门禁时挖出来的既有问题（不是本轮引入）

1. **默认 gate 从 2026-11-23 起就是红的**：`tests/l13_fast_parity.rs:1` 的 `#![cfg(feature = "l13-twin")]` + 封印后 feature 默认关 ⇒ 该 target 编译出 **0 个测试**，gate 正确报 NO-TESTS。已修复（parity suite 永远带 `--features l13-twin`），这是 P4 的真实价值——不是加一条门禁，而是原来的门禁是假的。
2. **`-Full` 下唯一红灯是真实的 ref 与 twin 分叉**：`prelude_full_observation_tables_match_reference` 报
   `ref-only: 188..192 -> 612..616 "(n: Nat) → Nat"` 与 `twin-only: ... "(n': Nat) → Nat"`。
   用 `git checkout` 回到未改动状态复跑同样失败 ⇒ 与本次改动无关，是封印期间积累的漂移。已登记为 [known-diff #16](l07-l13-known-diff.md)。
   我试过把孪生的 decl 类型渲染从 `types_names_list(cxt.types)` 换成 Locals 派生的名字表（对齐参考版 `Cxt::names()`），未解决，已完整回退，不做无根据的改动。
3. **dev profile 的 `link.exe` LNK2019（`anon.*.llvm`）**：首次在本机跑 gate 时 dev 链接失败，是 target/debug 里的陈旧增量产物，不是代码问题；release 链接正常。门禁请用 `-CargoArgs --release`。
