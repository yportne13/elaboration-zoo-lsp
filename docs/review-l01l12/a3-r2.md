### A6 修复的机制与触发证据
- 触发源（订正后的探针）：`m a a b c` 的重复实参 ⇒ η 展开后 invert 掩码内先序
  `[Some,Some,Some,None,None]`；`Eq (m a a b c) (λd.d)` + `refl` 迫使
  `?0 a a b c ≡ λd.d`，进入 `prune_meta`。
- 修复前：参考版按链头（最内层实参）配最外层 Π 层 → 保留 A/B、剪掉 C/D，
  codomain `D -> D` 引用被剪层 → **参考版 Err，快版 Ok**（parity 裂缝）。
- 修复后：参考版与快版同口径（剪 A/B、留 C/D），两版 Ok。探针以 `is_ok + parity` 钉住。

### 探针订正（orchestrator 首轮运行反馈后）
- **首版失败原因（非 prune_ty）**：探针源自 L05/L06 的 Leibniz `Eq` 直搬，但 L09 宇宙分层
  下 `A : Type 0 ⇒ A -> Type 0 : Type 1`，故 `Eq ... : Type 0` 的声明本身报
  `can't unify find: Type 0 / expected: Type 1`，源在 `Eq` 声明处即 Err，根本没进入
  `prune_meta`（orchestrator 运行输出为证）。这是**源层级写错**，不是掩码反转结论被推翻。
- **订正**：保留 L06 非对称非线性形态 `m a a b c`，把 `Eq` 的返回宇宙改为 `Type 1`
  （`def Eq[A : Type 0](x : A, y : A) : Type 1 = (P : A -> Type 0) -> P x -> P y`），
  去掉 L09 无对应物的 `the`，改用带注解的 `def test (a b c : Type 0) : Eq (m a a b c) (d => d) = refl`
  直接让构造子 `refl` 的索引合一逼出 `?0 a a b c ≡ λd.d`。
- 若 orchestrator 复跑后该源仍在类型检查阶段 Err，则本探针连同"parity 裂缝"结论一并降级为
  **needs-verify**（保留尝试源与失败输出），不做恒失败断言。
