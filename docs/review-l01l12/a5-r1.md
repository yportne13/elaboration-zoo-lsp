## 2. 发现列表

### [P0] 自递归宏无限展开 → `p_raw`/`p_decl` 无深度上限 → 栈溢出
- 位置：`src/L11_macro/parser/mod.rs:1120`（展开后 `p_raw(&t_borrowed, ...)` 递归）、
  `:1379`/`:1505`（块体宏路径）、`:1919`（声明级 `p_decl(&t_borrowed, ...)` 递归）；
  L12 同形：`src/L12_canonical/parser/mod.rs:1172`、`:1504`、`:2043`；L13 共享文件同样。
- 证据：`p_raw` 以 `input.first()` 命中宏名后，用 `state.1.clone()` 作宏表，
  将 transcription 重新 lex 成 token（`:1081-1118`），再对这份**新 token 流**调用
  `p_raw`（`:1120`），新流首 token 仍是同名宏则再次命中。全仓 grep
  `recursion|MAX_DEPTH|depth_limit|recursion_limit` 在 `src/L11_macro`、`src/L12_canonical`
  **零命中**，无任何深度/燃料上限。
- 机制/影响：触发源码
  ```
  macro_rules m { () => { m } }
  def x = m
  ```
  `m` 的 transcription 就是 `m`，重 lex 后仍是 `m`，`p_raw` 每层再展开，递归深度无界 →
  `stack overflow` 中止（LSP/前端可在任意源码上触发）。属于用户可触发崩溃。
- 处置：**仅报告**（需要给 `MacroState` 增加展开深度预算，或对两处递归点加 RAII/`Cell`
  深度守卫；因涉及 `MacroState` 元组 arity 或跨模块守卫、且 L13 共享副本同样需改，
  超出“最小 diff”范围，交由 orchestrator 决策）。

### [P1] L11 `Val::to_typ` 对字面量 / Prim `todo!()` → 字符串字面量取字段即 panic（已修）
- 位置：`src/L11_macro/typeclass.rs:30-32`（原 `Val::LiteralType|LiteralIntro|Prim => todo!()`）
- 证据：`Raw::LiteralIntro` 的推断类型是 `Val::LiteralType`（`src/L11_macro/elaboration.rs:891`）；
  `p_atom` 允许任意 atom 后缀 `.Ident`（`parser/mod.rs:540-543`），故 `"a".foo` →
  `Raw::Obj(LiteralIntro, foo)` → `infer_expr` 的 Obj 臂落到 `_ => trait_wrap`
  （`elaboration.rs:749`）→ `trait_wrap` 第一步 `typ_raw.to_typ()`（`:937`）→ `todo!()`。
  同类触发：`impl Foo["x"] for T` 走 `:547` 的 `a_eval.to_typ()`。
- 机制/影响：字符串字面量取字段 / 作 trait 实参是**用户可达** panic。快版孪生
  `bump_spine_iter::val_to_typ`（`:5633-5686`）对同形值一律返回 `None`，因此这也是
  L11 双 oracle 的潜在 parity 裂缝（basic panic / fast 返回 `has no object`）。
- 处置：**已修**。改为 `Val::LiteralType | Val::LiteralIntro(_) | Val::Prim(_, _) => None`，
  与快版口径一致（继续走 `unwrap_or(Typ::Val("$unknown$"))` 或返回 `"Not a type"` Err，
  不再 panic）。

### [P1] 超大整数字面量 `.parse::<u64>().unwrap()` panic
- 位置：`src/L11_macro/parser/mod.rs:506`、`src/L12_canonical/parser/mod.rs:549`：

- 证据：lexer `num = pmatch(|c| c.is_ascii_digit())…`（`parser/lex.rs:287`）会把整段数字

- 机制/影响：触发源码 `def x = 99999999999999999999999999`（> `u64::MAX`）→ `parse` Err →
