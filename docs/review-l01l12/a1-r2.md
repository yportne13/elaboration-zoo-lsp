## 2. 发现列表

### [P0] L02/L03 的 `CloCell` 在 32 位目标对齐不足，packed tag（3 位）解码 UB
- 位置：`src/L02_tyck/bump_spine_iter.rs:125-135`（原）、`src/L03_holes/bump_spine_iter.rs:221-231`（原）
- 证据：两处 `CloCell` 字段为 `name: &str, icit: Icit, env: Env, body: &Tm`，
  **不含 u64**。64 位下 `align_of == 8`，wasm32 上 `&str`（8B/align 4）、`Env`
  （u32+u32+ptr，align 4）、`&Tm`（4）使 `align_of == 4`。而 `v_clo` 写
  `ptr | 1`、`v_clo_of` 读 `v.0 & !7`（`L02:82,106`、`L03:97,125`），要求低 3 位
  为 0 → wasm32 上会清掉 bit2，解引用错位指针 = UB。
- 机制/影响：与 ROUND2 §A1 的 `XCell` **完全同类**（编排器只点了 L06–L12 的
  `XCell`）。本切片两层的 `CloCell` 是同一缺陷拷贝。触发条件：wasm32 目标 + 任意
  执行到 λ 闭包解引用（正常 elaboration 必然经过）。
  注：`PiCell` 含 `dom: V`（u64）恒 ≥8，不受影响。
- 处置：**已修**。给 L02/L03 `CloCell` 加 `#[repr(align(8))]` + 编译期
  `const _: () = assert!(align_of::<CloCell<'static>>() >= 8);`（64 位布局不变，
  零行为变化）。同时在 L01 复核 2 位 tag：`CloCell`/`Clo` 仅需 ≥4，wasm32 上
  恰为 4，加 `>= 4` 断言即可（无需 repr）。

### [P3] `src/L01_nbe/native_clo.rs` 的 SAFETY 注释误称「对齐 8」

## 5. 设计决定讨论（不属 bug，只记录）

### 5.1 L01 用 2 位 tag、L02/L03 用 3 位 tag，阈值不同是刻意的
- L01（`bump_spine.rs`）：tag `{0=Lvl, 1=Clo, 2=Spine}`，`v.0 & 3` / `& !3` → 指针
  只需 ≥4 对齐；wasm32 上 `CloCell`/`Clo` 恰好 4，**无需 repr**，加 `>=4` 断言即可。
- L02/L03：tag 低 3 位（含 U/Pi/Meta），`& !7` → 需 ≥8。`PiCell` 含 `V`(u64) 自然满足；
  `CloCell` 不含 u64，必须 `repr(align(8))`。
- 因此「L01 2 位只需 ≥4」经复核成立，且与 ROUND2 §E 的表述一致。

### 5.2 `EnvCons` 加断言属防御性（非编码需要）
L01/L02/L03 的 `EnvCons` 都含 `V(u64)` 恒 ≥8，且从不被 `ptr|tag` 直接编码（只以
`&EnvCons` 存于 `CloCell`/`Env`）。断言按 ROUND2 §A1 的「所有相关类型都钉住」要求
加入，仅防未来字段改动导致对齐退化。
