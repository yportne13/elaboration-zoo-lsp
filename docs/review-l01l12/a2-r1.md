## 2. 发现列表

### [P2] packed-word 指针 tagging 隐式假设 8 字节对齐（32 位目标潜在 UB）
- 位置：`src/L04_implicit/bump_spine_iter.rs:135,145`、`src/L05_pruning/bump_spine_iter.rs:153,163`、
  `src/L06_string/bump_spine_iter.rs:170,180,191`（`v_clo_of`/`v_pi_of`/`v_xcell_of`）；
  编码处同文件 `v_clo/v_pi/v_xcell` 与 `v_tag/v_spine_of/v_lvl_of`。
- 证据：`V((p as *const _ as u64) | tag)` 与 `&*((v.0 & !7) as *const _)`。该编码要求
  `CloCell`/`PiCell`/`XCell` 的 bump 分配地址低 3 位为 0（即 `align_of >= 8`）。
  这些类型含 `&str`/指针字段，在 64 位目标 align = 8（A1/A3 报告亦以 align 8 论证），
  但在 32 位目标（如 `wasm32-wasip1-threads`，指针/`&str` align = 4）`align_of == 4`，
  `& !7` 会清掉 bit2 → 还原出错误指针，解引用即 UB。
- 机制/影响：仅影响 32 位目标。`Cargo.toml` 明确为 wasm 目标做条件依赖，CI 的 wasm target
  只安装未 cargo build（`build-vscode` 只跑 npm/vsce），`build-cli` 仅 x86_64，故当前
  CI 不会触发；属"目标假设未静态断言"的潜在 soundness，且跨 L03–L13 通用（非单文件可修，
  需 `#[repr(align(8))]` 或按 `cfg(target_pointer_width)` 断言/改用索引编码）。
- 处置：**needs-verify / 仅报告**（无法 cargo 静态证明目标矩阵；本切片不改架构）。

### [needs-verify] L04/L05 参考版 unify η 臂缺 applicability 守卫（本层不可达）
- 位置：`src/L04_implicit/mod.rs:427,431`、`src/L05_pruning/mod.rs:929,933`；
  对照已加守卫的 `src/L06_string/unification.rs:476,481`（`v_applicable`）与

- 处置：**needs-verify / 仅报告**（建议后续与 L06/L13 统一加守卫以消隐患；当前无触发

- **L06 文件 IO builtin 用户可达 panic**：`cxt.rs:175-233`（fast `:725/738/755/784`）对
  `fs::read/write/append/remove` 失败 `unwrap_or_else(|e| panic!(...))`。`file_read_all_text

  记录在案，无测试钉死。若整体目标是 LSP/无崩，应改 Err 诊断（属跨层错误语义变更）。

  Bug-1 触发面，故需 η 守卫），L07/L08 取 decl **类型**（`e.ty`），L11/L12 取 **值**
  （见 §4），L13 取类型 + 有守卫。属分层刻意/历史分歧，多数被各自 blackbox 锁定。
- **L06 字面量 pretty 打印原文（无引号）**：`pretty.rs:196` `span.data.clone()`，被
  `tests/l06_blackbox.rs:98` 锁定，非 bug。

  L06 v2 记录为上游已知不完备（非不可靠），双实现一致。
- **L04 无类型 meta**（`MetaEntry::Unsolved` 不带类型，`insert/fresh_meta` 不记录期望类型）：
  上游 04 的分层设计，L05 才引入 typed metas；不视为 silently accept 缺陷。
