### [P1] L09 全局哨兵 off-by-one：0 号全局自引用崩溃 — 已修
- 位置：`src/L09_mltt/mod.rs:165`（`lvl2ix`，原 `x.0 > 1919810`）、
  `src/L09_mltt/unification.rs:244`（rename 边界，原 `x.0 <= 1919810`）；
  快版对应 `src/L09_mltt/bump_spine_iter.rs:1303/1454/2660/2705/4178/4291`（原 `> GLOBAL_BASE`）
- 证据：全局索引编码为 `global_idx + 1919810`（`cxt.rs:114` fake_bind、
  `elaboration.rs:289/374` `global.insert`），`global_idx = self.global.len()` 从 0 起，
  故 **0 号全局的层级恰为 1919810**。eval 用 `x - 1919810` 取表，快版 eval 用
  `*i >= GLOBAL_BASE`（`bump_spine_iter.rs:858/967`），而 quote/rename/Raw::Var/update_cxt
  的边界却写成 `> 1919810` / `> GLOBAL_BASE`，把 0 号全局误当局部层级 → 计算
  `l - x - 1` 下溢（debug 构建 panic；release wrap 成大索引后 eval 越界 panic）。
- 触发用例：`def f : String = f`（**首个**顶层声明且自引用；global_idx=0）。
  参考版：`infer_expr(Var f)` → `lvl2ix(lvl=2, Lvl(1919810))` → `2 - 1919810 - 1`
  u32 下溢 panic；快版：`Raw::Var` 臂 `blvl >= GLOBAL_BASE` 走 else 同一算式 panic。
  两版同崩（parity 一致）但都是用户可达崩溃。
- 处置：**已修**（统一为"全局 iff `level >= GLOBAL_BASE`"，与 eval 及
  `pretty.rs:117` 的 `ix.0 >= 1919810` 处理一致）。改动：
  参考版 `mod.rs:165`、`unification.rs:244`；快版 6 处 `> GLOBAL_BASE` → `>=`。
  对 `global_idx >= 1` 的既有输入两边界等价，故全部现有测试行为不变；修复后
  `def f : String = f` 接受，`println f` 经 `pretty.rs:117` 打印 `recursive_0`
  （两版一致）。
