## 2. 发现列表

### [P0] L06 `XCell` 与 L04/L05/L06 `CloCell`/`PiCell` 在 wasm32 对齐不足，packed tag 解码 UB（已修）
- 位置：
  - `src/L06_string/bump_spine_iter.rs:209`（`XCell`，解码 `v_xcell_of` at `:193-195`）
  - `src/L04_implicit/bump_spine_iter.rs:248,260`（`CloCell`/`PiCell`，解码 `:136-138,147-149`）
  - `src/L05_pruning/bump_spine_iter.rs:273,285`（同上，解码 `:154-156,164-166`）
  - `src/L06_string/bump_spine_iter.rs:302,314`（同上）
- 证据：编码 `V((p as *const _ as u64) | tag)`（tag ∈ {1,4,7}）、解码 `v.0 & !7`，要求分配地址
  低 3 位为 0 ⇒ `align_of ≥ 8`。`XCell` 仅有 `&str` 变体；`CloCell` 字段为
  `name:&str / icit / env:{u32,u32,Option<&EnvCons>} / body:&Tm`——**不含 u64**，64 位
  `align==8`，但 wasm32（`&str`/指针 align 4）上 `align_of==4`，`& !7` 会把 bit2 清掉 → 解引用
  错误指针 UB。`Cargo.toml:80-81` 为 wasm 目标做条件依赖、vscode web 扩展构建 wasm LSP 二进制，
  属真实目标。
- 机制/影响：32 位目标上 packed 指针还原错误（不是编译错误，是静默 UB）。ROUND2 §A1 已独立核实。
- 处置：**已修**。给 4 处类型加 `#[repr(align(8))]`（64 位下 align 本已为 8，布局逐字节不变，
  零行为变化），并紧邻加 `const _: () = assert!(align_of::<T<'static>>() >= 8);`：
  - L06 `XCell:216`、`CloCell:310`、`PiCell:323`
  - L04 `CloCell:256`、`PiCell:269`
  - L05 `CloCell:281`、`PiCell:294`
  - `EnvCons`（L04:195 / L05:215 / L06:244）含 `V(u64)`（wasm32 上 `align_of::<u64>()==8`），
    断言直接通过；当前它**并不**进 packed 字（仅经 `&` 引用），断言为防御性钉住（注释已说明）。
  同时把 7 处 `v_*_of` 的 SAFETY 注释改为点明「对齐 ≥ 8 由 `#[repr(align(8))]` 保证，含 wasm32」
  （L04 `:136-138,147-149`；L05 `:154-156,164-166`；L06 `:170-173,180-183,191-195`）。

### [P1] L04/L05 unify η 臂对不可应用值 `v_app` → 可达 panic 面（已修，参考版+快版同步）
- 位置：`src/L04_implicit/mod.rs:437,441`、`src/L05_pruning/mod.rs:939,943`；
  快版 `src/L04_implicit/bump_spine_iter.rs:1008,1020`、`src/L05_pruning/bump_spine_iter.rs:1152,1164`。
  对照已修的 L06 `src/L06_string/unification.rs:476,481` 与快版 `bump_spine_iter.rs:1737,1756`。
- 证据/论证（补守卫**是否只改不可达的 panic 分支**）：
  1. 参考版 η 臂对非 λ 一侧无条件 `self.v_app(&t, …, i)`，而 `v_app` 只认
     `Lam/Flex/Rigid`，对 `Pi/U` 走 `_ => panic!("impossible")`
     （L04 `mod.rs:182`、L05 `mod.rs:402`）。守卫 `v_applicable(v)` 对 L04/L05 恰为
     `matches!(v, Flex|Rigid)`——**为真时进入的正是 `v_app` 原本不 panic 的两个臂**，语义逐字不变；
     **为假时恰是原本 panic 的 Pi/U 分支**。
  2. 故补守卫后：`Flex/Rigid` 路径（含 η 求解、spine 扩展）字节级不变；仅 `Pi/U` 从
     `panic` 变为落到末尾 `_ => Err(UnifyError)`。**不存在任何非 panic 结果被改变**——
     与「判定/输出契约」不冲突。
  3. 快版原行为是 `spine.push(t,…)` 把 Pi/U 压成卡住链，最终 `_` 臂 `flex_of` 两侧皆 None →
     `false`。补同样的守卫后直接 `false`，与参考版新 Err 判定一致（L06 先例：参考版曾 panic、
     快版 Err 判定发散；本层尚未有种子）。快版守卫按 tag 实现：`0|5`（裸 Lvl/Flex）与
     `tag 2` 头为 `0|5`（中性链）为真，`3/4`（U/Pi）为假，`1`（Clo）已被前臂 `(1,1)` 接住
     （L04 `:163-169`、L05 `:181-187`）。
  4. 可达性：L04/L05 源码层无 decl 表 / builtin / `get_global` 类「把 λ 值当动态类型返回」的
     种子（`grep -i builtin|global|decl` 于两 `mod.rs` 仅命中内部标识符，无用户可达入口），
     故 Pi/U 分支在本层不可达；补守卫是**消除潜伏 panic 面**，不是修复已触发的 bug。
     R1 判定「不可达」维持；因守卫只作用于 panic 分支，补与不补在可触达路径上等价，
     补上后与 L06/L13 口径统一，无回归风险。
- 机制/影响：若不补，一旦后续层机制（如 L06 的 st2g）下移或内部不变量被打破，本层会以
  hard panic（BRIEF §1 定义的可达 panic 面）而非 Err 暴露，且与快版判定发散。
- 处置：**已修**。新增 `v_applicable` 帮助函数（参考版 L04 `mod.rs:140`、L05 `mod.rs:180`；
  快版 L04 `:163`、L05 `:181`），η 四臂加 `if v_applicable(...)`（参考版+快版同步）。
  未新增测试：本层无源码级触发用例（不可达），无可断言的最小复现；L06 的
  `tests/l06_blackbox_v3.rs:791-822` 为已存在的先例覆盖。

## 5. 设计决定讨论（不属 bug，只记录）

- **L04/L05 η 臂在本层事实上是死代码**：因无「λ 值当类型」种子，`Val::Lam` 只可能和 `Val::Lam`
  配对（被前臂接住），η 臂永不进入。保留守卫与 L06/L13 统一，是跨层一致性，不是本层功能。
  若未来做「无 decl 层裁剪」，可评估删除——本轮不动。
- **`v_applicable` 在参考版对 `Decl`（L06）为真、对 L04/L05 无此变体**：属分层差异（L06 有
  decl 表），非分叉 bug。
- **L04/L05/L06 `EnvCons` 的对齐断言是防御性的**：该类型当前不进 packed 字（`Env` 以
  `&EnvCons` 引用），断言仅防未来把它塞进 packed 字时误以为已 ≥8。
- R1 §5 其余记录（字符串 builtin 文件 IO panic 的 L13 逐字移植、L06 字面量 pretty 原文、
  L05/L06 η-塌缩不完备、L04 无类型 meta）维持不变，本轮无新证据。
