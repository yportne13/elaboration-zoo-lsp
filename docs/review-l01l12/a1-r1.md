### [P2] `bench_cek_deep` 提前返回路径丢弃百万层 `check` 树，递归 Drop 爆栈
- 位置：`src/L01_nbe/bench.rs:884`（原 `if rows.is_empty() { ... return; }`）
- 证据：函数头注释（`bench.rs:709-713`）明确声明
  「check 与每轮 input 都是百万层深的 Box 树：派生 drop 会逐层递归爆栈……
  这里用 `mem::forget` 泄漏」。正常出口在 `bench.rs:889` 做了
  `std::mem::forget(check)`，但**提前返回路径漏了**：
  ```rust
  let check = church_iter(n + n);          // 709
  ...
  if rows.is_empty() {                     // 884
      println!("（此规模没有选中的变体）");
      return;                              // check 在此被递归 Drop
  }
  std::mem::forget(check);                 // 889（正常路径才 forget）
  ```
- 机制/影响：`bench_cek_deep` 只在 `n > 8000` 进入（`bench_size:68`）。
  当 `--only` 未选中任何深段变体（如 `--only naive`、`--only bump_spine_memo`），
  `rows` 为空走提前返回，`check = church_iter(2n)` 被逐层递归析构。n 翻倍到
  64000 时树深 128000；在 readme 明示可复验的口径 `L01_STACK_MB=4` 下 4MB
  栈必然溢出（`--workload church --max-church 64000 --only naive`）。
  bench 主线程默认 128MB 只是把阈值推后，未消除该路径。
- 处置：**已修**。在提前返回分支补 `std::mem::forget(check);`（并加注释说明）。
  输出文案与正常路径行为不变。

## 5. 设计决定讨论（不属 bug，只记录）

### 5.1 packed-word tag 不变式：本轮**证明成立**
- L01（`bump_spine.rs`）用 **2 位 tag**：`00 Lvl`、`01 Clo(ptr|1)`、`10 Spine(idx<<2|2)`
  （任务书提到的 `v.0 & !7` 是 L02/L03 的形态；L01 只有 3 个 tag + 立即数，
  `!3` 是有意为之，非 bug）。
- L02/L03 用 **3 位 tag**：`0 Lvl`、`1 Clo`、`2 Spine`、`3 U`、`4 Pi`、
  L03 另有 `5 Meta`（`L02_tyck/bump_spine_iter.rs:71-116`、L03`:86-139`）。
- 证明：所有指针类构造器 `p as u64 | tag` 与 `mask = !(2^k-1)` 配对，
  其安全性只依赖 `p` 的低 k 位为 0。`CloCell`/`PiCell`/`EnvCons`/`Clo` 均含
  指针字段（`align 8`），由 `bumpalo::Bump::alloc` 按类型对齐分配 ⇒ 低 3 位恒 0；
  L01 的 `CloCell` 同理。立即数 tag（Lvl/Spine/U/Meta）自乘/移位构造，tag 位
  与负载位不重叠；4 个 tag 值两两不同。**未发现可碰撞编码，也未发现非 8 对齐
  的分配来源**。

### 5.2 连续性引理（`base + len - 1 == h` ⇔ 链上下标连续）：成立
`Entry.len/base` 的传递（`push` 时若 `a` 是 tag2 则 `len=prev.len+1, base=prev.base`）
保证了：若逻辑链连续则 `base+len-1 == 当前 idx`；若中间被别的 `push` 穿插，则
`idx > prev.idx+1 = base+len-1`，条件为假。`base` 条目的 `.a` 必非 spine 句柄，
故 `ChainRun` 自底向上重建与递归语义一致。`bump_spine_rpn` 的全同头模式摞、
`bump_spine_slim`/`native_clo` 的 quote 期沿 `.a` 下行推断（`entry[i].a ==
v_spine(i-1)`）与本引理等价（后者还排除了「Apply 惯例的 `f` 恰为 `v_spine(i-1)`」
这一仅 ChainWrap 可满足的巧合）。

### 5.3 arena 生命周期擦除（`'static` 存放 + 洗白）：sound
L02 `Machine::quote_memo`（`:870-872`）与 L03 `Machine` 的
`workbuf/qtasks/qdone/ustack/quote_memo`（`:1514-1596`）用
`&mut *(&mut self.field as *mut Vec<_<'static>> as *mut Vec<_<'a>>)` 缩短生命周期。
每条路径在**插入任何 `'a` 引用前**先 clear（`eval_iter`/`quote_iter`/`unify_iter`/
`rename_iter`/`quote_memo` 入口），调用返回后残留的悬垂引用不再被读取；
`Vec<&T>`/`Vec<QJob<'a>>` 的 Drop 不触碰元素 ⇒ 不产生 UB。唯一约束是
「不跨 `Bump::reset` 读取」，`Tycker::run_impl` 每次 `reset + clear_round` 满足。

### 5.4 `unify` 求解 + 判等记忆化的健壮性
`unify_iter` 的「只缓存成功 + `Store` LIFO 屏障」依赖 meta 写一次、force 单调
（flex→rigid 单向）、成功单调（`L03_holes/bump_spine_iter.rs:873-894` 的论证）。
本轮复核该论证与 `(2,2)` 受控内联环的门控（`:1094-1106`，仅当实参链顶层 `f` 与本层
`f` 同字才下钻），未发现反例；blackbox `unify_eta_absorption_matches_basic` /
`unify_meta_shorter_side_solvable` / `conv_dup_check_passes` 与 1200 seed fuzz
parity 钉住了旧 fail-fast 的两类 η/meta 误杀。
