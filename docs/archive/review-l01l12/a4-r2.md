## 5. 设计决定讨论（不属 bug，只记录）

### 5.1 L10 快版 `&mut *mach_ptr` 重入的 Stacked Borrows UB（P0，本轮不修）
- **机制**：`Machine::unify`（`bump_spine_iter.rs:3729`）先取
  `let mach_ptr: *mut Machine = self;`（`:3739`），随后
  `let Machine { spine, vals, icits, defs, metas, globals, ren, conv, unify_work,
  unify_stack, .. } = self;`（`:3741-3753`）把**整台 Machine 的多个字段以 `&mut`
  借出**，再把这些字段引用连同 `mach_ptr` 传入 `unify_iter`。`unify_iter` 在字段
  引用仍存活时执行 `unsafe { (&mut *mach_ptr).solve_multi_trait_ref(bump, cxt, mv) }`
  （`:2229`，另 `:2344`/`:2367`），而 `solve_multi_trait_ref`/`solve_trait_ref`
  以 `&mut self` 重新借用整台 `Machine`（含 `let Machine { spine, defs, metas,
  globals, .. } = self;` 的整机重借），返回后 `unify_iter` 继续使用
  `work`/`stack`/`vals`/`conv` 等旧引用（如 `conv.scratch1 = ...; continue;`）。
- **为何是 UB**：按 Stacked Borrows，从 `&mut self` 派生裸指针 `mach_ptr` 后，又通过
  `self` 解构做字段 `&mut` 重借，会 invalidation 掉更早的 `mach_ptr` 派生；此后
  `&mut *mach_ptr` 属 use-after-invalidate（同一分配上并存两条 `&mut` 血统）。
  当前 rustc 未必误编译，Miri 很可能报 `not granting permission`。
  `:3762-3765` 注释声称“字段已按不相交集合借出，重入经裸指针……无移动”，但被回调
  方法重借的恰恰是同一批字段，该不变式描述**不成立**。
- **触发条件**：任何走到“合一中 flex 求解点回调 `solve_multi_trait_ref`”的输入
  （trait 实例合成路径）；即 L10 trait/impl 正常用例都可能进入，非罕见路径。
- **建议修法（不实施）**：把 `unify_iter` 的 trait 回调改为**不跨字段借出重入**——
  二选一：
  1) 在调用点前结束字段借用（把需要回写的结果经局部变量收集，回调后再重建字段引用）；
  2) 把 `solve_multi_trait_ref`/`solve_trait_ref` 改成接收不相交字段的自由函数
     （`fn solve_multi_trait_ref(bump, spine, defs, metas, globals, ...)`），
     不再整机重借。
