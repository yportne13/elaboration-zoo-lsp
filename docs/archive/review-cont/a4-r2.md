## 3.【任务 3】L10 快版 Def 臂缺 `solve_multi_trait` —— 分叉证实，已修

- **核实**：L10 快版 Def 臂（`bump_spine_iter.rs:5122-5158` 修改前）在
  `check(body)` 之后**没有任何** `solve_multi_trait_ref` 调用；而 L10 参考版
  Def 臂（`elaboration.rs:289-291`，R1 已改可恢复 Err）与 L11/L12 快版 Def 臂
  （L11 `bump_spine_iter.rs:5374-5375`）都有。属 L10→L11 快版链继承缺口
  （L11 加了，L10 漏回传）。
- **分叉机制**：def 体检查后仍含未解 **trait 类型 meta** 时，参考版在定义点即
  求解/报 `Trait(..)` Err；旧快版不求解——meta 只靠合一挂起点惰性求解，
  报错时机与判定都可能分叉（快版可能静默放过或延后失败）。
- **修复**（`src/L10_typeclass/bump_spine_iter.rs:5154-5158`）：移植 L11 快版
  同款 `self.solve_multi_trait_ref(bump, &fake, 0).map_err(|e| Error(name.to_span()
  .map(|_| format!("Trait({:?})", e))))?`，插在 `check` 与 `eval(vt)` 之间
  （参考版同序）。L10 无 L11 的 `no_metas`/`err_unsolved_meta`（L11+ 特性），
  故只移植 solve 调用——与 L10 参考版（同样无 no_metas）精确对应。
- **安全性论证**：参考版自始带急切求解且 parity 全绿 ⇒ 现有测试输入在 def 尾
  不留未解 trait meta（否则参考版早已 Err 且两版分叉可见）⇒ 该调用在现有测试
  上是行为 no-op；对未来输入则把快版对齐到参考版的定义点判定。
  文案：`format!("Trait({:?})", e)`（e:String）= 参考版 `UnifyError::Trait(String)`
  的 Debug 形态 `Trait("...")`，与 L11 同款（a5-r3 已核过同构性）。

  `run` / `run_with_prelude` / `run_fast`（测试入口）**从不调用**这些闭包

  不可见，只影响 LSP quickfix 的搜索完备性（修复意图本身）。
