### 2.2 L09 typed universes 的适配（与 L07/L08 的差异点）

- 钉为 **`Raw::U(0)`**（L07/L08 钉 `Raw::U` 单宇宙的 L09 对应物），
  口径与 L09 全局默认层级一致（check_universe 的 meta 解也是 U(0)）。
- **宇宙扫描不受扰动**：enum 臂开头的 `universe_lvl` 扫描
  （`infer_expr(p.1)` 匹配 `Tm::U(lvl)`）对 U(0) 域贡献 lvl 0 = max 恒等
  （Hole 原本贡献nothing），`universe_lvl` 与 Sum 的层级不变。
  既有 `enum Eq[A](x: A, y: A)`、`enum HighLvl[A]` 等测试的行为面不变
  （meta 编号会变化——域洞不再造 meta——但全套唯一精确输出断言是
  `recursive_0`，无 `?N` 锁定，parity 双版同步位移安全）。
- **类型层面更健全**：Π[A:?][B:?]→U 原被 check_universe 判为 U(0)（洞
  层级默认 0），钉后为 U(1)（Π[A:U(0)]... 的正确层级）；该返回层级在
  两个调用点均被丢弃（`let (typ_tm, _)`），无观测面变化。
- **语义窄化（记录）**：无标注 `[A]` 现固定为 `A : Type 0`；高层级
  实例化（如 `P[Type 0]`）需显式标注 `[A : Type 1]`（标注域不钉）。
  这与「方括号参数是类型参数」的语言定义一致，且 1 参数情形
  `P[Nat]` 行为不变（原本就通过）。

## 6. R3 门禁反馈订正（探针第 4 源——子用例病态，非 pin 遗漏）

### 6.1 定位

- 失败断言：`tests/l09_fast_parity.rs` 新探针的 **is_ok（参考版）**——
  `run_basic` 对第 4 源返回 Err（第 1-3 源在同一次门禁中 is_ok+parity
  全绿，**钉 U(0) 的实际目标形态已被本轮门禁功能验证**）。
- 根因（选项 b，子用例对语言过严/病态）：第 4 源
  `enum Q[A : Type 0] { q[A](a: A) -> Q[A] a }` 的 Q **没有枚举级显式
  索引参数**，返回类型 `Q[A] a` 把 `Q[A] : Type 0` **过度应用**——L09
  的 App 臂（elaboration.rs:574-615）对非 Π 函数类型构造
  `Π(?dom, ?cod)` 与 `U(0)` 合一，`U(0) ≡ Π` 必败，**enum 声明处即
  Err**。该源与 pin 无关（Q 的 A 是标注域、不钉；Nat 无参数）。
- 为何 L08 同款"绿"：R1 的 L08 探针第 4 源**只做 parity 断言**
  （`assert_parity` 对两版一致 Err 也通过）——空转通过（vacuous
  pass）掩盖了病态；L09 探针加了 is_ok 才揭示。这是 R1 探针设计
  错误，非代码回归。

### 6.2 处置

- **L09 探针第 4 源改写**为 L07 `pack_annotated_params`（黑盒 v3 绿）
  的合法索引族形态：`enum Q[A : Type 0](a: A) { q[A](a: A) -> Q[A] a }`
  + `def t: Q[Nat] zero = q[Nat] zero`——枚举级显式索引 `(a: A)`、
  返回类型完全应用，与 L09 既有绿的 `Vec[A](len: Nat)` 同构。
- **L08 探针同款源同步改写**（`enum Q[A : U](a: A) { ... }` +
  `Q[Nat] zero`），保持断言风格不变（parity-only）并在注释记录理由。
- **is_ok 断言升级诊断输出**：失败时打印 `basic={:?}` 与 `fast={:?}`
  两版实际结果（本次若有两版结果可直接区分 is_ok 断/parity 断）。
- 注释中均记录病态源与订正理由（含"R2 门禁为何没发现"的空转解释）。
