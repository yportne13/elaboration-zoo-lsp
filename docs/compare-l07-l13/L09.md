## 1. 定位与语言特性增量

**结论：L09 是"再定基"，不是继承 L08。** 它按 MLTT 教学章（宇宙层级 + 和类型 / match）重写内核，与 L06–L08 的 decl 表世界系统性不同（[文档] `src/L09_mltt/README.md:4-10`；[文档] `docs/archive/review-continuity/a4-r1.md:14-26` 判"非逐行继承，是再定基层"）。

| 维度 | 内容 | 证据 |
|---|---|---|
| 新增语言面 | `Type N` 分层宇宙（`Tm::U(u32)`/`Val::U(u32)`，裸 `U` 只是变量名） | [码] `mod.rs:813`；[文档] README:37-39 |
| 新增检查 | 类型注解一律过 `check_universe`（含两条未解 meta 解路径）；enum 声明收集 `universe_lvl` 取 max；`check_ctor_wf`（构造子返回类型必须是本 enum 的 Sum 且参数位为 bare rigid） | [码] `elaboration.rs:246-295`、`:451-463`、`:567-605` |

**时代缺口一览**（这是回答"为什么再定基"的核心，也是使用者最可能踩的坑）：

| L06–L08 设施 | L09 里的形态 | 使用者实际影响 |
|---|---|---|
| decl 表 + 值层 decl 展开 | `global: HashMap<Lvl,VTy>`（终值），无 unfold | 无惰性 decl、无可重入展开；递归 def 靠 `fake_bind` 自引用占位 |
| `pm_defs` 事实表 + `unify_pm`/`update_cxt` | 已并入 σ 显式替换（`ccfcb87`），但精化只能沿 σ 可见 | 卡住 match 内部无法再精化（见 §3） |
| `Val::Match` pending 实参 splice | `v_app` 对 `Val::Match` **panic** | 合法源码（引用自递归卡住 match 的函数值再应用）可崩：参考版与快版同崩 + parity 一致，属刻意时代缺口（[码] `mod.rs:1-10`、`:710-726`） |
| `struct_eq` 快路径 | 无；`unify(Match,Match)` 分支体在**中性全局视图**下重求值 | 自比较不发散但与 L07/L08 不同构（[码] `mod.rs:457-468`、`unification.rs:344-364`） |
| 6 烧点通用 fuel | 只剩 1 烧点：frcs 的 Rigid lookup 命中（`UNIFY_FUEL=4096`） | 其余失控类（pm_defs/Match 重选/decl 展开/Prim 归约）无宿主，A4-R2 判"不补"（[码] `mod.rs:476`、`:345-352`、`:591-595`） |
| `redefine` 检查 | 无：顶层 def/enum 重名静默覆盖 | 覆盖 `global_names` 与 global 表条目，无诊断 |

## 3. 核心机制现状（逐项）

**3.1 精化载体：σ 显式替换，与 L07 蓝本逐点同构。** `Subst` 持久化单链（`mod.rs:304-321`），`Val::VSub` 包裹（`wrap_sub`，空 σ 零开销，`:335-341`），`frcs` 读点推开（槽位纪律：spine/Sum/SumCase 只包裹、闭包 env 逐槽包裹、Match scrutinee 推进 `:575-665`），`SpecSolve{acc}` 穿参，`force_arg` 给合一器参数视角（`:687-697`），`subst_cxt` 包 env 与局部 src_names、槽位布局不动（`cxt.rs:154-183`）。[文档] `docs/explicit-subst-refactor-status.md:41/55` 记 L09 参考+孪生均落地，31 parity、全 lib 705 绿、72 源逐字节 diff=0。

**3.2 全局名字世界：两表 + 大下标哨兵（本层最重要结构差异）。**
- 值表 `Infer.global: HashMap<Lvl,VTy>`，键 = 登记时的 `global.len()`（[码] `mod.rs:445`、`elaboration.rs:393/503`）。项层引用是 `Tm::Var(Ix(global_idx + 1919810))`，`GLOBAL_BASE=1919810`（孪生 `syntax.rs:13-14`）。
- 名字表 `Infer.global_names: FxHashMap<String,(Lvl,Rc<VTy>)>`，**append-only、不随 Cxt 克隆**（`mod.rs:446-456`、`:515-529`）。`src_names` 现在只装**局部**条目（binder/let/`Cxt::new` 的两个内建，`cxt.rs:30`），查找"局部优先、回落全局"（`elaboration.rs:638-643`、`pattern_match.rs:106-113`）。孪生侧同构（`machine.rs:75`、`:1389-1397`）。
- 哨兵边界必须是 `>=`：0 号全局恰为 1919810，用 `>` 会让首个声明自引用下溢（`mod.rs:398-408`，修复 `fd25b74`）；eval 的 Var 臂 `x.0 - 1919810` 越哨兵查表（`mod.rs:758-767`）。
- 递归 def：`fake_bind` 把名字指到全局层级（`mod.rs:502-510`）→ global 表先插 `Val::vvar(global_idx+1919810)` 占位 → 检查体 → 覆盖真值（`elaboration.rs:399-405`、enum `:506-511`）；构造子走 `define_global`（`:544-554`）。值层无 unfold ⇒ decl 展开类 fuel 无宿主。

**3.3 宇宙。** `check_universe` 对推断类型非 `U` 定向报 `expected universe`；未解 meta 两条路径：spine 空且 meta 类型 force 后是 `U` → 解 `U(0)`；spine 非空 → 带 `occ: Some(m)` 的 rename 造 `U(0)` 解（`elaboration.rs:250-291`）。enum 声明对参数域与构造子域逐个 `check_universe` 取 max 作为本体宇宙（`:451-463`），高宇宙 enum（`HighLvl[Nat] : Type 2`）由此成立。**无标注隐式域钉 `U(0)`**（`:440-450`）是 L07/L08 黑盒修复的 L09 形态，回归钉 `parity_enum_struct_impl_hole_pinned_u0`。

**3.4 依赖核心：force 只有二臂、卡住 match 不可再应用。** `force` = `Flex`（meta 解）+ `VSub`（σ 推开）两臂，其余恒等（`mod.rs:555-569`）——没有 Match 重选、decl 展开、Prim 归约。`eval` 的 `Tm::Match` 臂 force scrutinee，构造子值则选臂，否则整体卡成 `Val::Match`；`v_app` 对它 `panic!("impossible apply")`（`mod.rs:710-726`）。unify 的两个 η 臂已加 `v_applicable`/`vapp_ok` 守卫（`:326-331`），把"卡住 match/字面量与 λ 比较"从 panic 改判 Err（A4-R1 #6）。`unify(Match,Match)` 用 `neutral_globals` 开关（`:457-468`）让全局回落中性 rigid 后重求值分支体（`unification.rs:344-364`、`:695`）。

**3.5 匹配编译器：逐臂下钻（2026-09-19 `09b9ee8` 从决策树矩阵整体重写）。** `Compiler::compile`（`pattern_match.rs:190`）：顶层逐构造子 `probe_accessible`（值级结构探测，`:84-150`，meta 整表快照回滚 `:117/148`、逐 ctor 独立充值 `:114-116`、fuel 耗尽按可达 `:138-142`）→ 逐臂 `walk_pat` 绑槽并按用户序首匹配；构造子类型经 `infer_expr(Raw::Var(名))` 取（`:462`，与 `probe` 的双表直查是两条路径）→ 特化方程 `check_pm_final` 解入 σ → `subst_cxt` 臂上下文 → 分支体检查 → 嵌套位置覆盖走"两段式"延迟探测（走查只记账，σ 终态后提升）。诊断相对决策树收窄三处：顶层 `Unmatched` 不再有路径感知填充（改"构造子+999 通配"）、遮蔽只在通配臂后报 `Unreachable`、荒谬臂静默跳过（[文档] README:196-200；[文档] `docs/l09l13-match-compiler-analysis-2026-09-17.md §2`）。

**3.6 防护与健壮性。** 唯一 fuel 烧点 = `frcs` 的 Rigid lookup 命中（`mod.rs:591-595`），充值于 unify/nf/模式编译/探测入口（`meta_refuel` `:530-533`）；耗尽按未解处理（返回裸 rigid）。探测隔离为 `meta` 窄快照整循环一回滚（A4-R2 §2-3）。**未做深值迭代化**：quote/pretty/深值 Drop 仍是按深度递归，parity 用 256 MB、bench 默认 128 MB 大栈线程（[文档] README:316-321）。panic 面：`v_app` 的 `impossible apply`、`impossible {v:?}` 等（可能被 Debug 打印放大）。

## 7. 优劣评估

**优点（≥3）**
1. **教学密度最高**：最小 MLTT 内核 + 分层宇宙 + 和类型/match + 等式编码，`mod.rs` 两个 DEMO 全串即教材样例（`:1149/1337`）；比 L07/L08 少一半设施，读起来最快。
2. **σ 迁移完成度好**：与 L07 蓝本逐点同构，`docs/explicit-subst-refactor-status.md:41/55` 记全绿 + 72 源逐字节 0；本层是"旧 `update_cxt` 世界 → σ"最干净的样本。
3. **语义边界诚实**：卡住 match panic、无 Match 重选、fuel 适用面等全部文档化 + 双版同崩 + parity 一致（`mod.rs:1-10`、README §6），不会静默分叉。
4. **宇宙与构造子良构检查完整**：`check_universe` 全覆盖 + enum `universe_lvl` max + `check_ctor_wf` 拒绝 phantom 构造子（`elaboration.rs:246/451/567`），这两块比 L07/L08 更完整。
5. 双引擎 parity 29 例 + golden，跨实现分歧有闸门。

**缺点/风险（≥3）**
1. **时代缺口是结构性的**：`v_app` 对卡住 match panic 可被合法源码触发；无 Match 重选 / decl 展开 / Prim 归约 / `struct_eq`；L07 2026-11 加固 P1–P11 未回灌（FACTS §6），是层间健壮性差异最大来源。
2. **名字世界双表 + 遮蔽特例**：`src_names`（局部）与 `global_names`（全局）两表 + `shadow_local` 手工覆写（`mod.rs:488-497`），且"构造子类型查询"在 `infer_expr` 与 `probe_accessible` 里各有一次实现（`elaboration.rs:638-643` vs `pattern_match.rs:106-113`）；无 decl 表 ⇒ 无 `redefine` 检查、构造子登记只能裸名（无 `Enum.case` 限定名）。这是 L11 切回 decl 表的直接动因（§8）。
3. **哨兵常数 1919810 渗透全层**：eval/rename/quote/pretty/unify 都要认这个魔法数（grep 95 处命中），边界 `>=` off-by-one 曾真出 bug（`fd25b74`）；对外部读者是纯认知负担。
4. **诊断收窄**（决策树→逐臂，L10–L13 同款代价）：丢路径感知填充、遮蔽分析弱化、荒谬臂静默跳过（README:196-200、分析文档 §2）。
5. **测试薄**：lib 10、parity 29，远低于 L07 的 69 + 4 套黑盒；无 σ/force 机制级单测；孪生 0 lib。
6. **参考版性能历史 + 深值未迭代化**：即便 O(D²) 已修，参考版仍是"教学实现"地板；quote/pretty 深值递归、panic 而非诊断的剩余面（`impossible apply` 等）。
