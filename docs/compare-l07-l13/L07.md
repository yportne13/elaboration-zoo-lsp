## 7. 优劣评估

**优点**（每条带证据）：
1. **bug 族按构造排除**：旧 "改写 env 槽 + quote→eval 刷新" 的槽位错位类失败（add_assoc/add_comm/prove）
   在新载体下消失，README §6 首行明示，`tests.rs:1481` 有回归。[文档+码]
2. **机制单一、语义方向统一**：一个合一器 + `SpecSolve` 穿参，删掉 `unify_pm` 双轨与全局 `pm_solvable`；
   是 L08–L12 五层可复用、可逐点同构移植的蓝本（`docs/explicit-subst-refactor-status.md` §0-§1）。
3. **守护与工程化最完整**：fuel + 次数预算双道有界防护、三档判定、跨 meta 环守卫、深值遍历迭代化、
   σ 跨轮回收；且把"算不完"从"矛盾"里分出来（R1 修复后空类型零臂 match 恢复接受）。
4. **测试体系七层最重**：双 oracle + 三卷黑盒 + 70 lib 钉，且钉住"已知限制"而非只测 happy path（§5）。
5. **性能不弱**：参考版 match basic 0.145 ms 与 L08 持平，大值负载孪生 23×；"参考版"本身也经性能评审，
   可作为第二实现使用。

**缺点/风险**：
1. **不是证明助手**：with-K 无任何检查（README §7.3），接受集比 Agda 宽；浅 occurs 不传递，同一自指索引
   程序只换索引顺序就从接受翻成拒绝（`L07-RISKS.md` P1 实测）。
2. **判定仍是启发式**：fuel / 64 次预算耗尽 ⇒ 「无法判定」而非定理（README §7.2）；合法但需 >64 次比较的
   深/宽卡住 match 会被误报，需调常量。
3. **σ 可见性边界是架构取舍**：σ 只对被包裹值可见，decl 表缓存值与 meta 解不可见（README §1.3/§7.6；
   钉 `tests.rs:2268`），可能导致判定随求解顺序变化（P6）。
4. **诊断未闭环**：`Error` 有 span 但 LSP 未接入（`src/lib.rs:52` 仅导出）；孪生 span 全零；parity 不校文案。
5. **维护面积翻倍**：16+12 个 `.rs`、18.6k 原始行、双引擎机制需逐点同构；修补丁要写两遍（P12），
   文档漂移已经发生（§8）。
6. **"参考版"名不副实**：缓存/undo-log/内联栈等优化把参考版也变成第二套高性能实现，教学可读性被稀释。

**评估卡**（1–5）：

## 8. 与相邻层的关系与当前状态

- **继承/分叉**：L07 的 σ 机制被 L08–L12 全部继承（L08 是"零新核心机"、L09 换名字世界再定基、L10 trait、
  L11 decl 表+宏、L12 trait 求解下沉 Val 级）；L13 五轮后回退、保持 `update_cxt` 世界（`docs/explicit-subst-refactor-status.md`
  §4），所以 L07 是本仓 σ 路线的**定稿层/参照系**。[文档]
- **加固不对称（当前最大层间语义差）**：2026-11-08 的 P1–P11 只完整落在 L07；L08 只镜像了 P1/P2（双引擎）
  与 P9，**P3 三档未迁**（L08 仍报「分支不可达」，`L07-RISKS.md` §0.1）；L09–L13 未回灌 P1–P11 任何一项
