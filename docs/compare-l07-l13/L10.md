## 1. 定位与语言特性增量

**定位 = "L09 + trait 层"的增量扩展**（不是再定基、不是生产化）[文档 README §1/§5]。基线 = L09 的层级化 global 世界（无 decl 表、大下标哨兵）；新增语言面全部集中在 trait/typeclass，内核（NbE、σ 显式替换、逐臂匹配编译器）与 L09 同构，只补护栏。

新增（相对 L09）：
- `trait` / `impl` 声明、接收者方法调用 `x.foo y` 脱糖（`trait_wrap`）、`outParam(Type 0)` 掩码、实例表 Prolog 求解 [码 src/L10_typeclass/elaboration.rs:535-658]；
- `trait` 脱糖为 **`is_trait` 的 enum**（`Tm::Sum`/`Val::Sum` 带标记，构造子即实例），模式匹配/pretty/和类型机制零改动复用 [码 elaboration.rs:624-658 走 `Decl::Enum{is_trait:true}`]；
- 实例登记 `Synth::impl_trait_for` 进 `class_instances`（支持泛型与毛毯实例）[码 typeclass.rs:168-173；elaboration.rs:582-589]；
- 期望类型是 trait Sum 时 `fresh_meta` 不剪枝、直接放待解 meta；体检查完后 `solve_multi_trait` 扫未解 meta 逐个 `solve_trait` [码 mod.rs:576-587；elaboration.rs:367；unification.rs:449-507]；
- 相对 L09 的两项**恢复**：`unify` 的 `(Obj, Obj)` 合同臂、`UNIFY_FUEL=4096` [码 mod.rs:450、607-609；文档 README §1.5]。

丢弃/未继承（时代缺口，同 L09）：无 decl 表、无 `struct_eq`、无可变全局/文件 IO/builtin 注册表（唯一 builtin `string_concat`）、卡住 match 不可再应用（`v_app` panic）、重定义静默覆盖、构造子只有裸名 [文档 README §1.5/§2/§6.2]。

> **重点问题速答**（详证见 §3/§4/§6/§7）
> - **Q1 无 decl 表**：沿用 L09 再定基选型；trait 求解只需"名字 + 一阶 Typ 断言"，再加 decl 表会成第三个名字世界。代价：构造子/实例类型一律绕 `infer_expr(Var)` 取，且 L11 反手换 decl 表 ⇒ 该路线未被后继层延续。
> - **Q1b Val/Typ 双世界代价**：求解器在 `Typ`（可 Hash/Eq 的一阶项）上做 Prolog；Val 带 Rc 闭包/spine/Flex，不可作表键。代价 = 边界转换 + 信息有损（`Lam/Pi/Flex→None`，`Sum` 参数槽"剔不可转项"是有损泥土带）；Typ→Val 只能经"实例名 → `infer_expr` → insert → eval"回值世界。收益 = 求解器 430 行、两引擎共用。
> - **Q2 trait_wrap 复杂度**：每次方法调用 = (含同名方法的 trait 数) × 一次完整 Prolog 搜索 + 一次脱糖项重推断，每候选前整克隆 `trait_definition`；多解时**取 HashMap 迭代序第一个**（源码 TODO 自认）⇒ 语义不确定。effort≤1000 的 panic 是护栏（防无限 DFS），但失败形态是崩溃非诊断 = 缺陷；现有语言实例无依赖，该上限实际不可达，更像死保险。
> - **Q3 close O(n²)**：根因 = `ImplDecl` 把类型参数泄漏进 decl 级 cxt（`cxt.bind` 后 `cxt = c`），孪生 `env_ext_defs` tip 快路径永久失效，`k = lvl - flat_len` 随 define 数线性增长；修法 = 只包 Bind + q 引用的 define 槽并按保留槽重编号（§6）。**只修了孪生**。
> - **Q4 双实现**：`Synth` 共用、Val↔Typ 桥只在边界；孪生补 PM_FUEL、solve_multi 等重重写；parity 不剥 `?N`（强于 L11–L13，也更脆）。

## 3. 核心机制现状（逐项）

**精化载体 = 显式替换**（`ad412ab`）：`Subst` 持久化单链 + `Val::VSub` + `frcs` 读点推进 + `SpecSolve{acc}` 穿参；`update_cxt`/`refresh` 已删除（grep 0 命中），臂边界 = Rc 回滚、臂体前 `subst_cxt` [码 cxt.rs:165-181]。L10 定制四点：可解集 = 任意裸 Rigid 故 `SpecSolve` 无 `solvable` 字段 [码 pattern_match.rs:51-52]；occurs 守卫**不扫** Flex 的 spine（否则 GADT 嵌套 match 合法解被误判成环）[码 mod.rs:363-394]；`to_typ` 消费点走 `force_deep`（否则 trait 接收者经 `val_to_typ` 掉参）[码 unification.rs:486；elaboration.rs:1010]；孪生 `subst_cxt` 必须同步包裹 `names.by_lvl` 影子索引 [码 bump_spine_iter.rs:55-56；cxt.rs:161-164]。

**匹配编译器 = 逐臂下钻**（`4e97743`）：`compile` 对每臂独立走查 + 特化，保持书写顺序 = 运行时首匹配 [码 pattern_match.rs:186-309]。L10 特有适配 = **臂特化走 raw 侧 meta 间接**：`walk_pat` 返回的槽位刚性不在 raw 重推断解的 σ 里，必须把「头部 ≐ 走查 ret」显式方程以 σ 为种子补解入（`aafa5ed`）[码 245-295]。覆盖探测是**值级**（`e2560a4`）：直接查 `src_names`/`global_names` 取构造子类型、Π 链实例化、索引方程只进探测私有 σ，每探测独立充值 fuel、耗尽按可达处理 [码 88-184]。嵌套覆盖两段式：走查记 `pending_pos`，全部特化方程解出后才提升为带 σ/lvl 快照的 `NestedCheck` 再探测 [码 55-60、286-347]。保留的收窄：遮蔽只认通配臂；特化失败臂静默跳过 [码 306-308、248-251]。

**全局名字世界 = 无 decl 表**：真名进 `Infer.global_names`（append-only、不随 Cxt 克隆，2026-09-20 O(D²) 修复）[码 mod.rs:456-465、506-547]，值按层级进 `Infer.global: HashMap<Lvl, Rc<VTy>>` [码 mod.rs:455]；项层引用 `Ix(global_idx+1919810)`，`lvl2ix` 边界必须 `>=` [码 mod.rs:411-421]。递归 def = `fake_bind` 占名 + global 表先放自指 rigid、体检查后覆盖真值 [码 mod.rs:515-522；elaboration.rs:360-372]。中性 globals 视图用 `Cell<bool>` 开关（O(1)）取代旧「clone 整个 Infer（含三张 trait 表）」[码 mod.rs:469-497、963-972]——这是 trait 表给 clone 成本加码后的直接反弹。

**依赖类型核心**：`Type N` 分层宇宙（`U(u32)`）；`SumCase.typ` 保留；**无 `struct_eq`**；卡住 match 不可再应用，η 臂以 `v_applicable` 守卫改判 Err 而非 panic [码 unification.rs:11-17、649-656]；`force` 只有 Flex（meta 解，烧 fuel）+ VSub（σ 推开）两臂，无 Match 重选、无 decl 展开 [码 mod.rs:591-606]；重选只发生在 eval 的 `Tm::Match` 臂 [码 mod.rs:945-959]。参考版 quote/force **无记忆化**，孪生有 `QuoteMemo` [码 bump_spine_iter/quote.rs:94；mod.rs:987-1014]。

**trait/typeclass（本层核心）**：`Synth` 表驱动 Prolog —— `generator_stack`（逐实例 DFS）× `resume_stack`（子目标消费）× `assertion_table`（子目标 → waiters/answers，**兼作答案缓存**）[码 typeclass.rs:138-355]。Val→Typ 桥 `Val::to_typ`：Flex/带 spine 的 Rigid/Lam/Pi/Obj/字面量/Prim → `None`，裸 Rigid→`Var`，`U(n)`/`Sum`→`Val`/`Construct`；Sum 参数槽对不可转项**静默剔除**（论证：登记侧 None 即 Err、目标侧 arity 失配即 no-instance、trait_wrap 接收者路径依赖该剔除）[码 typeclass.rs:18-70，尤其 45-58]。`outParam`：声明期按 `Raw::App(outParam,..)` 形状填布尔掩码 [码 elaboration.rs:628-633]；求解与 `trait_wrap` 两侧都先滤掉 out 位（out 位填 `Typ::Any`，`match_typ` 的 Any 臂恒真）[码 unification.rs:474-487；typeclass.rs:412-413；elaboration.rs:1019-1022]。实例匹配 = **单向一阶** `match_typ`：只有 pattern 侧 `Typ::Var` 可绑，目标侧 rigid 不得被吃（旧双向绑定无 occurs 让 `f two` 错答 "list"）[码 typeclass.rs:389-429]。实例断言**依赖表恒空**（`dependencies: List::new()`）⇒ 本语言无超类约束/where 子句，Prolog 的 multi-goal 机械基本闲置 [码 elaboration.rs:582-586]。

**内建/prim/副作用**：只有 `string_concat`，体是无名 `Tm::Prim`，求值读 env 前两槽 [码 cxt.rs:41-89；文档 README §2]；无 decl 表 prim、无可变全局、无文件 IO/replay/宏。

**防护与健壮性**：`UNIFY_FUEL=4096` 共享池（unify 递归与 force 的 meta 展开各烧 1、入口充值；耗尽按不可合一/未解降级）[码 mod.rs:448-450、548-565、591-600]。孪生 2026-09 评审 P1 才补 `PM_FUEL` 4096（frcs lookup / Match 重选 / spine 链头三处燃烧；meta 展开无门 = 已知剖面差）[文档 README §5；docs/explicit-subst-refactor-status.md §3]。**L07 加固族 P1–P11 未回灌** [文档 FACTS §6/CONVENTIONS §2]。panic 面：`effort>1000` [码 typeclass.rs:219-224]、卡住 match 被 `v_app` 应用（同 L09；`v_applicable` 只在 η 臂挡）[码 mod.rs:334、unification.rs:649-656；文档 README §1.5]、旧 `to_typ` 的 `todo!()`（`b7b4225` 已改 None）[码 typeclass.rs:28-35]。

## 7. 优劣评估

优点：
1. **trait 机制用最小内核改动落地**：`is_trait` enum 复用 enum 全套机制；求解器独立 430 行且**两引擎共用**；trait 相关新增代码估计仅 700–900 行（参考）/500–700 行（孪生）[推断：按 typeclass.rs、elaboration trait 臂、孪生桥行数估算]，是"给 NB 内核加类型类"的低侵入样板 [码]。
2. **Val/Typ 分层方向正确**：把可 Hash/Eq 的一阶项独立出来，Prolog 的 `Assertion` 才能当表键（assertion_table 兼答案缓存）[码 typeclass.rs:130-153、341-351]。
3. **工程闭环扎实**：parity 逐字节 + bench 互检 + 内存分配探针驱动了 §6.0 修复；README 有诚实清单（effort panic、克隆 TODO、归因未核实）[文档]。
4. **单向一阶匹配**修正旧双向绑定假匹配，与 L12/L13 `val_match` 同族，是可迁移结论 [码 389-429]。

缺点/风险：
1. **求解器 toy 化**：`new_subgoal` 每子目标克隆实例表（typeclass.rs:299）、`trait_wrap` 每调用整克隆 `trait_definition`（elaboration.rs:1011-1012，源码 TODO 自证）、`synth` 前置 `clean()`；无 occurs/环检测，靠 effort≤1000 **panic** 兜底（typeclass.rs:219-224）。
2. **多解语义不确定**：`trait_wrap` 把可解候选 `collect` 后 `first()`，同名方法跨多 trait 时选择取决于 HashMap 迭代序（std RandomState 逐进程随机），源码 `//TODO: if traits.len() > 1, return err` 自认 [码 elaboration.rs:1079-1083]；parity 无歧义负例就测不出 [推断]。
3. **依赖表恒空**（elaboration.rs:584）：Prolog 的 consumer/waiters/multi-goal 机械基本闲置，机制复杂度与语言能力不匹配；加超类约束要重开这条链。
4. **O(n²) close 只修一半**：`close_tm_reduced` 只在孪生（machine.rs:1988-2027）；参考版仍全量 `close_ty`（mod.rs:580-583 → syntax.rs:34-44），泄漏根因（ImplDecl 绑参进 decl 级 cxt）两版都在（elaboration.rs:537-559、621-622）⇒ 参考版仍付 O(D) wrapper/次·fresh_meta [码]。
5. **文档漂移大片**（§8.2）：README 行号、测试计数、孪生过时注释都需重校，照 README 读会踩空。
6. **继承 L09 时代缺口**：卡住 match 不可再应用、无 struct_eq、无 builtin 注册表、L07 加固未回灌；`enum` 负载孪生发散长期挂账。
7. **parity 不剥 `?N`**：把"meta 分配顺序"变成契约，等价重构即红，长期维护成本高。
