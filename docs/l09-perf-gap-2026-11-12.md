> 架构，导致两个原本 O(1) 的操作退化成 O(D)；L07/L08 为此做过的配套优化（decl 表、以及更早 L06 的
> `close_meta_ty` 快捷）在 L09 没有对位物。** 其中 `close_meta_ty` 是 L09 真实语料 684× 的直接主因。

## 0. 结论

1. **两种性能形态、两个不同量级**：
   - 普通声明形状（纯 def、strchain、struct、enum/match）：L09 比 L07/L08 慢 1.5–8.6×，总代价 **O(D²)**（实测
     log-log 指数 1.77–2.05，L07/L08 = 1.00），绝对量多在 2–60 ms；
   - **Eq/GADT 证明形状**（`def proof: Eq[Nat] lit lit = refl`）：L09 **每声明成本随 D 近二次增长**，总代价
     **O(D³)**（实测指数 **2.91**），801-decl 的真实阶梯文件 1743 ms vs L07 2.55 ms = **684×**。
2. **根因 A（普通形状）= 全局引用求值走 env 线性扫描**：L09 把每个顶层 def/enum/构造子都作为上下文条目压进
   `env`/`lvl`/`locals`/`pruning`（`src/L09_mltt/mod.rs:660-674`），引用老全局时得到 de Bruijn 下标 ≈ 当前声明数 D，
   而 `eval` 的 Var 臂在 Rc 单链 env 上 `iter().nth(index)`（`mod.rs:1021-1033`）⇒ **每次引用 O(D)**。
   阴性对照：universe 负载（2048 decls，但声明间无全局引用）L09 只要 2.4 ms。
3. **根因 B（证明形状）= `fresh_meta` 缺 L06 的 `close_meta_ty` 快捷**：L09 每次建隐式 meta 都无条件
   `eval([], close_ty(&cxt.locals, ...))`（`mod.rs:719-726`）；`cxt.locals` 长度 = D+2，`close_ty` 逐层 clone 定义载荷
   （`syntax.rs:35-52`），再把这条 **D 长的 Let 链整体求值**（`mod.rs:1080-1083`，每层载荷重求值、又踩根因 A）⇒
   **单次 fresh_meta ≈ O(D²)**。L06 有等价快捷并实测 implicit k=9 从 2350 → 27.9 ms（**84×**，`src/L06_string/mod.rs:180-203`）；
   L09 grep 零命中。`refl` 的隐式实参正好命中该路径，于是 394 条 proof 把文件从毫秒级推到秒级。
4. **L07/L08 为什么线性**：顶层声明只进 `Rc<Decls>` decl 表（`Tm::Decl(名字)` + `decl_get` O(1) 哈希查，
   `src/L07_sum_type/mod.rs:1349-1357`、`cxt.rs:350-352`），**不进** `Cxt.locals/env/lvl/pruning`
   （`elaboration.rs:159` 注释 + `infer_owned` 就地写：`elaboration.rs:216-268`）⇒ `cxt.locals` 只有当前 def 内的
   局部 binder（个位数），同一份 `fresh_meta` 代码链长恒定 → 不痛。
5. **不是 L09 独有 bug**：L10 是同一"再定基"血统，同一 801-decl 文件跑 **1060.8 ms**（0.61× L09，仍 **416×** L07），
   proofs 指数同为 2.91。L13 回归 decl 表后 strchain 从 61.7 → 13.2 ms（今日跨层表）。
6. **真正"没同步"的优化只有 4 条**（按影响排序）：
   | # | 缺的优化 | L07/L08 现状 | L09 现状 | 影响 |
   |---|---|---|---|---|
   | G2 | `fresh_meta` 的 `close_meta_ty` 快捷（L06 有） | 无此快捷，但 locals 短、不需要 | **无，且 locals 长** | **684× 主因**（真实语料） |
   | G1 | 顶层声明不进上下文 / 全局 O(1) 取用 | decl 表 `Tm::Decl` + `decl_get` | env 槽 + 线性 `nth` | strchain 7.9×、struct 8.6×、common 1.7× |
   | G3 | `Tm::Lam/Pi` 体 `Rc<Tm>` | `Rc<Tm>`/`Rc<Ty>`（`L07 mod.rs:71,75`） | 仍是 `Box`（`L09 mod.rs:68,72`），`eval_ref` 建 Closure 时深拷 | church 1.72×、natadd 1.30×、match 1.24× 的尾巴 |
   | G4 | 内建 PrimFunc+eta 注册 | decl 条目 `prim/eta`（`L07 cxt.rs:280-311`） | builtin 是普通项 + `Tm::Prim`（`L09 cxt.rs:34-92`） | strchain 常数项，非主因 |
7. **旧文档的根因说法半过期**：`BACKPORT-2026-11-11.md:192` 与 `bench-crosslayer-ref-2026-11-12.md:178`
   的「根因 = `src_names` 逐 decl 克隆」已被 `866f23e5`（2026-09-20）修掉（现在 `src_names` 只装局部条目，
   全局名在 `Infer.global_names`，`mod.rs:581-591`）；「无 decl 表」仍是事实且是根因 A/B 的上游。
   866f23e5 只把"克隆"降成 Rc 递增，**没有消除 `close_ty`/Let 链的 O(D²) 求值**，所以修完仍慢。
8. **修复顺序建议**：先 G1（env/locals 改 O(1) 索引的持久向量，或全局值段与局部段分离）→ 预期 strchain
   61.7→约 10 ms、struct 48→约 10–15 ms、common ladder 106→约 75–85 ms；再 G2（移植 L06 `close_meta_ty` 谓词 +
   把全局 define 槽从 `pruning` 掩码折叠）→ 预期 L09 真实语料 1743→约 100–200 ms（10× 级，L06 有 84× 先例）。
   G3/G4 作为常数收尾。以上为【预估，未实测】；两项修复有乘性交互（G2 链内求值踩 G1）。

### 1.3 读法

- **不是"声明多就慢"**：801 decls 的纯 def / 真实 ladder 在 L07 只要 2.5 ms；L09 在无隐式、无老引用的 universe
  形态上同样只要 2.4 ms。
- **两类差距分工明确**：无隐式实参的形态 ≈ 每声明 O(D)（指数 1.5–2.05）；有隐式实参的 proof 形态 ≈ 每声明 O(D²)
  （指数 2.9）。
- **引用距离是二阶乘数而非独立根因**：同 decl 数下 blocked（proof→lit 远引用）3297.8 vs interleaved 1721.2
  （1.92×）；真实 L09 ladder 是 interleaved，1743 ms。注意 `experiments.md` §5.3 把「远引用」读成"固定常数"
  是**对照组污染**（plain_defs 本身每条也引用 preamble 的 `Nat`/`zero` 两个老全局，远引用成本已含在对照组里），
  真实结论是「每声明 O(D) 与引用距离/次数成正比，二者与 D 耦合，所以比值恒定但增长项在」。

## 2. 机制链（代码锚点）

### 2.1 上游设计差异 D1：顶层声明成为上下文条目（L09 无 decl 表）

| 项 | L07/L08 | L09 |
|---|---|---|
| 顶层 def/enum/构造子的名字 | decl 表键（`Rc<Decls>`，`cxt.rs:16-41,144-157`） | `Infer.global_names`（append-only，`mod.rs:581-591`） |
| 顶层声明的值 | decl 表条目 `Rc<DeclEntry>` | `Infer.global` 表 + **`Cxt.env` 槽** |
| 上下文（env/lvl/locals/pruning）长度 | 只 = 当前 def 内局部 binder 数（+2 内建） | **= D + 局部**：`define_global` 每次 `env.prepend(vt)`、`lvl+1`、`pruning.prepend(None)`、`locals::Define`（`mod.rs:660-674`） |
| 登记入口 | `decl_insert_mut`（`elaboration.rs:248,261,353,362,403,407`） | def/枚举本名/构造子**三路都 `define_global`**（`mod.rs:409/515/557`；`fake_bind` 只写名字表不碰 env，`mod.rs:647-655`） |
| 项层引用形 | `Tm::Decl(SmolStr)` + `decl_get` O(1)（`L07 mod.rs:1349-1357`、`cxt.rs:350-352`） | `Tm::Var(lvl2ix(cxt.lvl, level))`，下标 ≈ 距定义处的事件数（`elaboration.rs:644-651`） |

### 2.2 根因 A（G1）：全局引用求值 = O(D) 的 env 线性扫描

- `eval`/`eval_ref` 的 Var 臂：`env.iter().nth(x.0 as usize)`（`mod.rs:1021-1033`）；`Env` 是 `Rc` 单链 `List`，
  `nth` 从头数（`src/list.rs:232-251`）。
- 顶层声明进了 env ⇒ 老 def/内建/构造子的下标 ≈ D ⇒ 每次引用 O(D)。另外**递归 def 的自引用**用哨兵下标
  （`global_idx + 1919810`），当前代码也是先白扫整条 env 才回落 `Infer.global` 哈希——顺手可加
  `x.0 >= GLOBAL_BASE` 早分支（小头）。
- 定量：strchain 4096 defs × 每 def 约 2 个老引用（`string_concat`、`s_{i-1}`）≈ Σ2i ≈ 16.7M 节点访 ≈ 45–55 ms，
  与实测 61.7 ms 同量级；struct 2048 defs × 4–5 个老引用（`get_x`/`P`/`zero`/`Nat`）≈ 30 ms，量级吻合 48.1 ms。
- 对照：L07/L08 的 `Tm::Decl`+`decl_get` O(1)，且 env 只含局部 binder；L09 **孪生**用
  `Machine.globals: Vec<V>` + `global_names`（`L09 README:238-243`，perf-debt P2），下标 O(1)。

### 2.3 根因 B（G2）：`fresh_meta` 每次 O(D²)

- `fresh_meta`（`mod.rs:719-726`）：`eval([], close_ty(&cxt.locals, quote(cxt.lvl, a)))` **无条件**执行。
- `close_ty`（`syntax.rs:35-52`）为每个 `Locals` 条目套一层 `Tm::Let`，并逐层 clone 该条目的类型/体载荷 ⇒ O(D) 构造。
- 随后 `eval` 这条 Let 链（`mod.rs:1080-1083`）：逐层重求值每个既往 def 的项载荷，载荷里的全局引用又踩根因 A
  ⇒ 单次 ≈ **O(D²)** 节点访。
- L06 的等价快捷 `close_meta_ty`（`src/L06_string/mod.rs:174-203`）：当 `locals` 全是 define 槽、且被 quote 的类型
  不读 env 时，整条 Let 链对求值透明，直接 `eval [] q`。其注释自证实测 **implicit k=9（D=1024）2350 → 27.9 ms（84×）**。
  L09 grep `close_meta_ty|all_define_slots|env_independent` **零命中**。
- 为什么 proof 声明是热点：`def proof: Eq[Nat] lit lit = refl` 里裸 `refl` 的隐式实参要建 meta
  （`insert_go`，`elaboration.rs:16-29`），每个 proof 至少 1 次 `fresh_meta` ⇒ 每声明 O(D²) ⇒ 总 O(D³)。
- L07/L08 **也没有**这个快捷，但其 `Cxt.locals` 不随 D 增长（顶层声明走 decl 表），链长个位数 → O(1)；
  即「同一条优化在 L07/L08 没有宿主，也就没人痛」。

### 2.4 次要与已排除项

- **G3**：`Tm::Lam/Pi` 体 L09 仍 `Box`（`mod.rs:68,72`，`eval_ref` 建 Closure 时深拷 `mod.rs:1069-1079`），
  L07/L08 已 `Rc`（`L07 mod.rs:71,75`/`L08 mod.rs:81,85`）；`85b9c87e` 只回灌了 Closure 侧（L09 `Closure` 已 `Rc`，
  `mod.rs:164`）→ 解释 church/natadd/match 的 1.2–1.8× 尾巴。
- **G4**：L09 builtin 是普通项（`cxt.rs:34-92`，求值靠 `Tm::Prim` 特例 `mod.rs:1089-1098`），L07/L08 有
  decl 条目 `prim/eta`（`L07 cxt.rs:280-311`、`mod.rs:1052-1070`）→ 常数项。
- **已排除**：`unification.rs` 的 `lams(pren.dom, …)` 初看像 O(D)，但 `pren.dom` = meta 应用 spine 长度
  （顶层 meta 的 pruning 全 None ⇒ spine≈0），不是热点；pruning 掩码 O(D) 遍历（`v_app_pruning`，`mod.rs:969-983`）
  是 G2 的次级放大项（置信度中低）。
- **已同步**（不是缺口，避免误伤）：全局名搬 `Infer`（866f23e5）、`Locals` Rc 脊、`src_names` 仅局部 + `Rc<VTy>`、
  `Closure` 体 Rc、值层 Rc 槽（33a08764）、`neutral_globals` Cell 取代整机 `Infer::clone`、quote/rename 深链帧式化、
  struct_eq Match 快路径、match 编译器逐臂、深值迭代化。

## 4. 修复方案与预期（按性价比排序）

1. **P0 / G1：让「取全局值」O(1)**。两条路线：
   - 小改：`Env` 改为「全局段 + 局部段」两栈——局部段 Rc 单链短，全局段用 `Vec`/持久向量按 level O(1) 索引；
     配合 L07 的 `infer_owned` 所有权传递（`Rc` 强计数=1 时 `make_mut` 原地 push）避免再复制。
   - 顺手项：`eval` 的 Var 臂先判 `x.0 >= GLOBAL_BASE`（递归自引用哨兵）再扫 env。
   - 预期【预估】strchain 61.7→约 10 ms、struct 48→约 10–15 ms、common ladder 106→约 75–85 ms；universe 2.4 ms 不应变（阴性对照）。
2. **P0 / G2：移植 L06 `close_meta_ty`**：在 L09 的谓词形态是「`cxt.locals` 无 Bind 槽（全 define）且
   quote 结果不含小下标 Var（即不读 env，只有哨兵/全局引用）」→ 跳过 `close_ty`，直接 `eval [] q`。
   同时把「顶层 define 槽」从 `pruning` 掩码里折叠（或用稀疏表示），减少 `AppPruning` 的 O(D) 遍历。
   - 预期【预估】L09 真实语料（801 decls）1743→约 100–200 ms（10× 级；L06 有 84× 先例）；proofs 家族指数应从 2.91 回落。
3. **P1 / G3**：`Tm::Lam/Pi` 体 `Box`→`Rc<Tm>`/`Rc<Ty>`（同步 `eval_ref` 两处深拷点）
