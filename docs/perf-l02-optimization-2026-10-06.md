# L02 性能优化空间评估（2026-10-06）

**问题**：L02（`src/L02_tyck`，带类型核心：双向 check/infer + Π/let + beta-eta conv）还有没有性能优化空间？

**本报告**：Lead 汇总，四份子报告 + 全部原始证据支撑：

| 子报告 | 内容 |
|---|---|
| [00-baseline.md](perf-l02/00-baseline.md) | 本机基线矩阵 + 噪声界（含"档位成块"机制）+ 确定性内存基线 |
| [01-hotpath.md](perf-l02/01-hotpath.md) | 热点逐段走查 + 13 条候选 C1–C13 + 已封顶轴 |
| [02-experiments.md](perf-l02/02-experiments.md) | 判定协议 + 5 条内建消融 + C1/C2 影子副本 A/B |
| [03-verification.md](perf-l02/03-verification.md) | 独立对抗性复核 |

计时口径：`taskset -c 7`（Cortex-X2）+ keep-alive 保频 + 独占锁 + **强制 `--only`
单实现隔离** + 整轮重复 + 指标 `med_of_min`，A/B **同批严格交错**。
**`src/L02_tyck/readme.md` 的数字来自 Windows x64，不是本机事实**，引用处均标注。

## 0. 结论

### 0.1 三层回答

**第一层 · 对产品：优化空间 = 0（结构决定）。**
`mod L02_tyck` 虽在 `src/lib.rs:36-37` 声明，但带
`#[cfg_attr(not(test), allow(dead_code))]`，**lib 内没有任何调用点**——它是死代码；
真实使用者只有 `src/bin/l02bench.rs`、`src/bin/l02l05mem.rs` 两个基准 bin 和三个
黑盒测试。所以本轮**所有候选的产品收益都是 0**，价值在"研究/基准产物"以及
**"给 L03–L13 的机制模板"**（L03+ 的性能版是 L02 的逐层继承体）。

**第二层 · 现有机制的贡献已经被量化（本轮最有价值的部分）。**

| 机制 | `conv` | `conv_dup` | `church` | 本机判定 |
|---|---|---|---|---|
| 位相等快速路径 + 链内联环（`L02_NO_BITEQ=1`） | **2.02–2.22×** | 1.076–1.091× | 1.018–1.046× | 判定（3 k 全部） |
| conv 判等记忆化（`L02_NO_CONV_MEMO=1`） | ~0%（未判定） | **1.48–1.49×** | 不触发 | 判定（conv_dup 3 k） |

- **conv 总时间的 51–55% 是位相等+链内联环省下来的**；剩下 46% 是"结构确实不同、
  必须真走"的比较树。**不要再在 conv 上加同类位相等剪枝——上限就是那 46%。**
- **conv_dup 的关键路径是判等记忆化**（1.49×），位相等只值 8%。
- **readme 的"church 上中性"在本机不成立**：关掉 BITEQ 后 church k=11/13/15 分别
  **+4.6% / +3.8% / +1.8%**（符号检验 18/21、21/21、19/21，p=1.5e-3 / <1e-6 / 2.2e-4；
  该批 63/63 rep 频率恒定、null 双段互证）。但 **k=15 余量较薄**（1.805% vs 地板
  1.233%），且 E1–E3 用的是固定 A-先顺序（复核 §8 问题 7），故措辞按"**本机不成立**"
  而非"推翻"。即 church 负载的 **check 相位**也吃位相等剪枝。
- **确定性证据（零噪声）**：关掉 BITEQ 后 `conv` k=13 的 arena 高水位 10.0→**23.6 MB**
  （2.35×）、稳态 churn 从 295 allocs/49.5 KB（**arena 0 块**）变成
  484 allocs/**2.58 MB**（1.25 MB arena/轮）。⇒ **位相等省的不只是比较分支，
  而是整段求值+分配**（`EvalCod2 → evalExpr` 的 `EnvCons` 链）。

**本轮还实测抓到一块真实收益（唯一判定成立的优化）**：`eval_iter` 的**尾任务寄存器化**
——β/let 三处"入栈后必被立刻弹出"的 `work.push(W::Tm(…))` 改为循环局部 `cur`，
**12 行、严格 LIFO 等价**，实测 `church` **−6.42% / −5.77%**、`conv` **−7.42% / −5.70%**
（42 reps/侧、同批交错配对、配对地板 0.65–3.34%；同频平台子集 + 前后半 + pair 首位 +
频率分布四重排伪影全部通过），`l02l05mem` 分配计数**逐字节不变**。
**它比审计的 2–6% 预测更肥**（审计自评"最可能被证伪"的反而是它）；而审计预测 1–4% 的
`W` 40B→24B（C1）**未判定**——补丁确实生效（`size_of` 40→24B、分配字节精确下降
−8704 B（church）/ −12096 B（conv）、直方图出现 160 B→96 B 尺寸类迁移）但被
store-forwarding 吸收。详见 §4。

**第三层 · 剩余空间的形状（由上面的分解反推）。**

1. **油水在"残留路径的常数"，不在"减少比较次数"**：最大的那类比较已经被 O(1)
   位相等删掉，剩下的 46% 是真结构比较。**最值钱的优化形态 = 把"要结构比较 /
   要重复求值"的地方换成 O(1) 判定**，同类尚未覆盖的位置有两个：
   - **η 展开路径**（`bump_spine_iter.rs:691-713`）：每个 `(λ, 值)` 都新建
     `EnvCons` → `eval_iter` → 新 λ 值，**没有"该 η 对已比较过"的记忆化**，
     而 conv 的重复结构里 η 对可能重现；
   - **同一轮内跨 conv 调用的共享表**：现在每次 `conv_iter` 都新建
     `FxHashSet`（L03+ 的 `ConvScratch` 是这条路的形态）。
2. **数据结构常数（本轮 A/B 的对象）**：L02 的 `W` 枚举 **40B**（L01 只有 24B，
   因为 `W::PiBody(&str,&Tm,Option<&EnvCons>)`）、`Tm` 枚举 **48B**（L01 是 24B）、
   `WItem` 40B、`QJob` 48B。结果树每个节点都付 48B——这些是纯搬运/布局常数。
3. **已封顶的轴比 L01 多**：readme 已实测否决 7 条（左折叠下钻、`ApplyKnown2`、
   `nth` 展开、**spine 预分配 2^18（中性）**、`target-cpu=native`、eval 侧 β 记忆化、
   名字表示），本轮静态审计另判死 `Entry`/`QJob` 重叠项与边界检查类。
   ⚠️ **L01 轮的 spine 预保留结论（−7~10%）不能外推到 L02**：L02 的同类轴已有
   负面实测，且 `fast_ss` 在 L02 上几乎无收益（见 §2）——两层的分配结构不同。

### 0.2 方法学：本机噪声不是 i.i.d.，是"档位成块"

这是本轮与 L01 轮最大的不同，也是**必须先解决才能谈 1–6% 优化**的前提：

| 现象 | 实测量级 |
|---|---|
| 两个时钟档（church k=13：慢 1.025 ms / 快 0.852 ms，差 ~20%），**按进程抽取、时间成块** | — |
| `med_of_min` 跨批离散（3 个相同批次） | 中位 **0.19%**、最大 **1.46%** |
| `min-of-7` 跨批离散 | 最高 **20.1%** → 不可用 |
| **同批严格交错** A/B（21 reps/侧）奇偶分割假阳 | ≤**0.58%** |
| **"先跑完 A 再跑 B"（blocked）假阳** | **18.8–19.3%**（前 21 rep vs 后 21 rep，后段为分母） |
| 配对相对差 + 配对 bootstrap 地板（p95） | 中位 **~0.5%**、多数 ≤1.3%、**约 1/4 的格 2–10%** |

**"刀锋格"**：当 ~40% 的 pair 跨档时，配对各差呈"大正/大负/近零"三簇，点估计仍
无偏（null 段配对中位 −0.2%~+0.9%），但 bootstrap 可把中位推到相邻簇 ⇒ p95 抬到 8–10%。

**四条补救路线全部实测否决**（这是本轮的可复用结论，避免后人重走）：
| 路线 | 结论 |
|---|---|
| 加大 `--rounds` 让单 rep 的 min 跨档 | **不成立**：地板由**段位置/机器状态**主导（PRE1 看似 0.22–0.39%，PRE2 反序第一段就回到 6.87%）；且 rounds=25 使 k=15 绝对值 +8.1% |
| `scaling_cur_freq` 分层 | **无效**：63/63 rep 读数恒 2246400 kHz，却有 6.87% 地板 → 边界采样不是档位代理 |
| 进程内 k 归一化（double-ratio） | **更差**：噪声含 k 特异分量，归一化把它放大 |
| 总时间配对（Σ over k） | **不改善**：跨 k 有共模分量，求和保留它 |

⇒ **1–6% 效应的现实分辨率 = 该批该格的同批 null 地板**：≲1% 时可判；2–10% 时
必须重跑该批（换时间窗）。**任何未交错的 `fast_ss`/变体对比都不可信**——本轮
实测 `fast_ss` 对 `fast` 的"20–24% 收益"交错后只剩 **+1.6%/+2.5%/+6.0%**
（k=11/13/15，church），与 readme"两口径相当"一致。

## 1. 评估对象与边界

- L02 = `src/L02_tyck`：**带类型**层（Π/let + 双向 check/infer + beta-eta conv）。
  性能版 `bump_spine_iter.rs`（1715 行）；参考版 `mod.rs`（782 行）；
  parser 在 `parser/`。基准 `src/bin/l02bench.rs`（五负载 × 四实现 `basic`/`fast`/
  `fast_ss`/`fast_memo`），另有 `src/bin/l02l05mem.rs`（确定性分配计数）。
- 比 L01 多三条 L01 没有的热路径：**elaboration**（check/infer）、**conv 转换检查
  工作表**、**源文本解析 + 名字**。
- **L02 已具备 L01 轮发现的所有机制**（`ApplyKnown`、`ChainWrap(0)`、quote 记忆化、
  conv 判等记忆化、conv 位相等快速路径）——本轮找的是"下一层"空间。
- **变体形态冻结**：本轮未改主仓库任何源码（`src/**`、`Cargo.toml` 零改动）；
  所有改码实验在工作区外影子副本 `/tmp/l02-exp`。

## 2. 基线要点（完整表见 [00-baseline.md](perf-l02/00-baseline.md)）

`med_of_min`（ms，k=15，7 reps，`--only` 隔离）：

| workload | `fast` | `fast_ss` | `basic` | `fast_memo` |
|---|---|---|---|---|
| church | 4.493 | 3.592 | 66.95（14.9×） | — |
| conv | 6.307 | 5.834 | 246.81（**39.1×**） | — |
| conv_dup | 13.416 | 14.021 | — | — |
| dup | 7.632 | 7.239 | 137.87 | 6.094（**1.25×**） |
| dup_deep | 15.985 | 14.366 | 314.65 | 6.658（**2.40×**） |

- `basic`/`fast` 倍率本机 church ~15×、conv ~39×（readme 记 13×/25–27×）——
  本机 `basic` 更吃亏；`fast_memo` 对复制负载 1.25×/2.40×。
- 隔离后 `conv_dup k=15 fast_ss` 的 min = 12.15 ms，**复现 readme 自记的"隔离 12 ms"**，
  并确认"全量同进程跑 21 ms"是足迹污染（`fast_ss` 的大 bump 池页被淘汰）。
- **`fast_ss` 在 L02 上几乎没有收益**（交错后 +1.6~+6.0%）——L01 的稳态复用收益
  不迁移，因为 L02 的 elaboration 里 bump 分配占大头。

**确定性内存基线**（`l02l05mem --chapter L02`，同命令两次运行逐字节相同）：
k=11 `basic`/`fast` 字节比 church 6.9×、conv 21.8×、conv_dup 12.6×、dup 5.2×、
dup_deep 8.7×（分配**次数**比 765×–2910×）；`fast_ss` 稳态 churn ≤0.16 MB/轮
（conv 仅 46 KB，arena 0 块），dup_deep 例外 1.51 MB；`fast_memo` 把 dup 足迹
4.05→1.48 MB、dup_deep 4.62→1.49 MB。

## 3. 内建消融：机制贡献分解

矩阵与判定见 [02-experiments.md](perf-l02/02-experiments.md) §3；开关语义已核实为
`LazyLock<AtomicBool>`（**环境变量只读一次**，两臂同成本，A/B 干净），
`=0` ≡ 不关、空串 ≡ 开（`l02l05mem` 确定性证明：`=0` 只多 1 次 alloc/1 B =
`env::var` 的 String）。

| 消融 | `conv` | `conv_dup` | `church` |
|---|---|---|---|
| `L02_NO_BITEQ=1`（= 位相等 + 链内联环，**两者之和**） | +102.2 / +117.4 / +121.1% | +7.6 / +8.0 / +8.8% | +4.6 / +3.8 / +1.8% |
| `L02_NO_CONV_MEMO=1` | −0.2 / +0.1 / 0.0%（未判定） | **+48.2 / +49.4 / +47.6%** | 不触发 |

（k=11/13/15；"+" = 关掉机制后变慢的百分比，故 `conv` 的 BITEQ 值 2.02–2.22×。）

**与 readme 的对照**：BITEQ conv "~2×" **复现**（2.17/2.22×）；memo conv_dup
"1.4–1.6×" **复现**（1.48–1.49×）；memo 在 conv 上"零税"定性一致（本机点估计 ≤0.6%，
地板 2.1–9.1% → 未判定）；**"church 中性"在本机不成立**（+1.8~+4.6%，k15 余量较薄，
见 §0.1 与复核 §8 问题 6）。

**归因边界（必须写清）**：`L02_NO_BITEQ` 同时关掉 4 个决策点（`:683` 顶层 +
`:784/:789/:795` 链内环），所以上表是"两处剪枝之和"，**无法单独归因**；
`L02_NO_CONV_MEMO` 同时关掉查表+插入+扩容。凡引用这两行都必须带此限定。

**确定性交叉证据**：见 §0.1 第三层第 2 条（BITEQ 关掉 ⇒ conv arena 2.35×、
churn 从 0 arena 变 1.25 MB/轮）。

## 4. 候选 A/B（影子副本）

协议：跨二进制 A/B（驱动支持 `--bin-a/--bin-b`），**一次取锁内跑三段**
`nullA(bin_a×2) / ab / nullB(bin_b×2)`，段内**严格交错** A1B1A2B2…、pair 内顺序按
奇偶交替、**42 reps/侧**、`--only fast`、k=13/15；判定用**同批 null 段的配对地板**。
主负载 `church`（eval 侧占 93%），`conv` 次要。三条硬约束全部满足：主树 `src/**`
零改动、每个补丁过 `cargo test --lib L02_tyck`（27 用例）与
`cargo test --release --bin l02bench`、`l02l05mem` 分配计数不变性自检。

### 4.1 对照：跨树/跨次构建混杂 ≈ 0.1%

主树二进制（`28d988…`）vs 影子树同源未改 base（`6f9a27…`）：church k13 **−0.097%**、
k15 **+0.041%**（该批 84/84 rep 频率恒 2246400 kHz、42/42 pair 稳定）。
⇒ 混杂量级 0.1%，**远小于待判效应（1–6%）**，C1/C2 的判定无需再扣。

### 4.2 C1 `W` 枚举 40B→24B：**未判定（无可测收益）**

| 负载 | k | 配对差 | 同批配对地板 | 判定 |
|---|---|---|---|---|
| church | 13 | +0.438% | 0.822% | 未判定 |
| church | 15 | −0.493% | 2.668% | 未判定 |
| conv | 13 | +0.016% | 1.185% | 未判定 |
| conv | 15 | −0.189% | 1.588% | 未判定 |

**补丁确实生效，只是被微架构吸收**——确定性签名：同构副本实测
`size_of::<W>()` 40 → **24B**；`l02l05mem` 对照 allocs **逐格 +0**、bytes 精确下降
**−8704 B（church）/ −12096 B（conv）**（raw 逐字节核对：5224576→5215872、
1962821→1954117、10498376→10486280、49528→37432），直方图出现 160 B→96 B
尺寸类迁移，arena 序列逐项不变。⚠️ 复核（task-10 §8 问题 1）指出：本节初稿写的
"恰好 = 16 B × 544/756 个 `Vec<W>` 元素"中 **544/756 在 raw 里没有支撑**（乘积算术
恒真，但属推导而非独立证据），**已降级为描述性解释**；raw 支持的是"bytes 精确下降 +
160→96 尺寸类迁移"。⇒ **"改到了但测不出"**：省下的是 L1 命中内的 store+load，
Cortex-X2 的 store-forwarding 把它吸收掉了。这与 L01 轮"小栈变体无收益"同族。

### 4.3 C2 尾任务寄存器化（12 行）：**判定成立，~6% 加速**

改动：`eval_iter` 主循环把三处 β/let 尾部的 `work.push(W::Tm(…))` 改为循环局部
`cur` 寄存器（严格 LIFO 等价——三处臂内没有更晚的 push），免一次 40 B store+load
与一轮 jump-table 分发。

| 负载 | k | 配对差 | 同批配对地板 | 判定 |
|---|---|---|---|---|
| church | 13 | **−6.42%**（CI [−7.52, −5.70]） | 0.652% | **判定** |
| church | 15 | **−5.77%** | 1.358% | **判定** |
| conv | 13 | **−7.42%** | 3.339% | **判定** |
| conv | 15 | **−5.70%** | 3.161% | **判定** |

**为什么这个 ~6% 不是档位伪影**（这批段内降频很凶：1766400 阶梯降到 921600 kHz，
段间绝对水平漂 2.27×、**非配对地板爆到 52–55%**；复核补充：该批 **nullA 段本身在
2.36 GHz**，漂移主因是它。四重排伪影检查全部通过）：
1. **同频平台子集**（仅取恒定 921600 kHz 的 rep，n=27 pair）：k13 **−6.30%**、
   k15 **−5.91%**（平台自身 null 地板 0.70%/0.54%）——与全样本结论一致；
2. 前半 −7.16% vs 后半 −6.24%（无时间漂移伪影）；
3. A 先 −6.30% vs B 先 −6.55%（**无首位伪影**，pair 内顺序按奇偶交替）；
4. **频率分布对 A 略有利**（A 多一个高频 rep）而 A 仍慢 6% ⇒ 混杂方向**对效应不利**；
   conv 侧 B 更多落在最低档（787200）也仍快 7.4%；
5. 跨树/跨次构建混杂仅 0.1%（§4.1）。
**确定性不变性**：C2 的 `l02l05mem` 计数与 BASE **逐字节相同**（allocs/bytes 全 +0，
church+conv）⇒ 纯寄存器化，无分配/容量副作用。

**与审计预期的对照**：审计预测 C2 为 2–6% 并自评"**最可能被证伪**"（理由是 `work`
是 L1 热 Vec、40 B 搬运会被 OoO 吸收）；实测 **5.7–7.4%**，反而成立。而审计预测 1–4%
的 C1 落空。**教训：在本机上"栈条目宽度"类预测不可靠；"尾任务是否需要重新入栈再
弹出"这类控制流事实才可靠。**

### 4.4 正确性

C1/C2 各自 `cargo test --lib L02_tyck` **27/27**、C2 `cargo test --release --bin
l02bench` **27/27**；252 个计时 rep 的内置 `bench_check`/nf 节点数断言全过。

## 5. 结论与建议

**对产品**：仍然 **0 收益**（§0.1 第一层）——L02 是 lib 里的死代码，产品用的是 L13。

**L02 作为研究/基准产物：还有空间，而且本轮抓到了实打实的一块。**

1. **已确证可做（本轮唯一判定成立的优化）**：**C2 尾任务寄存器化**，12 行、
   church/conv 各 **−6%/−7%**、分配计数逐字节不变、27/27 测试全绿。这是本轮最该
   落地的改动。**但注意 L02 是 L03–L13 的逐层继承源**：只改 L02 会造成"参考层与
   继承体分叉"，落地方式需要决策（见第 4 条）。
2. **不要再做的轴**（有实测依据）：
   - **纯字节瘦身类**（C1 型）：`W` 40→24B 补丁生效但墙钟测不出（store-forwarding
     吸收）；同理"结构体再小 16 B"的预期收益在本机基本不可信。
   - **conv 侧再加同类位相等剪枝**：BITEQ 已经删掉 conv 一半以上的工作量，剩下 46%
     是"结构确实不同、必须真走"的比较树。
   - **容量/预分配/复用类**：readme 已实测 spine 预分配 2^18 中性；本机复核
     `fast_ss` 对 `fast` 只有 +1.6~+6.0%（L01 的稳态复用收益不迁移）。
   - readme 已否决的其余 6 条（左折叠下钻、`ApplyKnown2`、`nth` 展开、
     `target-cpu=native`、eval 侧 β 记忆化、名字表示）——L02 上不要重试。
3. **下一层该找什么**（消融反推 + 审计共识）：
   - **同类"把重复求值/重复比较换成 O(1)"的位置**：**η 展开路径**
     （`bump_spine_iter.rs:691-713` 每次 `(λ, 值)` 都新建 `EnvCons` → `eval_iter`，
     **没有"该 η 对已比较过"的记忆化**）；**同一轮内跨 conv 调用的共享表**
     （每次 `conv_iter` 新建 `FxHashSet`；L03+ 的 `ConvScratch` 是这条路的形态）。
   - **eval 主循环的其它 push/pop 与分发**：本轮 C2 只吃了"尾部必弹"的三处；
     `W::Tm(Tm::Pi/Let)` 的非尾推、`ChainWrap`、`WItem` 条目还没按同一思路过一遍。
     **这是本轮验证过的方法论（找"入栈后马上弹出"的控制流事实），值得沿轴继续。**
4. **落地范围：C2 不止是 L02 的事——它是全链共有的模式（Lead 已核实）。**
   grep 全仓：`work.push(W::Tm(c.body, …))` 这条"尾任务入栈后立刻弹出"的模式在
   **L03/L04/L05/L06/L10/L12/L13 的 eval（各 3 处）+ `bench_head`** 全都在，
   **没有任何一层做了寄存器化**（`cur = Some(W::Tm…)` 计数全为 0）。
   即：
   - 对 **L02**：这是它自己的未收割收益（~6%）；
   - 对 **L03–L12**：同样的模式在每一层；
   - 对 **L13（生产引擎）**：`src/L13_namespace/bump_spine_iter/eval.rs` 也有 3 处——
     **这是本轮唯一可能触及产品性能的发现**（L13 是 `typort` 的实际引擎，
     `measure_loop.sh` 可直接量 `typort check examples/hdl/*.typort` 的端到端墙钟）。
   落地选项：① 只改 L02 并登记与 L03+ 的分歧；② 下沉全链（每层一个补丁 + 各自 A/B）；
   ③ **先在 L13 上用 `measure_loop.sh` 量端到端收益，再决定下沉范围**（Lead 推荐：
   L02 bench 上的 ~6% 是合成负载，端到端值不值得铺 12 层要先用真实 HDL 负载回答）。
   **本轮按用户要求只做分析，未动主树源码；C2 的补丁在 `/tmp/l02-exp/exp9-c2.patch`
   与 `docs/perf-l02/raw/exp9-c2.patch`。**
5. **先修测量口径再做 1–6% 决策**：本机 `walt` 档位成块，**任何未同批交错的对比都
   不可信**（blocked 假阳 18.8–19.3%）；同批交错 + 配对统计 + 同批 null 地板能把
   分辨率做到 ~0.5%，本轮 C2 的 ~6% 正是靠这套口径才判得出来。

## 6. 复核与局限

- **独立复核**：[03-verification.md](perf-l02/03-verification.md)（task-10，391 行，
  自写分析器 + 独立重跑 + 603 个 `verify-*` raw）。结论表 15 条：
  - **C2 ~6% → 成立**：复核员用自写分析器从原始 rep 重算 **−6.420 / −5.765 / −7.416 /
    −5.703%**（与实验方逐字相同），并**独立重跑**得 **−6.529 / −5.596 / −7.713 /
    −6.445%**，四格判定、符号检验 p ≤ 7e-5；同频平台子集（n=27，−6.295/−5.909）、
    前后半（−7.162/−6.236）、A 先/B 先（−6.295/−6.545）、频率分布、跨树 0.1% **五重
    排伪影全部逐字复现**。
  - **C1 无可测收益 → 成立**：四判定格全未判定；复核还做了 k=9..15 全扫描，k=9/10
    名义 `判定(+0.69/+0.75%)` 的**方向是"略慢"**，且低于 1 µs 量化分辨率（低 k 处
    1 µs ≈ 1.4%），**不得当作收益引用**。
  - 消融（BITEQ 2.02–2.22×、conv_dup MEMO 1.48–1.49×、church BITEQ 非中性）、
    配对统计量、预注册（计划文件 mtime 早于取数）→ 均**成立**；数字抽查
    `00-baseline` 8 项、`02-experiments` 12 项**全部复现**。
  - 卫生：`git status --short -- src/` 为空、主树二进制 sha256 未变、
    `cargo test --lib L02_tyck` 退出码 0。
- **复核要求降级/已修订的 4 处**（均已在本报告落实）：
  ① "−8704 = 16 B × 544/756" 的 544/756 **无 raw 支撑** → 降级为描述性解释（§4.2）；
  ② blocked 假阳 18.84% **未标分母** → 补"前 21 vs 后 21"（§0.2）；
  ③ church **"推翻中性"措辞过强**（E1–E3 为固定 A-先顺序）→ 改为"本机不成立"
  （§0.1/§3）；④ C2 降频叙述漏了 **nullA 段在 2.36 GHz** → 已补（§4.3）。
- **协议的两点已知限制**（复核 §4.3，不影响 C2 判定）：① 逐格 null 地板是**单种子
  bootstrap 点值**，2/42 格不可逐字复现（±0.2–0.4 pp）；② E1/E2/E3 用的是**固定
  A-先顺序**（E2 的 +8% 属弱协议）——最终引用消融数字时应并列本次补做的精确符号检验。
- **未做项（如实记录）**：影子二进制 `l02bench-c2` 与补丁的**重建级比对**未做
  （补丁逐字节一致且 `git apply --check` 干净，属间接证据充分）；release 测试按时间盒
  未重跑（引用现有 27/27 日志）；C2 的 `--only fast_ss` 口径、k=11 格、C1+C2 叠加未复核。
- **消融不可单条归因**：`L02_NO_BITEQ` 是"位相等 + 链内联环"之和（4 个决策点），
  `L02_NO_CONV_MEMO` 是"查表+插入+扩容"之和。引用时不得写成单条机制。
- **分辨率上限**：1–6% 效应的判定完全取决于**该批该格**的同批 null 地板（观察分布：
  中位 ~0.5%、多数 ≤1.3%、**约 1/4 的格 2–10%**）。地板 2–10% 的格必须重跑，
  不能"拿同向当成立"。
- **规模上限**：本轮 k ≤ 15（bench 默认上限），更大 k 未测，不能外推。
- **确定性口径的边界**：`l02l05mem` 能证明"分配次数/字节变了多少"（精确、可复现），
  但**不能换算成时间**；C1 就是"分配字节确实少了 8.7–12 KB 而时间测不出"的实例。
- **绝对值的时效性**：全部数字属于同一 campaign（2026-10-06/07）；跨天/跨 session
  的绝对值不可比（governor 档位状态不同），只有同批相对值可用。
- **未测变体**：`basic`（参考版）只做了少量对照；`bump_spine_iter` 之外的实现
  （如 L03+ 的孪生）不在本轮范围。
