## 0. 一页纸结论

| # | L13 机制 | 结论 | 一句话理由 |
|---|---|---|---|
| 1 | 采集总闸 `lsp_collect` / `observe` | **需改造** | 两版 L06 都没有采集位；引擎结构（`Infer` / `Machine`）有承载面，但 L06 的 bench/run 口径必须默认关（L13 默认开） |
| 2 | 登记面 `DeclEntry` 带 span + `typ_pretty`（+ final 短路） | **需改造** | 两版 L06 的 decl 条目（4 / 3 字段）都不带 span 与渲染串；Def 名 span 就在 AST `Decl::Def.name` 里，可直接回填 |
| 3 | 观察表 + push 方法 | **需改造（子集）** | hover / inlay / println / check 有承载面；`completion` / `push_ctor_hover` / `push_qualified_hover` 在 L06 语言面无触发语法 |
| 4 | println 两阶段（`defer_println` / `println_jobs`） | **不适用**（span 侧可移植） | L06 只有单一返回串消费方，没有"诊断先发布、归一化后置"的两阶段管线；`println_spans` 本身可移植 |
| 5 | 失败 decl 通道（`failed_decls` / `note_failed_decl`） | **需改造** | 记录面可移植；L13 的**降级消费**（not-in-scope → "declaration failed above"）依赖继续型驱动，L06 `run` 是 fail-fast |
| 6 | 求值预算（`eval_budget`） | **需改造（部分不适用）** | tick/scope/checkpoint/`ElabTimeout` 可移植；`NatChainOverflow`/`guard_nat_chain` 无承载面（L06 无原生 Nat/`SumCase` 链） |
| 7 | check issue 的 LSP 通道 | **需改造** | 数据已在产生（`report_check_issue` → 可变全局 `CheckIssues`），但无 LSP 可见通道；排水**不能**清空全局（L06 把该全局当用户可见值打印） |
| 8 | 常驻 prelude / arena 压实 / twin kick（`prime_resident`/`observe_user`/`compact_state`） | **不适用** | L06 无 prelude、无常驻检查点、无跨 kick 状态（每轮 `Bump::reset`） |
| 9 | `FORCE_MEMO`（force 记忆化及其轮界清理） | **不适用** | L06 两版都没有 force 记忆化：force 只展开已解 meta 链，不展开 decl 值，无跨轮 memo 清理面 |
| 10 | 双引擎 owned 快照契约（`HoverEntry` + `hover_entry_at`） | **可移植** | 两版共用同一 parser AST，span 原生带 `path_id`/offset；观察面一律 owned `String` + `Span<()>` |

统计：**可移植 1 项**（#10）、**需改造 6 项**（#1/#2/#3/#5/#6/#7）、
**不适用 3 项**（#4 的 defer 半边/#8/#9）。可移植项 ≠ 0 ⇒ 进入实现阶段。

## 1. 逐项审计（代码坐标 + 证据）

### 1.1 采集总闸 `lsp_collect` / `observe`

- L13 参考版：`L13_namespace/mod.rs:1495`（`pub lsp_collect: bool`，默认在建
  `Infer` 处 `:2276` 置 `true`）；三个 push 方法首行 `if !self.lsp_collect { return; }`
  （`elaboration.rs:482` / `:2828` / `:2840`）；bench 入口显式置 `false`
  （`mod.rs:5028` / `:5079` / `:5115`）。
- L13 孪生：`bump_spine_iter/machine.rs:523`（`observe: bool`，`new()` 里 `:585`
  默认 `true`）；prelude 装载段置 `false`（`entry.rs:1586`），用户段恢复
  （`:1601`）。
- **L06 现状**：无任何采集位——`Infer`（`mod.rs:166-179`）只有 meta / decls /
  mutable_map / meta_expanding；`Machine`（`bump_spine_iter/machine.rs:37-75`）
  只有工作栈、decl 表与可变全局。
- **承载面**：有。两版都是"每轮清空、结构稳定"的引擎对象，挂一个 `bool`
  不影响布局语义。
- **改造点**：默认值必须**反过来**（L06 的 `run` / `bench_check*` 口径不含渲染，
  任务要求"不开启采集时无回退"）。孪生侧的 `clear_round`（`machine.rs:189-197`）
  不清 `observe`，与 L13 同纪律。

### 1.2 登记面：`DeclEntry` 携带 span + `typ_pretty`（+ final 短路）

- **L06 现状**：
  - 参考版 `DeclEntry` = `{vt, va, prim, arity}`（`mod.rs:158-164`），插入点
    `elaboration.rs:204`（占位）/ `:221`（真值）/ `cxt.rs:192-194`（builtin）。
  - 孪生 `DeclEntryF` = `{vt, va, prim}`（`bump_spine_iter/prim.rs:65-69`），

  无 span 字段；`entry.rs:21-22` 与 `machine.rs:530-531` 注释明示"导出 span 全零"），

### 1.3 观察表与 push 方法

- L13 孪生表字段：`machine.rs:495-534`（`hover_table` / `completion_table` /
  `inlay_hint_table` / `println_spans` / `check_issue_lines` / `ctor_hover_memo`
  / `observe` / `failed_decls` / `accumulated_errors`）；方法在 `observe.rs`：
  `clear_observation_tables`（`:12`）、`push_hover`（`:26`）、
  `push_hover_cached`（`:54`）、`push_ctor_hover`（`:76`）、
  `push_inlay_hint`（`:103`）、`peel_pi_collect`（`:134`）、
  `push_qualified_hover`（`:165`）、`hover_entry_at`（`:189`）。
- L13 参考版对应：`push_hover`（`elaboration.rs:2827`）、`push_ctor_hover`
  （`:2839`）、`push_qualified_hover`（`:2858`）、`push_inlay_hint`（`:481`）、
  `peel_pi`（`:469`）、`hover_entry_at`（`mod.rs:1613`）。
- **L06 现状**：0 处。
- **逐方法判定**：

  | 方法 | L06 | 理由 / 证据 |
  |---|---|---|
  | `push_hover` | 可移植 | `Raw::Var`（`parser/syntax.rs:18`）与 `Decl::Def.name` 都带源码 span |
  | `push_hover_cached`（+ `typ_pretty_final` 短路） | 需改造 | 需要 #1.2 的登记面回填；短路语义可原样搬（"登记期无未解 meta ⇒ 串与使用处一致"） |
  | `push_inlay_hint` | 需改造 | 有承载面（def 无返回类型注解 / let 无类型注解），但 L06 的 `Raw::Hole` **不带 span**（`parser/syntax.rs:24`），锚点只能取 def 名尾 / binder 尾 |
  | `push_ctor_hover` | **不适用** | L06 无构造子、无 `match`：`Decl` 只有 `Def` / `Println`（`parser/syntax.rs:28-37`） |
  | `push_qualified_hover` | **不适用** | L06 无 `Raw::Obj`、无命名空间；`p_atom`（`parser/mod.rs:236-252`）不产生限定访问（lexer 有 `Dot` 但 parser 不消费） |

  `"…" : String` 的悬浮对 L06 是主要用途之一，故两版都在
  `Raw::LiteralIntro` 处推 `(字面量 span, 自身, "String")`。

### 1.4 println 两阶段

- L13 参考版：`defer_println` + `println_jobs`（`mod.rs:1531-1536`），生产于
  `elaboration.rs:1706-1714`，消费在 LSP 主循环（`lib.rs:1811`，把归一化推迟
  到诊断发布之后）。L13 孪生**不移植**该机制（`bump_spine_iter/machine.rs:3926`
  注释："立即 nf + pretty（参考版 run() 口径；defer_println 不移植）"），
  改为 `println_spans`（`machine.rs:502-504`，驱动在 `entry.rs:1542-1549`）。
- **L06 现状**：参考版 `run` 在循环里 `pretty::pretty_tm(0, cxt.names(), &infer.nf(...))`
  直接拼返回串（`mod.rs:435-438`）；孪生 `run_decls` 同款（`entry.rs:182-189`）。
- **结论**：`defer_println` / `println_jobs` **不适用**——L06 的 `run` 只有
  一个返回串消费方，没有"诊断先发布"的第二阶段可推迟。`println_spans`
  （span + 渲染串）**可移植**，span 从 AST 折叠（`Decl::Println(Raw)`，
  `Raw` 的叶子 span 见 `parser/syntax.rs:17-25`）。

### 1.5 失败 decl 通道

- L13 参考版：`failed_decls`（`mod.rs:1499-1505`）+ `note_failed_decl`
  （`:1629-1631`）/ `note_failed_names`（`:1636-1638`）/ `failed_decl_names`
  （`:1643-1659`，def/enum/trait/class 本名 + 构造子/`.mk` 限定键）；消费是把
  终态 `error name not in scope` 降级为"引用了上方失败的声明"（孪生
  `machine.rs:889-903` 的 `not_in_scope_err`）。
- L13 孪生：字段 `machine.rs:524-529`，`note_failed_decl` 在 `machine.rs:865-887`，
  由继续型驱动 `observe_user` 的 Err 分支填充（`entry.rs:1134` 起）。
- **L06 现状**：无。参考版 `run` 在第一个错误处 `?` 返回（`mod.rs:433`），
  `infer` 内部无 accrual；孪生 `elab_all` 同样 fail-fast（`machine.rs:1373-1381`）。
- **承载面**：记录面有（失败时驱动手里就有 `&Decl`，能取名字）；**降级消费面**
  没有——L06 没有继续型驱动，"下方 decl 引用上方失败名"这个场景在 fail-fast
  下不会出现（首错即终止）。
- **结论**：**需改造**——移植记录面（`failed_decls` + `note_failed_decl`）并配一个
  **opt-in 继续驱动**（用于观察/测试），但**不改错误文案**（L06 的错误串被
  blackbox 按判定锁定，且文案含 Debug span 偏移是既有偏差）。

### 1.6 求值预算

- L13：`L13_namespace/eval_budget.rs`（144 行）——`scope`/`scope_default`/
  `tick`/`checkpoint`/`is_timeout`/`ElabTimeout`/`NatChainOverflow`/
  `guard_nat_chain`/`NAT_CHAIN_LIMIT`；tick 点：参考版 eval 主循环
  （`mod.rs:3429-3431`）+ Nat 链构造（`:3923-3925`）；孪生 `eval_iter`
  （`bump_spine_iter/eval.rs:275/288`）+ `quote_nat_chain`（`quote.rs:622-624`）。
- **L06 现状**：无预算、无 tick；求值器结构：
  - 参考版 `eval` 是**递归**（`mod.rs:350-374`，逐节点一次调用）；
  - 孪生 `eval_iter` 是**迭代循环**（`eval.rs:125-331`，`work` 栈）；
  - 孪生 `force` 也是**迭代循环**（`eval.rs:38-71`），参考版 `force` 递归但带
    跨 meta 环守卫（`mod.rs:255-269`）。
- **可移植**：`scope`/`scope_default`/`tick`/`checkpoint`/`is_timeout`/`ElabTimeout`
  + 入口 `catch_unwind`。
- **不适用**：`NatChainOverflow` / `guard_nat_chain` / `NAT_CHAIN_LIMIT`——L06 没有
  原生 `Nat(k)`、没有 `Tm::SumCase`（`bump_spine_iter/syntax.rs:16-33`），
  没有任何"运行期 k 驱动的裸分配循环"：唯一的变长分配是字面量拼接
  （`prim.rs:119-137` / `cxt.rs:16-24`），其长度由源码字面量 + 输入规模界定。
- **改造点（比 L13 多）**：
  1. 参考版是递归 ⇒ 自旋不是"循环"而是无限递归，`tick` 只能挂在**每次 eval
     调用**上，并用更密的掩码（每 2^16 次 vs L13 的 2^20）以便在栈溢出前中止；
  2. 孪生 `eval_iter` 用循环局部计数器（L13 同款，零签名改动）；`force` 的
     **循环**也补 tick（L13 的 force 是递归，故它没补）——L06 孪生 force 展开
     已解 meta 时无环守卫，这是真实自旋点。

- L13 参考版：`format_check_warning`（`mod.rs:4633-4649`）、`take_check_issues`

### 1.8 常驻 prelude / arena 压实 / twin kick

- L13：`prime_resident`（`bump_spine_iter/entry.rs:898`）、`observe_user`
  （`:1134`）、`compact_state`（`bump_spine_iter/compact.rs`）、
  `run_decls_with_prelude`（`entry.rs:1566`）、prelude 装载段 `observe=false`

- **结论**：**不适用**。L13 的 `observe=false` 装载段总闸在 L06 没有承载面

### 1.9 `FORCE_MEMO`

- L13：`bump_spine_iter/force.rs:214-216` 的 thread_local `FORCE_MEMO`、
  `force_memo_clear()`（`:445`）、容量上限（`:297`）、压实后必须清（`entry.rs:1487`

- **L06 现状**：`grep -n "FORCE_MEMO" src/L06_string` **无命中**。两版 force
  都只展开已解 meta 链（参考版 `mod.rs:247-274`；孪生 `eval.rs:23-72`），
  decl 值不参与 force（`Tm::Decl` 求值时直接查表，`mod.rs:369-372` /
  `eval.rs:148-151`）。
- **结论**：**不适用**（`docs/l13-to-low-layer-port-audit.md` §"unify/force fuel"
  已对 fuel 下过同源结论，本条是它的 memo 版）。

### 1.10 双引擎 owned 快照契约

- L13 契约：`HoverEntry = (Span<()>, Span<()>, String)`（`mod.rs:1459`）；
  孪生 push 时 `quote → export → pretty` 成 owned 串（`observe.rs:26-45`），
  消费侧只 pretty、不再 quote live `Val`；`hover_entry_at` 取同 path 内含 offset
  的**最小 span**（`mod.rs:1613-1619` / `observe.rs:189-199`）。
- **L06 承载面**：完好。两版共用同一 parser AST，`Span` 原生带
  `start_offset`/`end_offset`/`path_id`（`parser_lib.rs:64-70`）与 `ToSpan`
  （`:171-180`）；两版的 println 渲染管线（`quote → [export] → pretty`）已被
  "Ok 输出逐字节一致"钉住（`tests/l06_blackbox*.rs`）。
- **降级点（必须登记）**：L06 的 `Raw::Hole` / `Raw::U` / `Raw::App` 不携带
  自己的 span（`parser/syntax.rs:16-26`），故：
  1. `raw_span` 需要按节点折叠（App = 函数头 span ∪ 实参 span）；
  2. **hole 位置无法定位**（`Raw::Hole` 是零字段变体）——inlay/hover 的锚点
     只能退到 def 名尾 / binder 尾；
  3. `App` 的 span 端点取 AST 里能拿到的最外叶子，与"真实 token 区间"可能差
     括号/运算符，仅影响定位精度，不影响渲染文本。
- **结论**：**可移植**（本任务的核心可移植项）。

### 2.2 公开入口（两版同名同义）

```rust
// 参考版（src/L06_string/mod.rs）
pub fn run_with_surface(input: &str, path_id: u32) -> Result<(String, LspSurface), Error>;
/// 按偏移采集（惰性 hover）：只渲染光标处命中的悬停条目（§3.4）。
pub fn run_with_surface_at(input: &str, path_id: u32, offset: usize) -> Result<(String, LspSurface), Error>;
pub fn check_with_surface(input: &str, path_id: u32) -> (Option<Error>, LspSurface);
pub fn run_with_surface_budget(input: &str, path_id: u32, ms: u64) -> Result<(String, LspSurface), Error>;
```

`run_with_surface` / `run_input_with_surface` 与既有 `run` / `run_input`
**同驱动、同输出**，差别只有"采集开着"与"返回快照"。失败 decl 通道
（`check_with_surface`）是 opt-in 的继续驱动：失败 decl 的名字记入
`failed_decls`，**错误文案不变**、`run` 路径不变。

### 2.3 采集关闭时的热路径

- 参考版：每次 push 调用点多一次 `if self.lsp_collect` 判定；`DeclEntry`
  多 `span` + `Option<String>` + `bool` 三个字段（插入时零渲染）。
- 孪生：同上 + `Machine.observe`；`binder_spans` 只在 `observe` 时 push。
- 预算：**只在有预算时打点**——入口用 `eval_budget::enabled()`（进程级 relaxed
  计数）快照成 `Infer.budget_on` / 循环入口的 `budget_on`，无预算时热循环里只剩
  一个恒假寄存器分支，连计数器自增都不付（L13 是无条件 tick，第 3 节有实测对比）。
  打点时有预算才做 `Instant::now()`（2^10 掩码，只有递归参考版需要这么密）。
### 2.4 偏差登记（实现中确认、必须写进契约的部分）

| # | 偏差 | 处理 |
|---|---|---|
| D1 | hover 串的 **fresh 后缀**（撇号）在两版间可能差一个：两版共用 `pretty::fresh`，但推串时刻的局部名字表快照不同——参考版在**使用处实时渲染**（`cxt.names()` 含当时的 λ/let binder），孪生对 `final` 的登记串**直取缓存**（登记期快照）。DEMO_SRC 全量 217 条 hover 里**恰好 1 条**（`x` vs `x'`），类型 alpha-等价（L13 记作"残余 fresh 后缀显示差异"）。 | `tests/l06_lsp_surface.rs` 的 `assert_surface_parity_impl(b, f, prime_allow)` 只豁免撇号差异，并把条数钉在 1（多一条即失败）。 |
| D2 | inlay 标签取**类型**而非值：L13 的 check-let 站点传 `vt`（值），与它自己 `` `: <type>` `` 的文档矛盾。 | L06 两版统一传类型（`va`），测试钉 `: String`。 |

| D4 | 失败 decl 通道**只记录**不降级：L06 的 `run` 是 fail-fast，没有 L13 `observe_user` 那种继续型驱动；错误文案被 blackbox 套件按判定锁定。 | 记录面随 opt-in `check_with_surface` 填充；错误文案一字不改。 |
| D5 | `Raw::Hole` / `Raw::U` 无源码 span（parser 的零字段变体）；`App` 只能折叠成叶子并集（可能不含括号）。 | 洞的 hover/inlay 锚点退到最近子树叶子 / 最近 binder 尾 / 0（已在 `surface::raw_span` 与两版 push 点注释）；定位精度差异不影响渲染文本。 |
| D6 | `completion` 恒空：L06 无成员访问（`Raw` 无 `Obj`，parser 不消费 `.`）。 | 表字段保留（与 L13 三表契约同型），恒空并在测试里钉住。 |
| D7 | 孪生仍为每个 `def`（与 builtin）加 define 槽（参考版只登记 decl 表，bb3129cc 的载体切换只落在参考版），于是顶层 `cxt.lvl` 在两版差常数项。 | ① 洞 inlay 锚点改用 `Machine::decl_base_lvl`（`infer_decl` 入口刷新），等价参考版 `lvl > 0`；② **显示名字表**不再收顶层 def/builtin（`define_name(display=false)`）——这是 §3.4 那个 O(n²) 的根因修复；`env`/`name_map` 的 define 槽保持原样（基线性能不受影响）。 |
| D8 | 求值预算的**能力边界**：参考版 `eval` 是递归的，`def loop (x : U) : U = loop x` 的发散表现为栈耗尽（2 MiB 测试线程 ~7k 帧，远早于 20ms 预算）；L13 的 `NatChainOverflow` 是同族限制的另一个实例。 | 预算按生产口径（主线程 64 MiB）验证可中止，测试显式开 64 MiB 线程复现；测试线程默认栈下会先爆栈这一事实写进报告。 |

### 3.3 求值预算：成本归因与能力边界

**归因（消融构建）**：把三处 `eval_budget::tick` 全部注掉后重建（其余改动保持），
同一台机器单轮实测：

| 负载 k=13 fast_ss | 基线 | 注掉 tick 的构建 | 保留 tick 的构建 |
|---|---|---|---|
| church | 0.798 | 0.801 | 0.836 |
| strchain | 21.35 | 21.31 | 23.63 |
| prune | 132.6 | 134.5 | 136.6 |
| implicit | 16.64 | 16.82 | 16.36 |

⇒ tick 是唯一可见的回退源（church +4.8%、strchain +10.7% 的那一轮），注掉即回到
基线 1% 内。据此做了两处收敛（已在上表 3.2 生效）：

1. **只在有预算时打点**：参考版 `Infer.budget_on` 在入口 `eval_budget::enabled()`
   一次快照；孪生两个循环（`eval_iter` / `force`）在循环入口读一次 `budget_on`，
   循环体内只剩 `if budget_on { tick }`（无预算时是恒假寄存器分支）。
2. `enabled()` 用**进程级 relaxed 计数**而不是 TLS（每个 eval/force 入口都要读一次，
   本机 TLS 访问 1~2ns × 十万级入口就是 2~3%）。

残余 +3~5% 是"每个循环入口一次原子读 + 每次迭代一个可预测分支"的下限。要再压
只能把 tick 单态化掉（`eval_iter::<TICK: bool>` 两套代码）或把打点移到更稀疏的
点（`decl_apply`）；本轮判为不值当，登记为后续可选优化。

**能力边界（L06 与 L13 的差异）**：L13 的求值器是迭代的（自旋不涨栈），时间预算
足够；L06 参考版 `eval` 是**递归**的，`def loop (x : U) : U = loop x` 的发散表现为
**栈耗尽**（本机 2 MiB 测试线程约 7k 帧就爆），时间预算来不及。生产口径（LSP/CLI
主线程 64 MiB 栈，见 `.cargo/config.toml`）下预算能中止，`tests/l06_lsp_surface.rs`
的 `eval_budget_stops_divergent_recursion` 因此显式在 64 MiB 线程里验证；孪生
（迭代）在同一测试里直接验证。这与 L13 `NatChainOverflow` 是同一族限制：
**时间预算拦不住栈/单步分配**。

### 3.4 采集开启：一次真 O(n²) 的根因与修复

**现象**：`l06bench --observe`（与关闭采集同一调用口径）在 4096 层的合成链上
把 3~6 ms 的负载推到近 1 s：

| 负载 k=11 | 关闭采集 fast_ss | 采集开启（修复前） | 倍数 |
|---|---|---|---|
| church | 0.241 ms | 0.350 ms | 1.5× |
| solve | 0.296 ms | 1.81 ms | 6.1× |
| implicit | 4.19 ms | 887 ms | 212× |
| strchain | 3.69 ms | 944 ms | 256× |
| global | 5.90 ms | 1018 ms | 172× |
| prune | 49.0 ms | 9372 ms | 191× |

规模律 k=9→k=11（规模 ×4）：implicit 57.8 → 887 ms（15.3×）、strchain
49.4 → 944 ms（19.1×）⇒ 二次。

**根因（不是"渲染本身贵"，是记账 bug）**：孪生的每个采集 push 点都调用
`pretty_tm(0, types_names_list(cxt.types), …)`，而 `types_names_list` **每次
重建整张显示名字表**；孪生的 `define_name` 又把**每个顶层 def**（以及
`Cxt::new` 的 9 个 builtin）压进了 `cxt.types`。于是名字表长度随 decl 数 D
线性增长、push 点数也是 O(D) ⇒ O(D²)。

参考版没有这个问题：它的 `Cxt::new` / `add_builtin` / Def 臂都**只登记 decl
表**（bb3129cc 的载体切换），`cxt.names()` 只走 λ/let 的 `Locals`，所以参考版
采集开销只有 ~3×（16.3 vs 5.5 ms），孪生是 264×。旁证：DEMO_SRC 上唯一那条
hover 撇号差异也来自同一处记账差（参考版在使用处实时渲染、孪生复用登记期串，
名字表快照不同）。

**修复**：孪生 `define_name` 增 `display: bool`——顶层 `def` 与 builtin 传
`false`（照旧写 `name_map` / `env` / `binder_spans`，只是不进 `cxt.types`），
let-define 传 `true`（参考版 `Locals::Define` 会进名字表）。语义对齐一行，
Ok 输出不变（显示名字表变小只影响 pretty 的 fresh 后缀规避，与参考版一致；
门禁 51/34/94/532/24/36 全绿）。

**修复后**（k=11，同口径）：

| 负载 | 关闭采集 | 采集开启（修复后） | 倍数 | 修复前 → 后 |
|---|---|---|---|---|
| church | 0.217 ms | 0.279 ms | 1.3× | 0.350 → 0.279 |
| solve | 0.298 ms | 1.88 ms | 6.3× | 1.81 → 1.88 |
| implicit | 4.06 ms | 20.1 ms | 5.0× | 887 → **20.1** |
| strchain | 3.89 ms | 12.6 ms | 3.2× | 944 → **12.6** |
| global | 6.61 ms | 21.5 ms | 3.3× | 1018 → **21.5** |
| prune | 49.7 ms | 102.9 ms | 2.1× | 9372 → **102.9** |

采集开销从 172~322× 收敛到 1.3~6.3×，量级与参考版（`basic_obs`：
0.09 / 4.7 / 15.6 / 14.4 / 24.4 / 148 ms）相当。剩下的是"每个 push 点做一次
quote+pretty"的**线性**成本，仍有收敛空间。

**已落地第一档：按偏移采集（惰性 hover）** —— `L06_string::run_with_surface_at(
input, path_id, offset)`（孪生 `Tycker::{run_input_with_surface_at,
run_decls_with_surface_at}`；bench `--observe --observe-at`）。口径：push 点只做
O(1) 的 `span.contains(offset)` 判定，只有光标处命中（通常 0~1 条）才渲染；def
登记串也按"光标是否落在 def 名上"决定渲染与否。inlay / println / check issue
仍全量（全文件消费）。输出串与全量采集的同一条逐字节相同（同一渲染管线、同一
站点上下文；`tests/l06_lsp_surface.rs` 的 `hover_query_*` 两例钉住）。

同口径实测（k=11、rounds=3、同一进程同一 AST 热度，三行同场）：

| 负载 | fast_ss（无采集） | fast_obs（全量） | **fast_obs_at（按偏移）** |
|---|---|---|---|
| church | 0.211 ms | 0.269（1.27×） | **0.211（1.00×）** |
| solve | 0.280 ms | 1.448（5.2×） | **0.279（1.00×）** |
| implicit | 3.85 ms | 17.38（4.5×） | **3.85（1.00×）** |
| strchain | 2.44 ms | 11.74（4.8×） | **2.68（1.10×）** |
| global | 5.07 ms | 20.23（4.0×） | **5.60（1.10×）** |
| prune | 33.2 ms | 92.12（2.8×） | 42.6（1.28×） |

⇒ 悬停采集成本降到噪声级。prune 剩余的 1.28× 来自 **inlay**（全文件通道：每个
洞/无注解 let/无返回类型 def 各渲染一次类型），是下一档的目标。

**还能怎么降（按收益/风险排序，未实现）**：

1. **inlay 惰性化 / 加开关**：inlay 是 prune 剩余 1.28× 的来源；LSP 侧可以只在
   可见区请求 inlay，或先判长度再渲染（L13 的 80 字符截断发生在渲染之后）；
2. **按 decl 键缓存渲染串**（L13 `ctor_hover_memo` 同思路）：命中同一 decl 的
   多条使用处复用（现在只有"登记期 final ⇒ 使用处直取"这一条短路）；
3. **名字表增量维护**：`types_names_list` 每次重建 `List<String>`，可随 binder
   栈推进/回退增量维护（深 λ 嵌套负载）。

### 3.5 结论

1. **可以学**：L13 的 LSP **引擎侧**机制在 L06 都有承载面——观察面 owned 快照契约、
   登记面（span + 渲染串 + final 短路）、求值预算、失败 decl 记录、check issue 通道，
   本轮已全部落到两版并保持"Ok 输出逐字节一致 / 判定不变"。
2. **不能学（无承载面）**：构造子/限定名 hover、completion、常驻 prelude + arena 压实、
   `FORCE_MEMO`、`NatChainOverflow`——L06 没有 enum/成员访问/命名空间/prelude，
   force 也不展开 decl 值。
3. **性能**：默认（采集关闭）无可见回退，观测面零成本；求值预算的 tick 在 eval
   密集链上最坏 +4~5%，已从最初的 +10% 收敛（只在有预算时打点 + 非 TLS 开关），
   并给出进一步单态化的选项。
4. **采集开启**：曾有一处真 O(n²)（孪生把顶层 def/builtin 压进显示名字表、每个
   push 点重建整表），已修（`define_name(display=false)`）：4096 层合成链上
   从 172~322× 降到 1.3~6.3×（与参考版同量级）。再把 hover 改成**按偏移采集**
   （`run_with_surface_at`，已落地）后，悬停采集成本降到噪声级（1.00~1.10×；
   prune 1.28×，剩余是 inlay 全文件渲染）——这就是 LSP 一次 hover 请求的真实
   口径。
