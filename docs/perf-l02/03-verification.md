### 3.2 确定性旁证与算术

| 口径 | BASE raw | C1 raw | Δ |
|---|---|---|---|
| church `fast(one-shot)` | 228 / 5 224 576 B | 228 / 5 215 872 B | **+0 / −8 704** |
| church `fast_ss churn` | 221 / 1 962 821 B | 221 / 1 954 117 B | **+0 / −8 704** |
| conv `fast(one-shot)` | 304 / 10 498 376 B | 304 / 10 486 280 B | **+0 / −12 096** |
| conv `fast_ss churn` | 295 / 49 528 B | 295 / 37 432 B | **+0 / −12 096** |

- 算术核对：**16 × 544 = 8 704 ✓、16 × 756 = 12 096 ✓**；`−8704/16 = 544`、`−12096/16 = 756`。
  但这是**同义反复**：`544 = 8704/16`、`756 = 12096/16`，raw 中没有任何地方报告 544/756。
- raw **能**支持的机制证据是 `small-alloc top (fast)` 直方图：church 的 `size 160 × 196`
  在 C1 变成 `size 160 × 78 + size 96 × 118`（78+118=196，allocs 守恒）；conv 的
  `size 160 × 281` 变成 `size 160 × 114 + size 96 × 167`（114+167=281）。
  这正是 `Vec<W>` 元素 40 B→24 B 后容量 4 的块 160 B→96 B 的尺寸类迁移。
- 注意 118×64 = 7 552 ≠ 8 704，conv 167×64 = 10 688 ≠ 12 096：**仅凭 top-6 直方图无法
  精确重构 −8704/−12096**，还有 top-6 之外的尺寸类（如 320→192）。所以 02 §13 的
  "减少量恰好等于所有 `Vec<W>` 扩容所承载的元素数 × 每个元素少的 16 B" 是**过度精确的
  再解释**，应降级为："bytes 精确下降 8 704/12 096 且 allocs 不变；直方图显示 160→96
  （conv 另有 320→192）尺寸类迁移，与 `W` 变窄一致。"

## 4. 配对统计量审计

### 4.1 定义与实现（独立实现复算）

- 定义 `md = median_i (B_i−A_i)/A_i ×100%`，配对 bootstrap 重采样 pair；地板 =
  同批 null 段该统计量的 bootstrap p95（再与 0.5% 下限取 max）。
- 我用**从零写的**实现（`raw/verify-analyze.py`，不 import 他们的分析器）复算：
  C2 四格、C1 四格、E1–E5、A/A' 全部与 02 逐字一致（见 §1/§2/§3 及
  `raw/verify_02_recompute.txt`），说明**定义与实现没有错**。
- 我另加一个**正交的正式检验**（精确符号检验，`raw/verify_signtest.txt`）：C2 四格
  p ≤ 7e-5、E4 三格 p ≤ 1.5e-3、E5 不显著——与配对判定完全同向。**配对统计量本身成立。**

### 4.2 "配对消掉批内共模漂移"的论证

成立，且有直接证据：C2 原批 nullA 段中位 0.99 ms（2.36 GHz 平台）而 ab/nullB 2.06–2.24 ms
（0.92 GHz 平台），**非配对地板被抬到 52–55%**（我复算 nullB 非配对 p95 = 55.958/52.388），
而**同批配对地板只有 0.63–1.38%**；E1 的 nullB 段 unpaired −7.23% 而 paired −0.19%。
同一个批里两种统计量差两个数量级，正是共模漂移被配对消掉的直观证明。
另：交错性我用 `freqs.tsv` 的 order 列与 mtime 独立确认，不是采信驱动自报。

### 4.3 两点限制（不影响 C2 判定，但应写进方法学）

1. **bootstrap p95 地板本身有种子噪声**：在刀锋格上它只取少数几个离散值。
   例：E2 nullA k11 的 21 个配对差含 2 个 ≈+20%、2 个 ≈−17%，30 个种子的 p95 ∈ {0.329, 0.548}
   （中位 0.548）；E1 nullA k15 我算 0.689、02 算 1.121。**§2.3 的逐格地板是单种子点值，
   不应被逐字引用**；对 1–6% 效应应保留 ≥0.2–0.4 pp 的余量。C2 的效应（5.7–7.7%）离地板
   有 4–10 倍余量，不受影响。
2. **"地板 = bootstrap p95" 是启发式而非正式检验**；建议最终报告同时给出精确符号检验
   （或配对随机化检验）作正交证据。本次已给出（§4.1），结论一致。
3. 我最初还跑了"配对中位数的符号翻转置换检验"，它在 E4 k11 给出 p=0.21——这是
   **该检验对"幅度不对称 + 时间量化"的刀锋分布不适用**（18/21 为正，精确符号检验
   p=1.5e-3）。最终判定以**符号检验**为准，特此记录以免误读。

## 10. 哪些结论可以写进最终报告、哪些必须降级

**可以直接写进最终报告（证据充分）**

1. **C2「β/let 尾任务寄存器化」在 church/conv 上稳定加速 ~6%**（原批 −5.70 ~ −7.42%，
   我的独立重跑 −5.60 ~ −7.71%；四格配对判定 + 符号检验 p ≤ 7e-5；同频平台、前后半、
   首位顺序、频率分布、跨树五重排伪影全部通过）。这是本轮**唯一**判定成立的新码优化。
2. **C1「`W` 40B→24B」没有可测收益**：k=13/15 四格全部未判定（±0.5% 内），
   k=9..15 全扫描无正向收益；确定性证据只证明"补丁生效"（allocs 不变、bytes 精确下降、
   160→96 尺寸类迁移），**不能**当时间收益。方向性证据（church k13 符号检验偏向"略慢"）
   也不支持收益。
3. **消融分解**：conv 上 `NO_BITEQ`（位相等 + 链内环 4 个决策点**联合**）= 2.02–2.22×；
   conv_dup 上 `NO_CONV_MEMO` = 1.48–1.49×；conv 上 `NO_CONV_MEMO` 未判定；
   church 上 `NO_BITEQ` 非中性（1.8–4.6%，k11/k13 强、k15 弱）。
4. **方法学**：同批严格交错 + 配对相对差 + 同批 null 配对地板是这台机器上唯一可用的
   1–6% 判定形态；非配对/blocked 地板（52–55% / ~19%）只能作对照。
5. **跨树/跨次构建混杂 ≈0.1%**，不能解释 C2 的 6%。
6. **预注册先于取数**，无事后换指标。

**必须降级 / 改写后才可引用**

1. "−8704 = 16 B × 544、−12096 = 16 B × 756" → 改为描述性（bytes 精确下降 + 尺寸类迁移）。
2. "推翻 readme 的 church 中性" → "本机不成立（1.8–4.6%，k15 余量薄）"。
3. `02 §2.3` 逐格 null 地板 → 标注单种子 bootstrap 噪声（±0.2–0.4 pp），
   不要把它当可逐字复现的常数。
4. `C2 §12.1` 的降频叙述 → 补上 nullA 段在 2.36 GHz 的事实。
5. `C1` 的 "四个格" → 明确是预注册判定格 k=13/15；k9/k10 的 `判定(+)` 不得引用为任何方向。
6. E1/E2/E3 的判定 → 注明固定 A-first 顺序，E2 视为"同批 null 控下判定、协议弱于交替版"。
7. 影子二进制 ↔ 补丁的**重建级**一致性 → 标"未做"，只给间接证据。
