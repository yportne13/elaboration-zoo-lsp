# L13 性能版性能与内存深挖轮（2026-09-22）——六个并行分析 + 七项落地

## 0. 本轮的定位

对 L13 性能孪生（`bump_spine_iter`）做一次**并行归因 + 落地**轮：6 个子 agent
分别负责（1）采样剖析、（2）内存分配归因、（3）孪生核热路径读码、（4）参
考版与共享设施读码、（5）测试套件计时、（6）LSP 真实负载。所有发现交叉验
证后落地 7 项修改，全部有门禁背书。口径：l13bench（时间，nf 两版互检）、
l06l13mem（确定性分配计数）、release + fat-LTO，机器同前几篇文档。

**内存（l06l13mem，k=11，确定性分配计数口径）**：分配计数与字节数基本持平

是计数盲区。**时间收益 +24~50% 与内存计数持平并存是本轮的预期形态**，不是
矛盾。

## 2. 落地项（全部在 `bump_spine_iter.rs`，除注明）

1. **`declb_of` 单条目缓存**（`TWIN_DECLB_CACHE`，参考版 `DECLB_CACHE`
   同款移植）：Match/Match unify、quote、rename 每碰一对 Match 值就重建整
   张 decl 存根表（O(D) 键克隆 + 每条目 2 次 bump 分配）；adder_proof 这类
   Match/Match 密集证明每 decl 数千次。键 = (decl 表地址, len)——decl 表是
   COW `Rc`，make_mut 重分配换地址即自然 miss；(addr, len) 双键挡同轮
   free→realloc 同址 ABA。**失效纪律挂在 `force_memo_clear()`**——它是每个
   `bump.reset()` 轮入口的唯一汇聚点（bench/run/prelude/kick 均配对调用）。
   附加收益：缓存命中后同名 Decl 存根轮内共享，位相等捷径恢复命中。
2. **quote 的 `Nat` 类型项缓存**（`QUOTE_NAT_TM`）：`XCell::Nat(k)` quote
   每次嵌套 quote 一遍闭合的 Nat Sum 值（轮内恒定）+ 两个新草稿栈；键 =
   Nat 值打包字，轮界同上清。
3. **`stuck_decl` 裸 Decl 存根 intern**（`STUCK_DECL_INTERN`）：旧实现每次
   卡住新造单元，同名基座地址永不同——位相等捷径（`t.0 == u.0`）与
   conv.memo 键系统性 miss（自证注释在原 ：4477-4486）；intern 后共享（值
   不可变，共享即等价）。轮界同上清。
4. **`solve_trait_ref` 双 force 消除**：`all_params`（:7165）与
   `forced_params`（:7259）之间只有纯过滤（val_match/is_flex/head_key_v 全
   只读），第二遍 `force_list` 是纯重复——删。
5. **Call/Call 带 Flex 的三重快照 → META_JOURNAL**：旧实现每次整表
   `metas.clone()`（万条级 ≈1.1MB memcpy + 几万 Rc 计数）+ trait_metas
   clone，且 `constraints.clone()` 快照从未被读取（**死克隆**）。改 journal
   帧 + trait_metas truncate（trait_wrap / run_pure_probe 同款先例；审计确
   认全部 9 处 meta 就地写都走 `journal_meta`、trait_metas 只 push）。
6. **Def 检查 Nat 默认化重试的整表 clone → journal**（:9894）：同上形态，
   `saved_meta = metas.clone()` + 失败整体搬回 → journal 帧成功 discard /
   失败 rollback。新增 `meta_journal_discard()` 与 rollback 成对（成功出帧
   保留、失败出帧回滚）。
7. **参考版 bench 口径修复**（`mod.rs`）：`bench_check_nf_bounded` /
   `bench_check_first_err_bounded` 入口补 `force_memo_clear()`——孪生入口
   早有，参考版漏了。memo 键是值指针且条目持 Rc keepalive，跨轮指针不复
   用：不清则表只涨不中，CAP 1M 后每 force 付死表 miss。这是 basic 列的
   测谎偏差修复（struct k=11 basic −19%、prelude-core −30% 即来源于此）。
8. 小项：vapp1 两处 Decl 臂双 `decl.get` 合一；force_inner 两个 prim 执行
   臂的 w2/v2/i2 临时 Vec 改复用主栈（Vec::new 不分配但省三份栈管理）；
   **工具**：l13bench `--file` 加 `--with-prelude core|hdl`（旧实现不带
   prelude 也不注册 nat 内建，依赖 prelude 的真实示例两版都在 decl 1 失败，
   示例级互检不可用——adder_proof 实测确认并已可用）。

## 3. 六路分析的关键发现（未落地部分按收益排序存档）

### 3.1 已验证、暂不落地

- **观察面成本口径**（内存路实测确认）：prelude-core observe 开/关 =
  111,584/27.51MB vs 52,681/22.94MB（allocs +112%/bytes +20%），时间口径
  ≈36%（NOBSERVE A/B）。但 LSP 生产路径在 prelude 装载段已显式
  `observe=false`（`prime_resident` / `run_decls_with_prelude`）——**纯
  bench 假象，非 LSP 成本**；用户段观察面是产品面。采样路建议的「按请求
  类型延迟渲染」是真实机会（pcore 级文件键击路径 ~1/3），涉及 LSP 消费侧
  改造，单独立项。
- **decl 表 + 后缀索引每轮全量重建**（mem-l13-opt §3.2）：量化为 ≤10%
  churn（church churn 每轮 9.5k allocs 上限），LSP 常驻口径已是增量——
  **不值得做**，归档。
- **第一/二组 14 张表归还档**（§3.3）：读码确认存在（`clear_round`
  `:6109` 逐行核对），收益只在长会话 RSS（数十 KB~MB，仅 prelude-hdl 形
  态），分配计数零变化。机械改动，下次顺手。

### 3.2 孪生侧剩余机会（按收益×置信度）

1. **trait_wrap 二次正规化**（`trait_wrap` 入口 `eval(quote(a))` + 逐
   namespace 条目快照回滚探测）：prelude-hdl 采样 18% 样本两帧内有它——
   phdl 最大单项。perf-review-4 §4-P1 已列，孪生侧未落地。
2. **probe_accessible 每构造子 infer_expr+unify 探测**（pcore/exhdl 采样
   ~11%）：同 (Sum, ctor) 轮内不变却每次重推，可按 (sum, ctor) 缓存。
3. **eval_aux 运行时双遍线性扫 + 每子模式 1 元 arms1 bump 分配**（编译后
   执行分派）：大 enum 匹配负载可建 constr_idx 索引。
4. **嵌套 unify 清父层 conv.memo**（`unify_iter` 入口无条件 reclaim）+
   Call/Call 子 unify 每次新建 ConvScratch——memo 命中窗口被嵌套切断，
   需「成功单调」论证后共享。
5. **force_inner 内部递归走完整 memo wrapper**（round-13 结论契约已是规范
   WHNF，可本地 `continue` 短路）；待 §2.1/§2.3 落地后「调用约定」份额需
   重新归因再决定是否继续。

### 3.3 参考版/共享侧剩余机会

1. **参考版移植后缀倒排索引**（`elaboration.rs:2392-2456` 每 miss 全表
   `ends_with` 扫描 + 每 miss 重建 ns 方法键 HashSet + 命中克隆 7 元组）：
   孪生三件套已证 ~秒级收益，参考版 prelude-hdl 3.3s 的主要结构性差距。
2. **afe6a92 收尾**：class/impl/module 臂 5 处仍走 `&Cxt` 薄壳（每嵌套方
   法登记一次 O(表长) 深拷）。
3. **参考版每 def 双渲染合一**（`push_hover` quote+pretty 与 `vtyp_pretty`
   **nf**+pretty 各一遍；孪生已合并）。

### 3.4 测试基础设施（测试路实测）

- **409 个 lib 测试在 parity 二进制里重复编译+执行**（423 = 409 重复 + 14
  本体）：门禁成本 44%（~35s/次）。零代码改法：`--lib L13_namespace::` +
  `--test l13_fast_parity -- --skip "L13_namespace::"`。
- 慢测试 Top：`legacy_tests::test_examples_hdl_dir` 12-22s（每示例深克隆
  整个 prelude 状态）、observation_tests 三个 fresh-replay 12.3/8.5/7.4s、
  `module_probe_tests::probe_timing` 3.9-5.3s（还写 probe-out.txt，应
  `#[ignore]`）。
- **fat-LTO 重链接悬崖**：任何 L13 源改动触发全部 60 个二进制重链
  （增量 ~10-12 分钟，且 Windows 上遗留 exe 进程锁产物）；门禁可用
  `cargo test --release --lib --tests` 跳过 15 个 `[[bin]]`。
- **`cargo test --lib l13`（小写）静默跑 0 个测试**——过滤器大小写敏感，
  现有文档/CI 若用小写过滤词则 L13 lib 面实际无门禁（必须写
  `L13_namespace`）。

### 3.5 LSP 真实负载（LSP 路实测）

- **`typort check` 不走孪生**：`run_check` → `on_change` 纯参考版管线；
  `TYPORT_LSP_ENGINE=twin` 时 CLI 白付 ~2.1s prime。CLI 变成孪生真实测量
  窗口前，任何「CLI 端到端双引擎对比」的结论都要打折扣（本轮已规避）。
- adder_proof 的 0.23x 是 **LSP per-kick 稳态口径**（FUNC_PROF 已归因调用
  约定非多干活），l13bench --file 此前测不了它（§2.8 工具修复后可测部分
  运行段：159 decls basic 20.0ms / fast 9.2ms，两版一致失败于已知语义缺
  口——nf 口径不适用，kick 口径仍需 LSP 侧量）。
- 未验证错误类回落仍双跑（18-utils 形态）：粘性降级（0ee20bf）可同款推
  广到 untrusted-error 路径。
- 诊断发布挂在请求边界（空闲打字延迟一个 RTT）+ 孪生 kick 照付非 MUT 全
  套 Infer+Cxt clone。

### 3.6 采样器缺口（下轮工具改造）

入口 tick 式采样给出的是「入口调用频度 × 调用链」而非墙钟 self%：church
类归一化负载（时间全在未插桩的 eval/quote/force/spine 内核）结构性不可见
（k=12 仅 1 样本）。tick 应补挂 quote/tm_size/force/v_app/spine 内核，
归因需与 FUNC_PROF 计数交叉验证。另：release exe 的 PDB 不被 std
backtrace 解析（l06l13mem 栈归因此轮不可用），归因改用 k 倍增比例法+
尺寸算术+读码三重约束。
