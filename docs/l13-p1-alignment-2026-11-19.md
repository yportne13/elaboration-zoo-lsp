## S1（P1.3b）flex_flex 反向重试（L12 review R9）

### 动机

`flex_flex` 只按 spine 长度选一个方向试一次，失败即放弃。当“长 spine 含非
rigid 项（变量槽已被精化成构造子值）”时，该方向的 invert 不可行，而另一方向
其实可解——L12 语料里的 test5（内层 match）即此形态。L12 review R9 还指出：
第一次尝试失败时可能已 solve 部分 meta，必须回滚；且失败分档存放在
`Infer` 的 `Cell` 上，**不在** meta 快照内，若不恢复水位，首次尝试的
`Undecided`/`Fuel` 会单调残留，把反向重试后的真 `Absurd` 误报成“无法判定”。

### 改动清单

`src/L13_namespace/unification.rs`（参考版）

- `go` 闭包改为显式接收 `this: &mut Self`（对齐 L12 形态），以便在两次调用
  之间访问 `self.meta` / `self.unify_kind` 而不与闭包的可变借用冲突；
- 方向选择保持不变（`sp.len() < sp_prime.len()` → `(m', sp')` 先；相等/更长
  → `(m, sp)` 先，与 L12 `<=` 口径等价）；
- 首次尝试前取 `self.meta.clone()` 与 `unify_kind()` 水位；失败后
  `self.meta = snap; self.unify_kind.set(kind_before)`，再反向重试一次；
- 失败返回值取反向尝试的结果（首次失败的错误被覆盖）。

`src/L13_namespace/bump_spine_iter/unify.rs`（孪生，bool 无三档）

- `flex_flex_bump` 在首次方向前 `metas.clone()`；首选方向整体失败（invert +
  solve / 常数解 fallback + trait 合成任一环节失败）后 `*metas = snap` 再反向；
- 反方向的 `None` 分支对另一侧 meta 跑 `solve_bump` + `solve_multi_trait_ref`
  （与正方向 `go` 逐字对位，只是侧别互换）；
- 首方向成功路径不变（不复制/不恢复快照）。

### 与 L12 的偏差

1. 参考版只恢复 `meta` 与 `unify_kind` 水位，不恢复 `match_cmp_budget`——
   与 L12 R9 的实现一致（L12 亦只恢复这两项）；预算残留的影响面留待后续
   若出现“反向重试被预算误杀”的实证再评估。
2. 孪生用整表 `metas.clone()` 快照，与 L12 孪生同口径（孪生侧无 undo-log
   水位可用；`journal_meta` 只在帧打开时记录，不覆盖所有路径，不能替代）。
3. 参考版 `go` 的 Err 臂在反向尝试前会留下 `solve_multi_trait` / 约束挂账等
   非 meta 副作用，L12 同样不清理；本包只对齐 L12 的已验证口径，不额外扩大
   回滚面。

### 行为归因

两套全量门禁（615 / 630）与定向用例结果均与基线逐项一致，**没有出现**
Err→Ok 的用例。即 R9 的反向重试在当前 L13/twin 语料上未改变可观察结论，
属“机制对齐、oracle 不变”；孪生侧同步改动后 `l13_fast_parity` 无分叉。
若后续新增语料触发 Err→Ok，须按“先判断是修好了还是放过头了”逐条归因，
再决定是否保留。

## S3（P1.2）覆盖探测三态（Walk::Undecided）

### 动机

L13 的构造子可达性探测返回 `bool`：`probe_accessible` 把“索引方程失败”
一律当不可达，覆盖检查与臂前置过滤只能看到两种结局。L12 已把臂走查拆成
`Walk { Matched, Unreachable, Undecided }`，并在 `compile` 里对第三态给
“无法判定”诊断。L13 需要同样的机制位：**把“判不出”从“矛盾”里分出来**，
接到覆盖检查（不产生覆盖义务）与臂诊断（独立变体）上。

### 改动清单（`src/L13_namespace/pattern_match.rs`）

1. 新增三态 `enum Walk { Matched, Unreachable, Undecided }`（命名对齐
   L12 `Walk` 的第三态）。
2. `probe_accessible` / `ctor_accessible` 的返回与 memo 从 `bool` /
   `Option<bool>` 改为 `Walk` / `Option<Walk>`；映射口径：
   - 索引方程 `Ok` → `Matched`；
   - `Err(UnifyKind::Fuel)`（预算耗尽）→ `Matched`（保守要求覆盖）；
   - `Err(UnifyKind::Absurd)` → `Unreachable`；
   - `Err(UnifyKind::Undecided)`（rename/invert/solve、卡住 match 等
     语义判不出）→ `Undecided`；
   - 无参 Sum 短路 / 形状不合约 / 构造子解析失败沿用既有结论
     （`Matched` / `Unreachable`）。
3. 覆盖检查：缺构造子只在 `Walk::Matched` 时产生 `Unmatched`；
   `Unreachable` 与 `Undecided` 都不要求覆盖（结论与旧 bool 口径一致）。
4. 嵌套覆盖（`nested_checks` 两段式，未重写）：字段构造子只在
   `Walk::Matched` 时计入覆盖义务；第三态同样跳过。
5. 臂前置过滤：`Matched` 继续走查；`Undecided` 压
   `Warning::Undecided(body)`，`Unreachable` 压 `Warning::Unreachable(body)`。
   新增变体的 `Display` **暂与 `Unreachable` 同形**
   （`unreachable pattern: …`）——见下节偏差。

### 与 L12 的偏差（载体约束 / oracle 优先）

1. **覆盖结论不变**：L12 对任意非 `Absurd` 失败都按“可达”保守要求覆盖；
   L13 的 `update_cxt` 精化载体下，臂上下文可能解出探测期判不出的索引
   方程，产品 oracle（`l13_fast_parity` 的 GADT 函数索引用例
   `W (n => n)`）一直把这类臂按不可达过滤。本包只让 `Fuel` 按可达处理，
   `Undecided` 保持不可达结论——与 `docs/l13-p1-alignment-2026-11-18.md`
   §3.1 一致。
2. **诊断文案冻结**：`l13_fast_parity` 对 `Err` 正文做逐字（归一化后）
   比对；孪生侧只有 bool 探测、无 `UnifyKind` 三档（L12 孪生同款）。
   若参考版单独把 `Undecided` 臂的文案改成“无法判定”，W 用例会
   ref/twin 分叉。因此本包只把第三态落到**变体/结构**上，文案留待
   S4（孪生三档）一并放行；`Warning::Undecided` 的存在本身已让
   `compile`/后续消费者可区分两档，不需要解析字符串。
3. 未重写嵌套覆盖两段式（任务硬要求）：`pending_pos` / `nested_checks`
   原样保留，只把消费端的 `bool` 判定换成 `Walk == Matched`。

做 `compact_state`（与产品 `prime_resident` 同纪律）。旧口径的 18.4 ms 是"不压实
换来的"，代价是峰值 RSS 2.4 GB；新口径付 ~29 ms 换回产品级内存形状。
需要旧口径可用 `TYPORT_TWIN_NO_COMPACT=1` 对照。

**结论 3：C 的参考版 +2–4% 来自 bench 二进制自身**（计数分配器的每分配原子读、
`[NF-SLOW]` 探针），不是产品代码；探针已改为只读 `FUNC_PROF.enabled` 原子位。

> 教训：bench 数字变化先问"口径变了吗"。本轮两次"性能/内存异常"最终都是口径，
不是产品回归。
