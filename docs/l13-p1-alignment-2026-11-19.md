## S1（P1.3b）flex_flex 反向重试（L12 review R9）

### 动机

`flex_flex` 只按 spine 长度选一个方向试一次，失败即放弃。当“长 spine 含非
rigid 项（变量槽已被精化成构造子值）”时，该方向的 invert 不可行，而另一方向
其实可解——L12 语料里的 test5（内层 match）即此形态。L12 review R9 还指出：
第一次尝试失败时可能已 solve 部分 meta，必须回滚；且失败分档存放在
`Infer` 的 `Cell` 上，**不在** meta 快照内，若不恢复水位，首次尝试的
`Undecided`/`Fuel` 会单调残留，把反向重试后的真 `Absurd` 误报成“无法判定”。

### 改动清单

`src/L13_namespace/unification.rs`（参考版）

- `go` 闭包改为显式接收 `this: &mut Self`（对齐 L12 形态），以便在两次调用
  之间访问 `self.meta` / `self.unify_kind` 而不与闭包的可变借用冲突；
- 方向选择保持不变（`sp.len() < sp_prime.len()` → `(m', sp')` 先；相等/更长
  → `(m, sp)` 先，与 L12 `<=` 口径等价）；
- 首次尝试前取 `self.meta.clone()` 与 `unify_kind()` 水位；失败后
  `self.meta = snap; self.unify_kind.set(kind_before)`，再反向重试一次；
- 失败返回值取反向尝试的结果（首次失败的错误被覆盖）。

`src/L13_namespace/bump_spine_iter/unify.rs`（孪生，bool 无三档）

- `flex_flex_bump` 在首次方向前 `metas.clone()`；首选方向整体失败（invert +
  solve / 常数解 fallback + trait 合成任一环节失败）后 `*metas = snap` 再反向；
- 反方向的 `None` 分支对另一侧 meta 跑 `solve_bump` + `solve_multi_trait_ref`
  （与正方向 `go` 逐字对位，只是侧别互换）；
- 首方向成功路径不变（不复制/不恢复快照）。

### 与 L12 的偏差

1. 参考版只恢复 `meta` 与 `unify_kind` 水位，不恢复 `match_cmp_budget`——
   与 L12 R9 的实现一致（L12 亦只恢复这两项）；预算残留的影响面留待后续
   若出现“反向重试被预算误杀”的实证再评估。
2. 孪生用整表 `metas.clone()` 快照，与 L12 孪生同口径（孪生侧无 undo-log
   水位可用；`journal_meta` 只在帧打开时记录，不覆盖所有路径，不能替代）。
3. 参考版 `go` 的 Err 臂在反向尝试前会留下 `solve_multi_trait` / 约束挂账等
   非 meta 副作用，L12 同样不清理；本包只对齐 L12 的已验证口径，不额外扩大
   回滚面。

### 行为归因

两套全量门禁（615 / 630）与定向用例结果均与基线逐项一致，**没有出现**
Err→Ok 的用例。即 R9 的反向重试在当前 L13/twin 语料上未改变可观察结论，
属“机制对齐、oracle 不变”；孪生侧同步改动后 `l13_fast_parity` 无分叉。
若后续新增语料触发 Err→Ok，须按“先判断是修好了还是放过头了”逐条归因，
再决定是否保留。
